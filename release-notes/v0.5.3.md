# v0.5.3 — New games start with the original's queues, and the screens follow the original

Download the Windows installer or zip, or launch from source (Godot 4.7.2 + .NET 10 SDK). Everything in `v0.5.2` is unchanged except what section 3 lists.

**Changed since `v0.5.2`:**

- **`flags.newGameTurnOrder`** (T119, #638). `shuffle` under `classical-faithful`: New Game shuffles the turn order with the original's algorithm (16 draws, each swapping its slot with the drawn one; not Fisher-Yates) `[confirmed: code]`, research 871ca91, `2026-10-03-new-game-turn-order-shuffle.md`. The random generator is the clone's own stream `new-game.turn-order`, `[designed]`: the algorithm matches, but a seed does not reproduce the original's order. `improved` keeps the world's fixed order, `[designed]` (the user's decisions of 2026-10-02 and 2026-10-03). A loaded game never reshuffles. The CLI takes `--turn-order fixed|shuffle`.
- **`flags.balanceSheetTotals`** (T167, #1043). `original` under `classical-faithful` (the original's figures, `[confirmed: Wine + code]`, `2026-10-11-g1-original-checks.md` G2), `reconciling` under `improved`, `[designed]` (the user's decision of 2026-10-12) (section 3).
- **`economy.balanceSheetDebtLimitLowMax`, `LowStep`, `MidMax`, `MidStep` and `HighStep`** (T167): five new keys, identical in all three rulesets, read only under `balanceSheetTotals = original`.
- **`cityPopulationTierThresholds`** (T163) was empty and is now `[25, 50, 100]` in all three rulesets: the town-size tiers (section 3).

**Known caveat, unchanged:** `flags.diplomacyModel` is read by no code (#472, open). The two presets play diplomacy the same way, whatever this row says.

## 3. What changed for a player

### A new game starts like the original's

- **New games start with the original's regiments in training** (T161, #1000; bug #514). Each nation starts with the queue the original's DAT holds, read by the exporter (DAT +0x2C9, 40 slots of 8 bytes), so Rome starts with four units in training at its capital. Before, a classical new game started with every queue empty. A save keeps its own queues.
- **`classical-faithful` shuffles the New Game turn order** (T119, #638; section 2). Under the shuffle, nations ahead of yours play before your first turn.
- **Recruit unit follows the original** (T162, #1007; T166, #1042; bugs #1001, #1039). The dialog has an **All cities** entry that lists every regiment in training in queue order with its city and its readiness ("ready" or "N weeks"); Mobilize and Disband act on the selected row. All cities is listed only when more than one town holds queued units, and the dialog opens on it then. Recruit with All cities selected trains at the capital (research 89c37ff, `2026-10-11-g1-original-checks.md` G8, G9). The fortification refusal for a listed town below 75% is unchanged.

### Armies, towns and loading

- **Join units joins every selected unit** (T164, #1020; bug #1011). It joined only the first two before. The first selected unit's slot survives; the quality is the sum over the count, truncated; a mercenary, mixed types or an over-size sum refuse the whole join with the army unchanged.
- **Load game browses to any folder and opens the original's `.sav` files** (T165, #1021; bug #1002). The screen offers `.json` and `.sav` files only. An original save that cannot be used (truncated, no human seat, an unknown world) is refused with a message naming the file. Original-`.sav` import still targets `classical-mediterranean` plus `classical-faithful` (section 6).
- **Four town-size markers** (T163, #1008; bug #818). Small, medium, big and very big towns draw four different markers (under 25, 25–49, 50–99 and 100+ thousand), the capital its own. The original's four tiers are `[confirmed]`. That the clone recomputes the tier whenever it draws a marker (so a growing town changes marker) is the user's decision of 2026-10-11, recorded in `game-design.md` as a deliberate difference.

### Balance sheet

- **Under `classical-faithful` the Balance sheet shows the original's figures** (T167, #1043; bug #1038), `[confirmed: Wine + code]` (research 89c37ff, `2026-10-11-g1-original-checks.md` G2). The Expenditure **Total includes the Mercenary units line**; the **Fleet line counts every owned fleet**, finished or under construction; the **Debt limit is shown rounded down**, capped at 20,000 (below 5,001 to 100, 5,001–10,000 to 500, above to 1,000). Only the sheet's figures change; no charge changes, and the deposition test keeps the unrounded value. Under `improved` the sheet keeps the Total that reconciles with the quarter's treasury change.

### Fixes

- **An AI–AI battle's "destroys army of" line is written directly before its treaty block** (fix 1040, #1050), as the original does (g3 §3). Only the order of two news lines changes.
- **Esc on a confirmation prompt no longer logs a script error** (fix 598, #1035). Esc still answers No.
- **A ruleset with a bad divisor or debt-limit step is refused at load** (fix 979, #1026; fix 1054, #1059), with a message naming the key, instead of failing later. Fix 979 covers the runtime divisors and the RollTroops span; fix 1054 requires the three `balanceSheetDebtLimit*Step` keys and `LowMax` to be greater than 0 and `LowMax` to be less than `MidMax`. The shipped rulesets load.
- **Save and load hardening** (T71, #1049; #308). A bad `dataFile` or document path (empty, a NUL or another invalid character, a directory) is a typed error with its own message. A failed save keeps the previous file. A save version with no migration step is named as a defect of the build, not blamed on a newer build. A save whose `Neighbours` or `ConqueredBy` ids name no nation is refused at load.

**Tooling, not the game:** the Windows zip and installer are built by a release workflow on the tag push (T131, #1051); the nightly regression and soak gate (T28, #1055); T154 (a review run reads its brief from inside its own worktree); and fixes 1004, 1018, 1027, 1056, 956, 895, 694, 751 and 874 (headless-check, script and comment fixes). None of it changes play.

Carried over from `v0.5.2`, still `[designed]`: `improved`'s rows and its `combat.onDefeat` scatter, the legality-first attack, the purse caps, the leader draw, the painted map surface, the generated sounds, the new dialogs' unread wording, the watch-mode notice's wording, and `improved`'s AI economy. New this patch and `[designed]`: the stream name `new-game.turn-order`, and `improved`'s `newGameTurnOrder = fixed` and `balanceSheetTotals = reconciling`.

## 6. Compatibility

- **Native saves:** `SaveFormat.CurrentVersion` is **4**, unchanged. The one change in the persistence code (`SaveMigrations.cs`, T71) only changes which exception a version with no migration step throws, so a `v0.5.2` save loads as it did. A save made before this tag keeps the queues it holds; only a new game gets the DAT queues. A loaded game never reshuffles its turn order. A save whose `Neighbours` or `ConqueredBy` ids name no nation is now refused (T71).
- **Document schema:** `GameDataSchema.CurrentVersion` is **1**, unchanged. A custom ruleset needs the five `economy.balanceSheetDebtLimit*` keys and the flags `newGameTurnOrder` and `balanceSheetTotals` as the shipped files carry them, and is refused at load if a runtime divisor, a debt-limit step or `LowMax` is out of range (section 3).
- **Original `.sav` import** still targets `classical-mediterranean` plus `classical-faithful` only, by policy; Load game now opens such a file from any folder (section 3).
