#### T83 Play any nation from the CLI: --seat, a steady turn loop, and compact status views

- **Design milestone**: M18 (the headless half). It is a correction for bug [#361](https://github.com/diegoami/imperial_conquest_2/issues/361), found by the user playing the classical scenario on 2026-09-25. **Labels**: `phase:3 lane:ui`
- **Branch**: `task/T83-cli-seat` · **Model/effort**: Sonnet / Medium · **Reviewer**: **Opus / Medium**
- **Start after**: — · **Merge after**: —. It is **never in flight with T80**; both add CLI fixtures and Presentation tests.
- **Owns**:
  - `src/IC2.Cli/Program.cs`: argument parsing only
  - `src/IC2.Engine/Presentation/GameSession.cs`, `GameSession.Commands.cs`, `GameSessionRendering.cs` and `SessionOutput.cs`: the seat handling, the end-of-turn loop and the new status views
  - `tests/IC2.Engine.Tests/Presentation/**`: new test files, plus any existing test whose expectation this changes, named in the PR
  - `tests/fixtures/cli/**`: a new `--seat` script and its golden. `demo.txt`/`demo.golden.txt` must reproduce unchanged.
- **Scope**: In an all-AI scenario the CLI accepts orders for whichever seat is active. After `end` it plays the other seats, and then that seat too, as AI, and pauses on the next one: Rome first, then Carthage. There is no way to choose a nation, and `status` on the classical map (16 nations, every army, 334 cities) is too long to play from.
- **Done when**:
  1. **`--seat <nation>`.** It makes that nation human for the session. The CLI pauses on that seat every round, and the AI plays every other seat. An unknown nation id is rejected with the list of ids. `--seat` on a scenario that already has human seats adds this one as human, and the PR says so.
  2. **The turn loop is steady.** With `--seat carthage` on `classical-mediterranean`, three `end`s in a row each return to Carthage, and Carthage is never played by the AI. A test pins it.
  3. **All AI without `--seat` is watch mode.** Each `end` plays exactly one full round and returns. Orders are rejected with a message naming `--seat`, and read-only verbs (`status`, `news`, `map`, `help`) work. A test pins both. *(A design choice; the PR puts it to the user.)*
  4. **Compact views.** `status mine` shows only the seat's nation, armies, fleets and cities. `armies [nation]` and `cities [nation]` show one section, filtered by nation. `help` lists them. A test checks each view's first lines.
  5. **Goldens.** A new script, `--seat rome` over two rounds, has its own golden and reproduces byte for byte from a fixed seed. `demo.txt` reproduces unchanged.
  6. `dotnet build IC2.sln` and `dotnet test IC2.sln` are green, and the diff lists only Owns paths.
- **Hazards**:
  - **Saves.** If a `--seat` session is saved, record whether the seat's human flag is saved with it or is session-only, and test a reload.
  - **The AI must not see a human seat as its own.** The AI's offer and diplomacy rules treat human seats differently (T82). A `--seat` nation is human in every such check.
