#### T149 The game plays sounds at the original's events, generated with ElevenLabs

- **Design milestone**: M18 (the Godot UI). A correction task for bug [#790](https://github.com/diegoami/imperial_conquest_2/issues/790) (row M06 of bug #723), from the user's play on 2026-10-06: *"at least some type of sounds like the original."* The user put it in the v0.5.0 gate the same day ([build-process.md §4.8](../build-process.md#48-the-playability-gate-until-v050)), with replacements generated through ElevenLabs' sound-effects API on the owner's key. The research read is [`2026-10-06-sound-events.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/8da1588/docs/reports/2026-10-06-sound-events.md) (research `8da1588`, code only, not heard in play). It maps all ten of the original's sounds to their events, through the 16 call sites of `TPremierForm_MakeSound` (`0x0045BF28`), and describes each from local measurement. The clone has three silent stubs (`sfx.city_captured`, `sfx.battle`, `sfx.unit_move`, asset-specification.md §4.6) and plays nothing. **Labels**: `phase:3 lane:ui release:v0.5.0 local-only` (the sounds are generated with the owner's key on this machine).

- **Scope**:
  - **Protects**: every rule, every news line and every CLI line (no change under `src/IC2.Engine/` beyond the Owns lines above; the two new events are not newsworthy; every CLI golden byte-identical); the game's pace (no sound blocks the game: the original's synchronous `PlaySoundA(path, NULL, 0)` stalled it, and that is not copied); the asset format (asset-specification.md §1.4: mono, 44,100 Hz, 16-bit PCM WAV). Forbidden: an original WAV, or anything derived from one (samples, a resampled copy, a fingerprint), in a prompt, a pack, a test or the repository; the ElevenLabs key in any file, log or output; a random draw for any sound choice.
  - **The keys** **[derived: the report's table; the key names are this task's]**. The three existing keys keep their names and take the nearest original sound: `sfx.unit_move` is sound 1 (an army's step), `sfx.city_captured` sound 7 (a city taken) and `sfx.battle` sound 9 (a field battle resolved at once). Seven new keys: `sfx.fleet_move` (2), `sfx.battle_arrows` (3), `sfx.battle_javelin` (4), `sfx.battle_melee` (5), `sfx.siege_failed` (6), `sfx.fleet_sunk` (8) and `sfx.nation_conquered` (10). Keys 3–5 belong to the tactical battle screen, which the clone does not have until v0.6.0 (T125–T130). They are generated and shipped now, and nothing plays them yet.
  - **The cues** **[derived: code, the report's call sites; the clone's event names are this task's reading]**, from the domain events the call published, in their order:
    - `ArmyMoved` of a **human** seat's army: `sfx.unit_move` repeated `min(max(|ToX − FromX|, |ToY − FromY|), 12)` times, 70 ms apart **[designed: the original plays it once per tile as the army walks; `ArmyMoved` carries the endpoints, not the path, so the clone counts the Chebyshev distance, which is the step count of a straight move and a lower bound on a winding one (Sol's review of PR 793, R3)]**. `FleetMoved` of a human seat's fleet: `sfx.fleet_move`, counted the same way. A computer seat's moves are silent, as in the original. Whether a seat is human is read from the state after the call.
    - `CityFallsToNation`: `sfx.city_captured`. `CityFailsToBeCaptured`: `sfx.siege_failed`.
    - `BattleFleetSunk`, `FleetLostAtSea` and `FleetScuttled`: `sfx.fleet_sunk`.
    - `BattleResolved` of a field battle: `sfx.battle` **[designed for a human's own battle: the original opens its tactical screen there and plays the melee and missile sounds during it; until v0.6.0 the clone resolves it at once, so it gets the same distant-battle sound the original gives two computer nations]**.
    - `NationConquered`: `sfx.nation_conquered`.
    - These sounds play for every seat's events, the computer's included, as in the original (only the steps are limited to a human seat). They come from `EventsPublished`, so a command submitted from any screen (`MainGameScreen`, `GameMapView`, `ContextPanel`, `DiplomacyScreen`) and every seat an end of turn runs are heard alike (Sol's review of PR 793, R2 and R4). If another event the list needs turns out to be absent, stop and report.
  - **Playback** **[designed]**: asynchronous, through Godot's `AudioStreamPlayer`s. Cues queue in order, a cue already playing for the same key is not restarted, and at most 12 step sounds play from one order. Sound on/off is in Settings, on by default; the original has no such option, so this is the clone's own. A key the pack lacks plays nothing, never a system default.
  - **The generator** **[designed]**: `scripts/generate-sounds.ps1` (with `.py` doing the work) reads `assets/sound-prompts.json` (one entry per key: its text prompt, from the report's suggested prompt, and a target duration) and calls ElevenLabs' sound-generation endpoint with the key from the user environment variable `ELEVENLABS_API_KEY` (read like `OPENROUTER_API_KEY`: the process, then the Windows user scope; never a file, never printed). It writes each result into the authored pack as §1.4's WAV, converting if the API returns another format, and trims leading silence. Its default is a dry run that prints what it would ask; a real run takes `--key <sfx key>` or `--all`. Generation spends the owner's ElevenLabs credit, so the implementer generates each key once, and again only when the result fails conformance or the listening review; the PR lists what was generated and how often. Only the prompt text is sent.
  - **Not this task's**: music; the tactical battle screen's playback of keys 3–5; volume control; the original's `WAVS\` folder lookup.

- **Hazards**:
  - **The original's files stay out.** `WAVS\SOUND*.WAV` are the owner's and never enter a prompt, a pack, a test or a log; the report's descriptions in words are the only input.
  - **The key and the cost.** `ELEVENLABS_API_KEY` is the owner's; never print, log or commit it, and never pass it on a command line that a log records.
  - **A blocking call.** Godot's audio is asynchronous by default; a sound played from inside the command's own call stack in a way that waits for its end would copy the original's stall. Done-when 4 pins it.
  - **Not heard in play.** The mapping is from the code alone (the report's [open] item); a cue the user finds wrong in the listening review is a rework, not a research question.
