#### T68 Exporter provenance: preset-specific wording and the missing corpus ids

- **Design milestone**: none — a correction to merged T29 code, bug [#299](https://github.com/diegoami/imperial_conquest_2/issues/299) and [#236](https://github.com/diegoami/imperial_conquest_2/issues/236) N1. **Labels**: `phase:2 lane:data`
- **Branch**: `task/T68-exporter-provenance` · **Model/effort**: Sonnet / High · **Reviewer**: **Opus / Medium**
- **Start after**: T63 · **Merge after**: T63 — and **merged before T56, T66, T67 and T69**, each of which adds or rewords a ruleset key that reaches `classical-faithful.json` only through the exporter (added 2026-09-23)
- **Owns**:
  - `scripts/export-classical-world.cs`
  - `data/rulesets/classical-faithful.json` — regenerated through the exporter, never edited by hand
  - `data/rulesets/toy-ruleset.json` — **`_provenance` wording only**, no value
  - `data/rulesets/improved.json` — **`_provenance` wording only**, and only if the Done-when 2 guard needs it
  - `tests/IC2.Engine.Tests/Export/**`
  - `tests/fixtures/corpus.json` — **new ids only**, and only if Done-when 4 finds one missing (every id it names exists today)
- **Scope**: `scripts/export-classical-world.cs` builds `classical-faithful.json` by loading `toy-ruleset.json` whole (§9, ~:417–419), annotating the fields it can match to a corpus id through `RulesetCorpusMap.Entries` (~:651), and replacing `description` (~:490). Every other `_provenance` string is copied verbatim.

  - **#299.** A note written from the toy ruleset's point of view ships in the faithful preset. On `main` at `7e18d83`, `classical-faithful.json:870`, `flags._provenance.diplomacyModel`, describes the shipped preset as *"this toy ruleset"*. It is the only such string today (`improved.json` carries its own wording at that key, per #299's comment). The defect recurs: a new field's provenance can be written in the toy ruleset, where it is copied verbatim, or hand-edited into `classical-faithful.json`, which fails `ExportScriptReproducibilityTests`. T63 hit exactly this.
  - **#236 N1.** Of the 227 `confirmed` provenance entries in `classical-faithful.json` at T29's merge, 47 cite only a report. Several are **exact** ruleset constants with a corpus id that was simply not used:
    - the 25-value type-effectiveness matrix (`combat.detailedResolver.typeEffectiveness`) ↔ the 25 `matrix.*` ids;
    - `economy.unityCap` (990) ↔ `caps.maxUnity`;
    - `economy.purseCapPerUnit` (1000) ↔ `caps.maxPurseTalents`;
    - the four season values (`economy.supplyConsumption.seasonValues`) ↔ `supplyMorale.seasonTable.{spring,summer,autumn,winter}`.
- **Done when**:
  1. **The exporter owns preset-specific wording (#299).** Either an explicit override map from dot-path to `classical-faithful` text, applied after the load, or a stated rule that toy provenance is written preset-neutrally, with the toy notes rewritten to follow it. The PR says which and why.
  2. **A guard.** A test fails if any `_provenance` string in `classical-faithful.json` or `improved.json` contains "toy", case-insensitive. Reintroducing the current `:870` text fails it; show that in the PR. The export script itself also refuses to write such a file, throwing the way its other checks do (for example on a duplicate city id).
  3. **`:870` is corrected**, by regenerating through the exporter.
  4. **The exact-match ids are mapped (#236 N1).** `RulesetCorpusMap.Entries` gains the 25 `matrix.*` ids in the recorded orientation, `caps.maxUnity`, `caps.maxPurseTalents` and the four `supplyMorale.seasonTable.*` season ids. The exporter's own value cross-check passes for every one, and each field's `_provenance` in `classical-faithful.json` cites its id. Array elements are cited the way the script already cites `terrain.moveCosts[i]`.
  5. **The other entries are re-checked.** The PR lists every `confirmed` provenance entry in `classical-faithful.json` that still cites no corpus id, each with the reason no id fits. It does not assume the reviewer's list was complete.
  6. **Values do not move.** `git diff` of the three rulesets shows only `_provenance` strings, `ExportScriptReproducibilityTests` is green, and a second export run reproduces the file byte for byte.
  7. `dotnet build IC2.sln` and `dotnet test IC2.sln` green, and the diff lists only Owns paths.
- **Hazards**:
  - **The export reads the original DAT.** The worktree needs `assets.local.ini`, or CI's fixtures directory, to run it, as T29 and T63 did.
  - **Never hand-edit `classical-faithful.json`.** Every change reaches it through the exporter, or the reproducibility test fails.
  - **The guard must not catch legitimate citations.** No `_provenance` string in either shipped preset names a toy file today. If the chosen rule needs to cite one, word the guard so that it still fails on the `:870` text.
  - **Four tasks queue behind this one** (T56, T66, T67, T69). Keep it narrow.
