#### T209 Global Automation: mobilize ready training slots before End turn

Policy revision (owner, 2026-10-27): [T220](T220.md), #1499/#1500, requires Average or better quality in addition to ordinary readiness. The original T209 readiness-only policy below is historical; manual mobilization remains unchanged.

- **Release / priority**: v0.8.0 required QoL; P1. [Scope decision](../release-plan.md#25-planned-v080-faithful-battles-and-quality-of-life-automation).
- **Owner direction**: auto mobilize is opt-in and uses the global Automation tab. The provisional policy is to attempt every ready slot of the active human nation after End turn confirmation; if a slot becomes ready only during that turn's later training tick, it is considered on the next confirmed End turn. No per-city approval is required while the global switch is on. This is separate from auto recruit's later per-city plans.
- **Start after**: T207/T208 support coordinator, which can then supply newly created armies. **Owns**: `godot/UI/UserSettings.cs` (one switch), `godot/UI/SettingsScreen.cs` (one control), `godot/UI/MainGameScreen.cs` (confirmed End-turn order/summary only), a new Godot-free `godot/UI/Automation/AutoMobilizePlanner.cs`, `tests/IC2.Engine.Tests/IC2.Engine.Tests.csproj` (link planner), `tests/IC2.Engine.Tests/Ui/UserSettingsTests.cs`, a new `tests/IC2.Engine.Tests/Ui/AutoMobilizePlannerTests.cs`, `godot/Checks/SettingsCheck.cs`, `godot/Checks/EndTurnBoxCheck.cs`. The planner links against the existing Godot-free `RecruitUnitDialogModel`; its engine handler, readiness/placement rules, rulesets and native save schema are read-only.

### Scope

Add a global, default-off **Auto mobilize ready units** switch. On confirmed human End turn, read that nation's live recruitment queue in ascending slot order and use the existing `MobilizationReadiness.IsReady` rule and `RecruitUnitDialogModel.NextArmyId` to propose `mobilize <slot-index> <new-army-id>`. Submit through the ordinary session command path. After an accepted command compacts the queue, inspect the same index again; after a refusal, advance and show its typed reason. Bound attempts by the initial queue length so a malformed state or repeated refusal cannot loop. Re-read live state after every submission. Do not mobilize another nation's slot, an unready slot, or anything on Make more moves/Cancel, open battle or AI seat.

Mobilize **before** T207 army support and T208 fleet support, then one ordinary `end`: newly created armies can receive the configured support in that same confirmed flow. This is a new player-selected automation order, not a change to mobilization eligibility, placement, troop strength or the turn tick. A failed mobilization leaves its slot in place and does not prevent later ready slots or the player's End turn. Report accepted, skipped and refused counts/reasons in the visible summary. Global settings persist outside the campaign save; off remains identical to current behavior.

### Done when

1. Settings migration/normalization, the Automation tab and `UserSettingsTests` prove default off, global persistence and legacy-file loading. The control explains when it acts and that a new army may be created.
2. Pure planner tests pin active-nation filtering, human readiness under faithful and improved asymmetry, queue index compaction, deterministic new-army IDs, one-unit and full-cap/blocked-placement paths, and unchanged state/RNG during planning. No private fixture is needed for these controls.
3. `EndTurnBoxCheck` uses an actual trained slot and the real UI confirmation to prove exactly one accepted `mobilize` before army support and one `end`; Cancel does nothing, refused/partial cases retain their slots and show reasons, hotseat acts only for the active nation, and the automation-off state/RNG/command sequence is unchanged. Manual Recruit unit / Mobilize remains unchanged.
4. Build solution and Godot project; run focused tests and `SettingsCheck`/`EndTurnBoxCheck` headlessly with completion markers/no FAIL, then full CI and the Godot churn guard. Record pass/fail/skip counts and fixture availability.
