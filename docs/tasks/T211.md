#### T211 Campaign-saved multi-turn army targets

- **Release / priority**: v0.8.0 required QoL; P1. [Scope](../release-plan.md#25-planned-v080-faithful-battles-and-quality-of-life-automation); [issue #1384](https://github.com/diegoami/imperial_conquest_2/issues/1384).
- **Owner decisions (2026-10-23)**: target a fixed map cell or city, not a moving unit. Targets belong to a particular campaign save, not global Settings. No automatic attack.
- **Start after**: T210. **Owns**: the optional target record on `SaveGame`, `GameSession` target lifecycle and save/load, a Godot-free target planner, `MainGameScreen` and `GameMapView` target controls and confirmed End-turn sequence, the army command strip/menu entry, relevant save, planner and Godot checks. Movement commands, `MovementWalker`, combat and original-compatible SAV format are read-only.

### Scope

A selected owned, unembarked army can enter **Set travel target** mode, then click a land cell or a city. A city target retains its city ID; its coordinates are resolved from the current world. Because ordinary army movement blocks every city tile, reaching a city means stopping on a legal adjacent land cell. The target control shows the chosen destination, remaining distance/progress and **Cancel target**. Escape or choosing another command leaves the map without arming a target. Setting or clearing a target issues no game command. The player can replace a target.

Persist an optional list of target records in the clone's native JSON `SaveGame`, keyed by army ID and nation ID. An older save with no list loads with no targets; no schema bump is needed for this optional metadata. Loading a different save replaces the session's target list. The records are never represented in an original-compatible `.sav`, and importing one starts with no targets. A save made while a target exists, copied to another machine and reopened must resume it. Stale records (missing army, changed nation/world, invalid cell/city) are dropped with a visible reason at the next pass rather than rejecting the campaign save.

After the player confirms End turn, run the target pass **after** T209 mobilization and T210 recruitment and **before** T207/T208 support, then issue one ordinary `end`. Visit target records in army state order; for each active human nation's army, propose at most one ordinary `move <army> <x> <y>` toward the fixed target using its live moves. The engine's existing walk may spend several moves and stop partway; re-read position, moves and target after the command. Do not try to end turns automatically. A newly set target makes its first move on the next confirmed End turn, and then on each later confirmed End turn until it arrives or stops. No command is issued on Cancel/Make more moves, while a tactical battle is open, or for a different hotseat nation.

On arrival, clear the target and say so. Stop and clear it with a visible reason if the move is refused, makes no progress, the army disappears/changes owner/embarks, a route becomes blocked, or it reaches hostile contact; never issue an attack, siege, declaration of war or embark order. A manual move, attack, siege, embark or disband of that same army cancels its target before the manual action; unrelated commands do not. Targets for other hotseat armies remain saved and untouched. The automation-off path (no targets) issues no extra commands or RNG draws and preserves existing movement and End-turn behavior.

### Done when

1. Set, replace, display and cancel a selected army's target through the real Godot controls. Terrain and city clicks bind fixed coordinates or city ID; invalid targets and enemy-owned armies are refused without game commands. The target mode never hijacks ordinary map selection or attack controls once exited.
2. Save, close, load and continue a target in a second process through the ordinary native JSON save path. Legacy saves load empty, a different save replaces targets, stale targets are handled without corrupting state, and original-compatible SAV import/export does not claim or synthesize this metadata.
3. Pure tests cover city-adjacent arrival, fixed-cell arrival, partial movement across turns, blocked/refused/no-progress stop, ownership/embark/hotseat gates, authored army ordering, one move per army per pass, player intervention, and unchanged state/RNG during planning. Use existing movement commands for actual effects.
4. A Godot End-turn check proves confirmed order `mobilize` → `recruit-standing` → target `move` → support → one `end`, with visible progress/stop summary. Cancel and Make more moves issue nothing. A save/resume check proves target persistence and hotseat isolation.
5. Build solution and Godot project; run focused tests, relevant headless checks with completion markers/no FAIL, full CI and Godot churn guard. Report counts and private-fixture availability.
