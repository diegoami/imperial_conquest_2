- **Scope / Protects**: map validated native state into T184's complete write plan and expose one shared typed export result to CLI and UI. Add offline `IC2.Cli --export-sav <input.json> --output <new.sav> [--template <private.sav>] [--config <assets.ini>]`; this exclusive mode rejects gameplay/script/seed/ruleset overrides and duplicate/unknown/missing arguments. Explicit template wins; otherwise use an explicitly named original SAV resolved through existing configured `assets.local.ini`/private fixture conventions, with the selected identity reported. Do not silently choose the latest save, infer the user's original installation path, modify configuration, or ship a template. If no uniquely selected compatible template is available, explain the required path and refuse. Reuse native `SaveManager` load/migrations and repository context resolution before mapping. Provide a nonmutating session adapter in the owned exporter for UI use: inspect public `GameSession.World`, `Ruleset`, `Scenario`, `State`, `OpenTacticalBattle` and `HasPendingPeaceOffers`, refusing any unresolved peace-offer modal/runtime continuation rather than dropping it. No native temporary JSON save or call to the private `BuildSaveGame` is required. Offline saved documents and live sessions share the same state-mapping core. Do not change native save schemas, SaveManager, importer semantics, rulesets, game mechanics or state.

  **Supported state and omissions.** Support validated `classical-mediterranean` world/scenario and unmodified shipped `classical-faithful` ruleset, strategic state only, including midturn state, pending diplomatic offers, recruitment, launched/building fleets and embarked armies. Pending diplomatic trade/alliance offers are SAV-encodable and required, including the owner's `save1`, `save77`, `saveY` and `saveyy` JSONs; these are distinct from unresolved live peace-treaty modal continuations and cannot be silently rejected or omitted. Match canonical world/nation/city identities and original dimensions, units, slots and value ranges; matching IDs alone do not validate a changed custom world/preset. Explicitly reject other/custom worlds or scenarios, `improved`/modified rulesets, any active battle, unsupported control modes/flags, unrepresentable strings/numbers/counters/links and unknown required mappings. The sole string exception is an export-copy alias for a generated mercenary placeholder: only when the full unit name is exactly `Mercenary unit (label N)`, `N` is that same unit's nonzero `UnitSlot.MercenaryLabel`, and the name exceeds the original's 23-byte ASCII limit, encode `Mercenary (label N)`. Preserve the numeric mercenary label and all unit/army/slot identity and data. Do not truncate, regex-match, infer or alias any other name, including custom names or label mismatches; already-fitting names remain unchanged and every other encoding/length failure stops export. CLI and UI use this same rule and explicitly report each original and exported name with stable army/slot identity; the structured CLI report carries details and the UI shows concise success details. No separate CLI flag is required for this policy. No coercion to faithful or turn advancement to make a state exportable. Validate human/computer seats and allow only the original encodable nation flag; never silently map an unsupported controller to computer. Do not promise preservation of runtime computer-general flags. Alias processing must leave the source JSON bytes, live state and RNG/draw state unchanged.

  The report explicitly distinguishes written original fields from nonencodable native metadata: schema/envelope versions, native IDs/labels, world/ruleset/scenario identifiers, free-text provenance, `Calendar.TurnIndex`, master `RandomSeed`, draw positions/streams, original-unpersisted runtime settings/computer-general and display pacing, first-end news bookkeeping, and native score baselines/caches without an original equivalent. Active battle/draw state is rejected as a whole, not dropped. Inventory additional native members during field-map review; no unclassified member may vanish. Native score baselines that correspond to original stored bookkeeping must be mapped explicitly, not put in the omission list merely because convenient. Original load does not restore process RNG ([research report](https://github.com/diegoami/imperial-conquest-2-research/blob/d5f0bc797ec23c181e854f743db1b06343e2876d/docs/reports/2026-09-29-loading-a-save-does-not-reseed.md)); export promises representable current state, never identical future random outcomes or native JSON roundtrip identity.

  **Mapping/evidence.** Use T184's pinned reports plus current importer field mapping as an inventory, not a proof of invertibility. For each native state member and every original byte region state its mapping, validation, derivation, template-preservation rationale or explicit omission/rejection. Resolve original record/index order, nation codes, unit slots, recruitment indices, fleet/army transport links, map base/rough-sea/covered-cell/marker reconstruction, capital markers, nation relations/neighbours, all nation stored counters/baselines, mercenary slot sentinels, news, current seat/order/calendar and pending offer. Declare canonical marker regeneration and any original stale-bookkeeping differences. Empty native `_provenance` is normal and does not supply raw bytes. The [evaluated safety finding](https://github.com/diegoami/imperial-conquest-2-research/blob/3bda5a0244b98e837e55269efe4eb552edfc4a65/docs/reports/2026-10-17-sav-export-live-regions-and-safe-rejection-policy.md) supplies T184's precise live/history/UNKNOWN boundaries, not a complete changed-state profile. Map the owned-city list in original ASCII-name order with -1 unused entries, historical 270-BC baselines with proved scenario/history applicability, conqueror history independently of alive/dead, and controller flags independently of UI preferences. Prove each preserved region remains valid after changes; same-template lineage and sampled zero UNKNOWN bytes do not suffice. New records require complete field/default/residue policy; moved records keep their own full bytes and repair carrier indices. Preserve representable pending offers and distinguish stale offer type from a live offer using source/relation semantics; do not clear or reroll them. Validate assembled original message capacities as well as individual text buffers, retaining the sole approved mercenary alias above. The report did not inspect or convert the twelve owner JSONs, establish a changed-state candidate, or perform native Windows round trips. A region requiring unsupported guesses stops for targeted research; no general research ticket is required merely because this is a writer.
