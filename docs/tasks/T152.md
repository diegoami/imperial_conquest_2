#### T152 The dispatch scripts take the model from quota-tracker's /recommend

- **Design milestone**: none. Process tooling, the user's decision of 2026-10-08. The quota tracker now chooses the model itself (`/recommend?tier=heavy|light`), and the scripts' own ranking by `headroom_pct` compares percentages that are not comparable between providers: pools differ hugely in size, some are monthly and some weekly, and Claude sessions draw on some of them as their main model. **Labels**: `lane:infra release:v0.5.0`
- **Branch**: `task/T152-recommend`, from `origin/main` · **Model/effort**: the implementer from `/recommend?tier=heavy` with CLAUDE.md rule 17's exclusions (Claude only when nothing else scores positive) / Medium · **Reviewer**: the complex tier ([§3.4](../build-process.md#34-why-the-reviewers-model-differs-from-the-implementers)), GPT-6 Sol at `low`
- **Start after**: T150 (it edits both scripts) · **Merge after**: [T150](T150.md). It is **never in flight with** T151 or another task or fix under `scripts/Choose-Model.ps1`, `scripts/external-implement.ps1` or `scripts/*OpenCode*`.
- **Owns**:
  - `scripts/Choose-Model.ps1`;
  - `scripts/external-implement.ps1`: **only** `-Model auto`'s chain, the substitute choice that calls `Choose-Model.ps1` (T150's Done-when 2), and the run log's and the PR body's "Implementer attempts" lines that name the chosen model (Done-when 4);
- **Scope**:
  - **Protects**: the family rules ([§3.4](../build-process.md#34-why-the-reviewers-model-differs-from-the-implementers)): a reviewer is never of the implementer's family, and T150's substitute is never OpenAI. Explicit `-Model`/`-Reviewer` runs exactly the model named, as today.
  - **Out of scope**: the quota tracker itself, and Alibaba, which `/recommend` does not rank and which stays an occasional choice in its discount hours (CLAUDE.md rule 20).
- **Done when**:
  1. **`Choose-Model.ps1` ranks by `/recommend`.**
     - It calls `localhost:8765/recommend?tier=<heavy|light>`: **one rule: `heavy` for `-Role implementer`, `light` for `-Role reviewer`**, whatever the tier. It keeps the `ranking` order.
     - It maps each row's provider to an alias **per role**, from two tables in the script, using only names the receiving script accepts (`external-implement.ps1 -Model` or `external-review.ps1 -Reviewer`):
       - **implementer** (heavy): `minimax` → `mm-m3`, `zai` → `glm`, `opencode_go` → `mimo-pro` (the user's decision of 2026-10-09, bug #908: DeepSeek is blacklisted, and OpenCode Go's rows map by model: `mimo-v2.6-pro` → `mimo-pro`, `mimo-v2.6-flash` → `mimo-flash`; this entry said `deepseek-flash` and `deepseek-pro` before), `claude` → Claude Sonnet (the script's exit-3 fallback, not an OpenCode alias). `openai` has **no** implementer alias: OpenAI never implements, so Sol stays free to review (T150's Done-when 2).
       - **reviewer**: `zai` → `glm`, `opencode_go` → `mimo-pro` or `mimo-flash` by the row's model (bug #908; `deepseek-pro` before 2026-10-09); the row places OpenCode Go in the order, and the substitute dispatched for it is MiMo Pro whatever alias is printed ([§3.4](../build-process.md#34-why-the-reviewers-model-differs-from-the-implementers)), `alibaba` → `qwen` when it appears. These are Sol's substitutes, the only reviewers the ranking orders (Done-when 3).
     - A row with no alias for the role is printed as `unmapped for <role>` with its provider, and the next row is taken. It is never guessed.
     - It no longer reads `headroom_pct` or `pace_pct` anywhere.
     - It prints each candidate with its `score`, its `confidence` and its `reasons`, and lists `skipped` with why.
  2. **Our exclusions apply on top, in this order.**
     - `-ExcludeModel` and `-ExcludeFamily`, as today.
     - Claude (sonnet, opus) is dropped while any other candidate has a positive `score`, because Claude is the orchestrator.
     - `luna` and `sol` are never implementers, and reach a review only through §3.4's tier rules (Done-when 3), never through the ranking.
     - **T150's substitute** drops every failed family **and the whole OpenAI family** (Luna and Sol), whether or not it failed.
     - A negative `score` is ranked after every non-negative one and chosen only when nothing else is left.
  3. **`-Model auto` takes the first implementer candidate** that Done-when 1 and 2 leave, instead of a fixed chain, and falls back down the same list on an infrastructure failure, as the chain does today. **T150's substitute** takes the same heavy-tier **implementer** list (implementer aliases only), after Done-when 2's substitute filter: every failed family and the whole OpenAI family are dropped. **Reviews keep their dispatch interface**: this task does not change `external-review.ps1` or [§3.4](../build-process.md#34-why-the-reviewers-model-differs-from-the-implementers)'s tiers (Luna for a simple PR, Sol for a complex one, a cold Claude Opus for a very complex one; the main session passes `-Reviewer` explicitly, as Appendix C step 2d says). What changes is that **`Choose-Model.ps1 -Role reviewer -ExcludeModel <implementer>`** prints **Sol's substitutes** (GLM, MiMo Pro, Qwen; DeepSeek Pro before bug #908) in `/recommend?tier=light` order, with their `reasons`. A substitute the ranking skips or scores negative comes last, and one of the implementer's family is never listed. The main session takes the first when Sol cannot review.
  4. **The reasons are logged.** The implementer's run log and the PR body's "Implementer attempts" name the chosen model and quote its row's `reasons`. For a review, the main session copies the reasons `Choose-Model.ps1 -Role reviewer` printed into its tier comment, as Appendix C step 2b's record.
  5. **When the tracker is not usable,** the script stops with exit 3 and a message naming the problem; it never falls back to percentages:
     - **`note` says the statistics are loading** (an empty `ranking`): it waits and retries up to 3 minutes.
     - **The service does not answer:** it prints the restart command (`systemctl --user restart quota-tracker`, in the WSL host) and stops.
  6. **The tracker is called in one place.** `external-implement.ps1` gets its candidates only through `Choose-Model.ps1`, which takes `-RecommendFile <json>` (a canned response, in place of the call) and `-RecommendUrl <url>` (default `http://localhost:8765/recommend`; a closed local port simulates a silent service). Its retry wait is a parameter, so a test can shorten it. **`Choose-Model.ps1 -SelfTest`** covers, without the network:
     - the mapping and an unmapped row;
     - each exclusion of Done-when 2, Claude with and without another positive score included;
     - a negative score;
     - the loading `note`;
     - a silent service (a closed port: exit 3 with the restart message);
     - the per-role mapping and the substitute filter, with an `openai` row first and a failed `minimax`.

     `external-implement.ps1 -WhatIf -RecommendFile <json>` prints the model it would run and its `reasons`, which shows that the dispatch script honours the chooser. `Choose-Model.ps1 -Role reviewer -ExcludeModel glm -RecommendFile <json>`, with a canned light ranking that puts `zai` first, prints the OpenCode Go row (`mimo-flash` for a light `mimo-v2.6-flash` row; DeepSeek Pro before bug #908) and then Qwen, and never GLM or an OpenAI model. That is the offline probe of the substitute order.
  7. All three scripts parse, `dotnet build IC2.sln --nologo -v q` and `dotnet test IC2.sln --nologo -v q` are green, and `git diff --name-only origin/main...HEAD` lists only Owns paths.
- **Hazards**:
  - **The alias table is the owner's heavy/light table.** If `/recommend` names a model that has no alias, report it and do not guess one.
