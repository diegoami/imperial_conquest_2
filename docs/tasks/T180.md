After each frame and each half-round's final Setup/reconciliation, refresh complete current text, positions, values, rosters and overlays; clear stale messages/selection markers.   - **Travel and handoff**: for both sides' actual movement frames, render the unit continuously from the typed event's start to destination, using only producer endpoints/identities and coherent `Before`/`After`. Hold `Before` values during travel with one shared interpolated pose on board/minimap and participant position text; suppress the stationary duplicate. Commit `After` together at arrival, visibly show the destination, then permit the next dependent shot/melee. At nonzero pacing, travel and arrival must each be observable, including across a large `AdvancePlayback` delta; elapsed-time carry must not erase all intermediate stages before a screen draw. Use endpoint interpolation, not an invented terrain route, extra tactical steps or commands. Preserve every original interleaving (including move/shot/move and per-unit arrival/combat); do not group all movement ahead of all fighting. Placements animate only where valid on-board endpoints exist; initial copy-in, pending/off-grid placement, forfeited/no-distance movement and absent endpoints reconcile without fabricated travel.
  - **Turn begins**: before the new active side's first travel/combat, visibly announce side/nation, half-round and human/computer nation/computer general controller, explicitly including an enemy turn. Derive this from producer controller/phase/identity evidence, including opening automation. A HalfRound frame can precede the old side's melee: keep its resolving/pending-handoff message, finish that combat in order, and release/announce the new controller only at the producer's valid Setup/controller boundary. Do not infer the turn from selection, strategic attacker status, or an already advanced session. Announcement is a presentation stage, not a synthetic gameplay event or extra exchange notification.
  - **Rout departure**: on each typed rout, prominently annotate the current exchange `UNIT ROUTED` with stable slot/name/side and numeric exchange losses retained alongside the notice. Keep the exchange actor/target roles; the departing slot is a separate effect identity. Then hold the notice and last displayed position, fade that unit there from visible to transparent, remove it, and only then advance. Hold the coherent `Before` snapshot for all panels during hold/fade, with explicit routed/departing status and a shared opacity/pose on board/minimap; commit `After` atomically after the fade so rosters, participant values and grids all agree on removal. A temporary departure glyph is explicitly presentation-only, never a live/selectable unit. Use its last actually displayed glyph/position when available (including an overkill exchange); never invent a location or resurrect an already absent unit. With no drawable prior unit, keep notice/hold and reconcile without a phantom glyph. Rout without a current exchange has a standalone rout notice, never an invented exchange. Cascade victims receive their own identity/removal stages in original order and the same hold/fade when drawable; distinguish cascade removal from a fresh direct rout. Preserve typed non-rout removal causes rather than relabeling surrender/destruction as rout. No ghost glyph/role marker survives commit. An escape-path animation is future optional work, not required here; fade implies neither survival nor a strategic retreat.
  - **Timing and completion**: at nonzero pacing use explicit bounded display-only announcement, travel, arrival, rout hold and fade stages; derive/document pacing in owned code without new settings/schema or unproven original-game timing claims. At both pause settings zero, collapse visual waits/animation to their final poses/snapshots but traverse the same stages, frames and notifications in order. Explicit skip/finish may collapse waits at any stage, including half-faded rout or mid-travel, and must commit the destination/removal and all remaining producer frames exactly once. Ordinary advance must handle zero elapsed time, fractional steps, oversized deltas and consecutive moves/routs/cascades without lost stages, duplicated notification, stale pose or endless wait.
