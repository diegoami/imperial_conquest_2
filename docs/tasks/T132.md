#### T132 The right-hand info panel can be hidden and shown again

- **Design milestone**: M18 (the Godot UI). The first item of the v0.4.1 list: the user's request of 2026-10-04 after playing v0.4.0, *"the right info panel must be hideable"* ([#690](https://github.com/diegoami/imperial_conquest_2/issues/690)). A v0.4.x item, so it bypasses the playability gate ([build-process.md §4.8](../build-process.md#48-the-playability-gate-until-v050)); v0.4.1 is cut as soon as it merges ([release-plan.md §2.2.1](../release-plan.md#221-v04x-patches)). **Labels**: `phase:3 lane:ui single-instance release:v0.4.1` (it launches Godot for its check, [build-process.md §7](../build-process.md#7-concurrency-single-instance-and-local-only))
- **Branch**: `task/T132-hideable-panel` · **Model/effort**: Sonnet / Medium ([§3.3](../build-process.md#33-model-selection): not architecture, so the OpenCode default, then Sonnet) · **Reviewer**: the complex tier ([§3.4](../build-process.md#34-why-the-reviewers-model-differs-from-the-implementers)): GPT-6 Sol at `low` **+ human visual review** ([§9](../build-process.md#9-standing-governance-decisions) Q-B)
- **Start after**: none · **Merge after**: none. **It runs before T131** (the user's decision of 2026-10-04, [release-plan.md §2.2.1](../release-plan.md#221-v04x-patches)), so `v0.4.1` can be cut soon; T131 runs right after it. It is **never in flight with** T127 or T128 (the v0.5.0 UI tasks), nor with another task or fix under `godot/**`, except an engine task's one-line entry in `godot/UI/CommandVerbCatalog.cs`, which this task does not touch.
- **Owns**:
  - `godot/UI/MainGameScreen.cs`: **only** the toggle button beside the right-hand column, the show/hide of that column, the toggle key in `_UnhandledInput`, and the remembered choice;
  - `godot/UI/SidePanelToggle.cs` (new, Godot-free): the panel's shown/hidden state for the run, which key toggles it, and the button's caption and tooltip;
  - `godot/Checks/SidePanelToggleCheck.cs`, `godot/Checks/SidePanelToggleCheck.tscn` (new);
  - `tests/IC2.Engine.Tests/Ui/SidePanelToggleTests.cs` (new), and the one `<Compile Include>` line for `SidePanelToggle.cs` in `tests/IC2.Engine.Tests/IC2.Engine.Tests.csproj`.
- **Scope**:
  - **Protects**: hiding the panel changes no game state, command or rule: no command is submitted, the session's state is the same object, and the selection, any armed order and the viewed nation stay as they were. The map, the news log, the last-command label, the menu bar, the toolbars, every overlay and dialog, and every other screen behave as before. Forbidden: an edit to `ContextPanel.cs`, `GameMapView.cs`, `AreaMapView.cs` or any file under `src/`; a new `GameCommandTable` row (the table is the original's menu, and this control is not the original's); a change to the column's width or content when it is shown.
  - **What hides.** The whole right-hand column that `MainGameScreen` builds (~:163, `sideColumn`): T110's Area-map strip, T102's overview mini-map and the context panel. Hiding only the context panel would leave the mini-map's 320 px in place and free no map. The Area-map highlights stay reachable from the menu bar while the column is hidden, as they are today; the column shows their state when it comes back.
  - **Design calls, each a default [designed]** that the reviewer and the user see in the PR and its screenshots, and that the user may change at the visual review:
    1. **The control.** A narrow button on the column's left edge, in the body row between the map and the column, so it stays on screen while the column is hidden: `»` hides (the column is shown), `«` shows (it is hidden), with the tooltip *Hide the panel (F12)* or *Show the panel (F12)*. **F12** toggles it too: no key in `godot/` uses it today (only Esc and Shift+X), and the original's other menu shortcuts are unread (`GameCommandTable.cs`'s remark, audit §5 gap 2). The key goes through `_UnhandledInput`, so it does nothing while an overlay is open (`ActiveOverlay`), as Esc and Shift+X do, and a focused text field keeps it.
    2. **The map widens.** The column's `Visible = false` gives the body `HBoxContainer`'s space to `GameMapView`, which is already `ExpandFill`; its existing `Resized` handler keeps the player's zoom and pan (it re-fits only once, at the first layout). Showing the column again gives the map back exactly its previous width.
    3. **Remembered for the run, not across launches.** The choice is a static, like `SettingsScreen.SelectedPackId` (which is not persisted either), so a New Game or a Load in the same run keeps it, and every launch starts with the column shown. There is no persisted settings store in `godot/` today; adding one (a `user://` config file) is the user's call and a follow-up, not this task's.
    4. **Selecting a unit while the column is hidden does not show it.** The selection still happens; the player shows the column to read it.
- **Done when**:
  1. `SidePanelToggleTests`: the initial state is shown; a toggle flips it and a second toggle restores it; F12 with no modifier is the toggle key and F12 with Ctrl, Shift or Alt, Esc and Shift+X are not; the caption and tooltip match each state; the state is shared by two instances in one process. It fails on `main` (the type does not exist) and passes after.
  2. The headless `SidePanelToggleCheck` builds the real `MainGameScreen` on a new classical-mediterranean game at the 1500 × 850 viewport (as `ContextPanelWidthCheck` does) and asserts, after settle frames each time: at the start the column is visible, the context panel is at least 340 px wide and inside the viewport, and the button reads `»`; a real click on the button (`Viewport.PushInput`, as `AreaMapCheck` clicks) hides the column, the map's width grows by at least 340 px, the button reads `«` and stays inside the viewport, and the map's zoom and pan are unchanged; a real F12 key event shows the column again and the map's and the panel's widths equal the start's exactly.
  3. In the same check: with an army selected, hiding and showing the column keeps the selection and the panel's army view; no command is issued across every toggle, counted as `MapClickCheck` counts it (every `GameMapView.CommandIssued` and `ContextPanel.CommandIssued`, and `CommandTable.IssuedCount` unchanged), and `Session.State` stays the very same reference; with an overlay open, F12 changes nothing; a second `MainGameScreen` built in the same run (a New Game) starts with the column hidden when it was hidden in the first.
  4. `ContextPanelWidthCheck`, `MapClickCheck`, `MapClipCheck`, `AreaMapCheck`, `MenuBarCheck` and `ScreensCheck` pass unchanged.
  5. `dotnet build IC2.sln --nologo -v q` and `dotnet test IC2.sln --nologo -v q` are green, the `godot-headless` CI job is green, `scripts/check-godot-churn.ps1` leaves a clean tree, and the diff lists only Owns paths.
- **Hazards**:
  - **The human visual review** posts four screenshots of a windowed run: the column shown, hidden, shown again, and hidden with a city selected. "Looks right" is the user's call (Q-B), and it settles the four design calls above; a change the user asks for there is rework of this task, not a new one.
  - **`Visible = false`, not a zero width.** A collapsed width leaves the column's minimum sizes in the row (the 340 px floor) and frees nothing; T24's first pass lost the panel to an `HSplitContainer` sign convention, which is why the body is a plain `HBoxContainer`. Keep it one.
  - **No re-fit on a resize.** If the map re-fits when it widens, the player's zoom and pan are lost; Done-when 2 catches it. The fix belongs in `MainGameScreen`; `GameMapView.cs` is not owned.
  - **F12 may turn out to be the original's.** If the EXE's form stream (audit §5 gap 2) is read later and assigns F12, the key moves through the bug list.
  - **Never two Godot processes at once**: run the headless checks one at a time.
  - Wiring `SidePanelToggleCheck` into `.github/workflows/ci.yml` is a one-line follow-up after the merge (build-process §7), not this task's.
