#### T100 The menu bar and the main toolbar, driven by one command table

- **Design milestone**: M18 (the Godot UI). From the user's decisions of 2026-10-01 on the UI command audit ([`original-ui-command-audit.md`](../investigations/original-ui-command-audit.md) §1 and §3.1): the original's menu bar with its submenus and its shortcut toolbar icons, each wired to an engine command; the audit first, then one UI task per menu group; the seat commands left out for now; and a short new in-game help page, with Show hints and About kept. **Labels**: `phase:3 lane:ui single-instance`

It is **never in flight with** another task or fix under `godot/**`, except an engine task's one-line entry in `godot/UI/CommandVerbCatalog.cs`.

- **Scope**: the main game screen gets the original's menu bar and its main toolbar. Every command goes through one table, so a menu entry and its toolbar icon run the same handler, as the original's `StrategicDecision`, `ChangeNation`, `ShowOnAreaMap` and `UnitMapAction` do **[derived: code, audit §1]**.
  - **`GameCommandTable`**: one row per command, holding its id, its menu path, the original's caption **[confirmed: `menu-and-toolbar-inventory.md`]**, its icon key or none, its shortcut or none, and whether it is wired yet. It lists every entry of the audit's §1 except **Game → New player, New nation and Abdicate**, which are out (the user's decision to leave the seat commands out for now). Nothing else in the UI lists commands.
  - **The menu bar**: File · Game · Strategy · Nations · Area map · Unit map · Help, with the submenus Unit map → Army, Fleet and City, and Area map → Show mercenaries. Entries a later task wires are shown disabled.
  - **The main toolbar**: Open, Save and End turn; the six Strategy entries; and the 16 nation buttons plus All nations, drawn as colour swatches from the nation palette (T97: background and foreground) with no new art. The nation buttons are disabled until T110. Each icon is the command's `ui.command.<id>.icon` key from T101, drawn through the pack loader; a missing texture falls back to the caption as text, never an empty button.
  - **Wired here**, to commands that already exist:
    - File → **New** (the New Game flow), **Open** (`LoadGameScreen`), **Save** (T95's save), **Save As** (a name prompt, then a save under `user://saves`) and **Close** (back to the main menu). New, Open and Close first confirm that the current game will be left **[designed]**; Save does not;
    - Game → **End turn**;
    - Strategy → **News** (the news log) and **International relations** (`DiplomacyScreen`);
    - Unit map → **Cancel selection**, shortcut **Shift+X** (T99's handler);
    - Help → **Help topics**, **Show hints** and **About Imperial Conquest**.
  - **Moved**: the top bar's Save and End Turn buttons, and the bottom toolbar's Diplomacy and News buttons, become these entries. The top bar keeps the calendar and the active seat. The bottom Cities, Armies and Fleets toggles stay until T110 replaces them.
  - **Help topics** opens a short in-game help page **[designed]**: the mouse controls (left and right click, target clicks, wheel zoom, drag pan, Esc and Shift+X); one line per menu; and where the rules come from: the `classical-faithful` ruleset from the original's own data and the research reports, the `improved` preset designed. It never quotes or reproduces the original's help file (`Imperial Conquest 2.HLP`), which cannot ship.
  - **Show hints** turns tooltips on and off for every toolbar button and menu-backed control, with a check mark, as the original's `TPremierForm_ToggleHints` does. It is on by default and kept for the session.
  - **About** shows the game's name, its version, and a line saying it is a re-creation of the 1996 game.
- **Done when**:
  1. `GameCommandTableTests` asserts that the table holds exactly the audit's §1 entries minus the three seat entries, each once, under the inventory's menu and caption. It asserts that each icon key is a member of `AssetKeys.AllKeys`, and that no two rows share an id. It fails on `main` and passes after.
  2. The headless `MenuBarCheck` builds the real `MainGameScreen` and asserts that the menu bar's seven menus come in the inventory's order, with the Army, Fleet, City and Show mercenaries submenus.
  3. In the same check, the **End turn** menu item and the **End turn** toolbar button each advance the calendar by one turn, through the same handler: a counter on the table's handler is incremented by both.
  4. The **Save** menu item writes a save under `user://saves`, and `SaveResumeCheck` passes.
  5. In the same check, International relations opens `DiplomacyScreen` (`ActiveOverlay`), News toggles the news log, Help topics opens the help page, and About opens the about box. Shift+X clears a selection.
  6. With hints on, every enabled toolbar button has a non-empty tooltip. With Show hints toggled off, none has one, and the menu item's check mark follows.
  7. No disabled menu entry or toolbar button issues a command when pressed (asserted by the session's command count).
  8. `MapClipCheck` passes with the toolbar and menu bar outside the map's rect, and `ScreensCheck`, `CommandFeedbackCheck` and `MapClickCheck` pass.
  9. `dotnet build IC2.sln` and `dotnet test IC2.sln` are green, and the diff lists only Owns paths.
- **Hazards**:
  - **The icon keys are T101's**, named in its entry: `ui.command.<id>.icon` for `open`, `save`, `end_turn`, `news`, `relations`, `taxation`, `balance_sheet`, `recruit_unit`, `build_fleet`, and the Area-map and Unit-map ids listed there. Use those names exactly. Until T101 merges, rebase onto it before Done-when 1 can pass.
  - **The menu shortcuts are [open]** except Shift+X: they live in the EXE's form stream, which no report has read (audit §5, gap 2). The key handler's letters (N, A, C, F, L, Q) are known but not their modifier keys, so don't invent them.
  - **The toolbar order across groups and its separators are [open]** (audit §3.1). Use File and Game, Strategy, then Nations, and say so in a code comment.
  - The help page is new text: never paraphrase or copy the original's help file.
  - Wiring `MenuBarCheck` into `.github/workflows/ci.yml` is a one-line follow-up after the merge, not this task's.
