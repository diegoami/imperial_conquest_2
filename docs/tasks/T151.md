#### T151 A failed run keeps its work and its worktree; worktrees are cleaned up on a schedule

- **Design milestone**: none. Process tooling, the user's decision of 2026-10-08: *"relax the rules of deleting worktrees immediately after failure, throwing away diagnostics and work done. Rather plan some clean up regularly."* T140's round-2 work was lost to the implementer script's `git reset --hard` between attempts (#854), and the review script deletes a failed review's worktree and everything in it. **Labels**: `lane:infra release:v0.5.0`
- **Branch**: `task/T151-keep-worktrees`, from `origin/main` · **Model/effort**: Sonnet / Medium ([§3.3](../build-process.md#33-model-selection): the OpenCode default, the implementer picked from quota-tracker's `/best`) · **Reviewer**: the complex tier ([§3.4](../build-process.md#34-why-the-reviewers-model-differs-from-the-implementers)), GPT-6 Sol at `low`
- **Start after**: T150 (it edits both dispatch scripts) · **Merge after**: [T150](T150.md). It is **never in flight with** another task or fix under `scripts/*OpenCode*`, `scripts/external-*.ps1` or `scripts/Clean-Worktrees.ps1`.
- **Owns**:
  - `scripts/external-implement.ps1`: **only** the step between two attempts that today resets and cleans the worktree (`git reset --hard` and `git clean -fd`);
  - `scripts/external-review.ps1`: **only** the review worktree's path assignment (`$worktree = …`), `New-ReviewWorktree`, and the `finally` block's removal (`git worktree remove`);
  - `scripts/Clean-Worktrees.ps1` (new).
- **Scope**:
  - **Protects**: no game code, data, ruleset, fixture or golden. A run still starts from a clean tree. Only what happens to the *previous* attempt's state changes. Nothing is deleted that holds unpushed commits or uncommitted changes unless the user names it.
  - **Out of scope**: the documents. The process lines (§4.7 step 4, Appendix B's last instruction, Appendix C step 4) changed in this task's plan PR, and the session-start mention of the cleanup report is this task's doc claim after the merge.
- **Done when**:
  1. **A failed implementer attempt keeps its work.** Before the next model starts, the script saves the failed attempt's uncommitted state as `rendered/attempts/<model>-<yyyyMMdd-HHmmss>.patch` in the worktree (git-ignored), and prints that path. The patch is a binary-safe `git diff --binary` of the attempt's tree against its start commit taken after `git add -A --intent-to-add`, so untracked files are in it as new files, and `git apply` on a clean tree at the start commit restores them (no `git stash`). The saved patch is not removed when the next attempt resets the tree. A self-test applies a saved patch to a clean tree and gets the failed attempt's files back, untracked ones included.
  2. **A review never deletes its worktree.** Each attempt gets its own tree, `ic2-work\<pr>-review-<reviewer>-<yyyyMMdd-HHmmss>`, so no attempt's tree is reused, removed or overwritten. The script prints each tree's path in its log. Neither script runs `git worktree remove` or deletes a worktree's directory any more. The implementer script never did, and its only change is Done-when 1.
  3. **`scripts/Clean-Worktrees.ps1`** lists every worktree under `C:\Users\diego\projects\ic2-work\`, one line each: its path, branch or detached HEAD, age (last modification), PR state when the branch has one (`gh pr list --head`), and whether it is **safe**. A tree is safe only when all of these hold: (a) `git status --porcelain --ignored` shows nothing outside `bin/`, `obj/`, `.godot/` and `.vs/` (so a run's ignored diagnostics under `rendered/` count as work and keep the tree); (b) no commit on it is absent from `origin`; (c) its branch's PR is merged or closed, or, for a detached review tree, the PR it reviewed (read from its `<pr>-review-…` name) is merged or closed. An open PR's trees are never safe, whatever their age. With no switch it only lists. `-Apply` removes the safe ones that are older than `-OlderThanDays`, with `git worktree remove` and then `git worktree prune`. `-Force <path>` removes one named tree whatever its state, after printing what it holds. It never touches the main checkout. It exits 0 and prints a one-line summary (`N worktrees, S safe to remove, R removed`).
  4. A self-test (`-SelfTest`) builds temporary worktrees in each state (clean and merged; dirty; ignored files under `rendered/` only; an unpushed commit; a detached review tree of an open PR, old; a detached review tree of a merged PR) under a temp root it passes in place of `ic2-work\`, and shows the list and `-Apply` treat each as 3 says.
  5. All three scripts parse, `dotnet build IC2.sln --nologo -v q` and `dotnet test IC2.sln --nologo -v q` are green, and `git diff --name-only origin/main...HEAD` lists only Owns paths.
- **Hazards**:
  - **Disk.** Keeping every review tree grows `ic2-work\` by one clone-sized tree per review. The schedule is what bounds it, so the PR body states the size of `ic2-work\` before and after one `-Apply`.
  - **Never `git stash`** to save an attempt (Appendix A: the stash is shared by every worktree).
