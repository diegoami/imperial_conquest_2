#### T210 Global per-city auto recruit plans

- **Release / priority**: v0.8.0 required QoL; P1. [Scope](../release-plan.md#25-planned-v080-faithful-battles-and-quality-of-life-automation).
- **Storage choice**: the owner chose global automation settings. A city plan is keyed by `(worldId, cityId)` in `user://settings.json`, shared across campaigns on this machine in that world. The UI states that explicitly. It is not native-save state and adds no save-format migration. T209's global auto mobilize remains a separate switch.
- **Start after**: T209. **Owns**: `godot/UI/UserSettings.cs`, `godot/UI/SettingsScreen.cs`, `godot/UI/Dialogs/RecruitUnitDialog.cs` (plan controls only), `godot/UI/MainGameScreen.cs` (confirmed End-turn automation sequence/summary only), a new Godot-free `godot/UI/Automation/AutoRecruitPlanner.cs`, `tests/IC2.Engine.Tests/IC2.Engine.Tests.csproj` (planner link), `tests/IC2.Engine.Tests/Ui/UserSettingsTests.cs`, a new `tests/IC2.Engine.Tests/Ui/AutoRecruitPlannerTests.cs`, `godot/Checks/SettingsCheck.cs`, `godot/Checks/StrategyDialogsCheck.cs`, `godot/Checks/EndTurnBoxCheck.cs`, `docs/release-plan.md` (storage clarification). `RecruitUnitDialogModel`, engine `RecruitStandingUnitCommandHandler`, rulesets and native save schema are read-only.

### Scope

Add a global default-off **Auto recruit** switch to the Automation tab. From the existing Recruit unit dialog, a selected **specific owned city** can save or clear one plan: unit type, troop count on its normal increment/limits, and desired count of queued regiments at that city (1–40). Do not attach a plan to the `All cities` selector. Editing a plan submits no game command. The plan's world and city IDs prevent plans for one campaign map from acting in a different world. A stale, foreign, missing, ineligible or no-longer-valid plan is retained in settings but skipped with a visible reason; the player can clear it. A global plan intentionally applies in another campaign of the same world if the city is owned there.

On confirmed human End turn, run **T209 auto mobilize first**, then auto recruit, then T207/T208 support, then one ordinary `end`. Visit the current world's cities in authored order. For each owned city with a plan, if fewer than the plan's desired number of that city's units are in the active nation's training queue, propose at most **one** `recruit-standing <city> <type> <troops>` through the existing session path. Use the existing `RecruitTroopBounds`, `RecruitmentEligibility` and `StandingRecruitmentCost` for preflight; let the engine make the final decision. Respect the shared treasury reserve even under Classical Faithful, so automation never deliberately creates new debt. Honor the 40-slot table and 100% mobilization gate. Re-read live state and treasury after each accepted order; a refusal is reported but does not stop the next city or End turn. Newly ordered slots are not ready for T209's earlier mobilization pass.
