#### T153 The guard and the run report see every path outside the worktree, bash commands included

- **Design milestone**: none. Process tooling, from bug [#875](https://github.com/diegoami/imperial_conquest_2/issues/875), the user's decision of 2026-10-08 to make it a task next after T152. T152's rework run (mm-m3, session `ses_ee2fa07dcffenhznsGbp1QlMgM`) wrote three scratch scripts to the TEMP root with `cat > /tmp/… <<EOF` and ran one with `pwsh -File /tmp/…`. Every call completed. OpenCode's `external_directory` guard catches a path *argument* (its `rm -f /tmp/…` was rejected) but not a shell redirection or an interpreter's script path. T150's "Outside paths touched" report lists only paths under the two allowed roots, so it cannot show a write to a forbidden place either. **Labels**: `lane:infra release:v0.5.0`
- **Branch**: `task/T153-guard-bash`, from `origin/main` · **Model/effort**: the implementer from `/recommend?tier=heavy` with CLAUDE.md rule 17's exclusions / Medium · **Reviewer**: the complex tier ([§3.4](../build-process.md#34-why-the-reviewers-model-differs-from-the-implementers)), GPT-6 Sol at `low`
- **Start after**: T152 · **Merge after**: [T152](T152.md) (it edits `external-implement.ps1`). It is **never in flight with** T151, T152, or another task or fix under `scripts/*OpenCode*`, `scripts/external-*.ps1` or `.opencode/**`.
- **Owns**:
  - `scripts/Invoke-OpenCodeWatched.ps1`: **only** `Get-OpenCodeOutsidePathsInText`, `Get-OpenCodeOutsidePaths` and the fields of the run object they fill;
  - `scripts/external-implement.ps1`: **only** `Format-OutsidePathsReport` and the lines that print it and append it to the PR body;
  - `.opencode/agents/external-implementer.md` and `.opencode/agents/external-reviewer.md`: **only** the `bash` permission block;
  - `scripts/fixtures/opencode-export-outside.json` (new): a canned session export (no secrets, no real session content beyond the tool calls' command strings) for the tests.
- **Scope**:
  - **Protects**: no game code, data, ruleset, fixture or golden. Nothing that T150's two allows permit today (`~\.local\bin\*`, `%TEMP%\opencode\*`) is denied, and the `..` denies stay. No read of `auth.json`, `opencode.db` or any key.
  - **Out of scope**: OpenCode's own permission engine. The fix lives in our agent files and our report.
- **Done when**:
  1. **The report sees every outside path.**
     - `Get-OpenCodeOutsidePaths` returns every path outside the run's worktree that any recorded tool call names: a `read`/`write`/`edit`/`list`/`glob`/`grep` path argument, or a `bash` command line. In a `bash` command line that means a redirection target (`>`, `>>`, `2>`, `tee`), an interpreter's script path (`pwsh -File`, `python`, `bash`), and any other absolute or `/tmp`-style path.
     - Each path is marked **allowed** (under T150's two allows) or **not allowed**.
     - `Format-OutsidePathsReport` prints the not-allowed ones first, under "Outside paths touched — NOT allowed", with each attempt's model. The run's log and the PR body carry the same section.
     - A path that only appears in the prompt or in tool output still does not count, as in T150.
  2. **`bash` cannot write to the TEMP root.**
     - Both agent files' `bash` block denies, after its `"*": allow`, any command line that names `/tmp/`, `C:?Users?diego?AppData?Local?Temp?` or `$env:TEMP`/`%TEMP%`, unless the path continues into `opencode?`.
     - The patterns are written so the `%TEMP%\opencode\*` allow T150 gives still works: last match wins, so the `opencode` allow follows the deny.
  3. **Tests, offline, with no real OpenCode run:**
     - **The pattern test:** T150's allow-pattern test, extended, feeds both agent files' rules a list of command lines and checks each lands on the intended outcome. It covers:
       - `cat > /tmp/x.ps1`, `pwsh -File /tmp/x.ps1` and `echo hi > C:/Users/diego/AppData/Local/Temp/x.txt`: denied;
       - `type $env:TEMP\x` and `rm %TEMP%\x`: denied;
       - `cat > C:/Users/diego/AppData/Local/Temp/opencode/x.txt`: allowed;
       - `godot --headless …` and `git -C … status`: allowed.
     - **The export test:** `scripts/fixtures/opencode-export-outside.json`, holding the three calls of T152's run as recorded plus a `%TEMP%\opencode` write and an in-worktree write, gives exactly the three `/tmp` paths as not allowed, the `%TEMP%\opencode` one as allowed, and nothing for the worktree.
  4. **After the merge,** the first real run whose session names an outside path is recorded on #875 with its report. A not-allowed path it shows is a finding, not a pass.
  5. All touched scripts parse, `dotnet build IC2.sln --nologo -v q` and `dotnet test IC2.sln --nologo -v q` are green, and `git diff --name-only origin/main...HEAD` lists only Owns paths.
- **Hazards**:
  - **Don't over-deny.** A pattern that also matches the worktree, `rendered/`, or the Godot shim would end every Godot run. The pattern test's allowed cases are the guard against that.
