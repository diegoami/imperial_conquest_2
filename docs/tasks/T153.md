#### T153 Agents may use TEMP freely, and the run report lists every path outside the worktree

- **Design milestone**: none. Process tooling, from bug [#875](https://github.com/diegoami/imperial_conquest_2/issues/875), the user's decision of 2026-10-08: *"why do you have such a problem if they write to TMP! Let them."*
  - **What happened:** T152's rework run (mm-m3, session `ses_ee2fa07dcffenhznsGbp1QlMgM`) wrote scratch scripts to the TEMP root (`cat > /tmp/… <<EOF`, then `pwsh -File /tmp/…`), and that was harmless. What ended the run was the guard rejecting its cleanup, `rm -f /tmp/…`.
  - **The fix:** agents may read and write the TEMP root, so no TEMP access ever ends a run. The run report lists every outside path a run touched, for information, not as a fault.
  - **Labels**: `lane:infra release:v0.5.0`
- **Branch**: `task/T153-temp-allowed`, from `origin/main` · **Model/effort**: the implementer from `/recommend?tier=heavy` with CLAUDE.md rule 17's exclusions / Medium · **Reviewer**: the complex tier ([§3.4](../build-process.md#34-why-the-reviewers-model-differs-from-the-implementers)), GPT-6 Sol at `low`
- **Start after**: T152 · **Merge after**: [T152](T152.md) (it edits `external-implement.ps1`). It is **never in flight with** T151, T152, or another task or fix under `scripts/*OpenCode*`, `scripts/external-*.ps1` or `.opencode/**`.
- **Owns**:
  - `.opencode/agents/external-implementer.md` and `.opencode/agents/external-reviewer.md`: **only** the `external_directory` block;
  - `scripts/Invoke-OpenCodeWatched.ps1`: **only** `Get-OpenCodeOutsidePathsInText`, `Get-OpenCodeOutsidePaths` and the fields of the run object they fill;
  - `scripts/external-implement.ps1`: **only** `Format-OutsidePathsReport` and the lines that print it and append it to the PR body;
  - `scripts/fixtures/opencode-export-outside.json` (new): a canned session export (tool calls' command strings only, no secrets) for the tests.
- **Scope**:
  - **Protects**: no game code, data, ruleset, fixture or golden. `~\.local\share` (the OpenCode data roots, `auth.json`, `opencode.db`), keys, the private fixtures and `assets.local.ini` stay unreachable. T150's `..` denies stay. The allow covers the TEMP directory itself and nothing above it.
  - **Out of scope**: OpenCode's own permission engine.
- **Done when**:
  1. **TEMP is allowed.**
     - Both agent files' `external_directory` allow the whole TEMP root, `C:?Users?diego?AppData?Local?Temp?*`, in place of T150's narrower `…Temp?opencode?*`, after the `"*": ask` and before T150's `..` denies (last match wins, so the denies still close a traversal).
     - `/tmp/…` in a `bash` command maps to the same directory under Git Bash, so a command naming it reaches the same allow. If OpenCode asks for it under another spelling, that spelling is allowed too, and the PR says which.
  2. **The report lists every outside path.**
     - `Get-OpenCodeOutsidePaths` returns every path outside the run's worktree that any recorded tool call names: a `read`/`write`/`edit`/`list`/`glob`/`grep` path argument, or, in a `bash` command line, a redirection target (`>`, `>>`, `2>`, `tee`), an interpreter's script path (`pwsh -File`, `python`, `bash`) or any other absolute or `/tmp`-style path.
     - `Format-OutsidePathsReport` lists them for information, each with its attempt's model. The run's log and the PR body carry it.
     - A path that only appears in the prompt or in tool output does not count, as in T150.
  3. **Tests, offline, with no real OpenCode run:**
     - **The pattern test:** T150's allow-pattern test, extended, checks:
       - `C:\Users\diego\AppData\Local\Temp\x.ps1`, `C:/Users/diego/AppData/Local/Temp/sub/x.txt` and the `opencode` subfolder: allowed;
       - `C:\Users\diego\AppData\Local\Temp\..\..\Roaming\x` and `…\Temp\..\Local\…`: denied (T150's `..` denies);
       - `C:\Users\diego\AppData\Local\Temp2\x` (a sibling): still asks;
       - `~\.local\share\…\auth.json`: still asks.
     - **The export test:** `scripts/fixtures/opencode-export-outside.json`, holding the three `/tmp` calls of T152's run plus a worktree write and a `~\.local\bin` call, lists the three `/tmp` paths and the `~\.local\bin` one, and nothing for the worktree.
  4. **After the merge,** the first real run that touches TEMP is recorded on #875 with its report. A rejection there reopens the task as a bug.
  5. All touched scripts parse, `dotnet build IC2.sln --nologo -v q` and `dotnet test IC2.sln --nologo -v q` are green, and `git diff --name-only origin/main...HEAD` lists only Owns paths.
- **Hazards**:
  - **Allow TEMP, not its parents.** A pattern that also matched `AppData\Local\*` would open `~\AppData\Local` wholesale. The pattern test's sibling and traversal cases guard against that.
