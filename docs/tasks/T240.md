# T240 — The army table keeps dead slots until the original's sweep

Triage of #1601, owner decision 2026-10-30: fix it. Evidence: [`2026-10-30-army-table-order-after-deaths117.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/150d95d/docs/reports/2026-10-30-army-table-order-after-deaths117.md) and [`2026-10-30-all-ashore-army-order1439.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/150d95d/docs/reports/2026-10-30-all-ashore-army-order1439.md) (research `150d95d`).

**The original:**
- A dead army's record is left in its slot, marked dead (a tombstone). A new army is appended after every slot, dead or alive.
- The sweep `FUN_0044adb0` walks the table from the last index down, and `FUN_0044abe0` swap-removes each tombstone: the last record moves into the dead slot.
- The sweep runs at the start of `FUN_00451fdc`, when a human ends the turn, and before each AI seat.
- In the #232 campaigns, survivors kept their order in only 4 of 43 death turns, and the sweep model reproduces 42 of the 43; deaths after the last sweep stay as dead records in the End-turn autosave until the next End turn's first sweep. These are the report's corrected figures (receipt-based pairing, research [`325c94c`](https://github.com/diegoami/imperial-conquest-2-research/blob/325c94c/docs/reports/2026-10-30-army-table-order-after-deaths117.md)); the version above, at `150d95d`, gave 2 of 19 and 18 of 19.

**The faithful AI** reads the table in order: the small-army merge `FUN_004509f0` picks its donor and receiver by index, and the army phase visits armies in index order.

**The remake** closes the gap at once and keeps the survivors in order.

## Contract

- **A ruleset flag**, `armyTableCompaction`: `swapRemoveSweep` for `classical-faithful`, `inOrder` for the other shipped rulesets. Its `_provenance` names the reports above and the owner's decision. `inOrder` changes nothing.
- **Dead slots** under `swapRemoveSweep`:
  - Removing an army leaves a dead slot at its table position until the next sweep. The live army list stays the live armies in table order.
  - A new army takes the next slot after every slot, dead or alive.
  - Record dead slots in **one place**, covering every way an army leaves the table (battles, disbands, joins, transfers, the AI's absorb, elimination, armies lost with a fleet). For example, the command dispatcher and the system pipeline can compare the army list before and after each accepted step, instead of editing each removal site.
  - Check that every removal keeps the survivors' relative order, and that every creation appends. Report any site that does not, rather than reordering it silently.
- **The game state** keeps the dead slots, as an optional field that is empty by default. A remake save carries them, so saving mid-turn and loading gives the same later sweep. Older saves load with none. Original-SAV import and export are unchanged: an exported save holds the live armies in their current order.
- **The sweep** reproduces `FUN_0044adb0`/`FUN_0044abe0` exactly: from the last slot down, each dead slot takes the record currently in the last slot. It runs when a human seat ends its turn and before each AI seat's turn. Fleets are out of scope (`FUN_0044ad7c`), and so is which path leaves a dead record across an End turn in the original.
- No rule other than army order changes. The designed (`inOrder`) rulesets keep today's order exactly.
