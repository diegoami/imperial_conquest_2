#### T122 The tactical battle's constants and computer-general tables as ruleset data

- **Design milestone**: M21 (the tactical battle, v0.5.0 *Battles*, [#496](https://github.com/diegoami/imperial_conquest_2/issues/496)). It is the data half of the port: it puts every gameplay constant of `game-design.md`'s Combat, "The tactical battle", into the rulesets ([build-process.md §2.6](../build-process.md#2-how-the-build-avoids-conflicts)), so that T123 and T124 read them instead of writing literals (design principle 1). It also exports each nation's three battle colours into the world data, for T128's icon recolour (the user's decision of 2026-10-04 on #496, answer 7). **Labels**: `phase:2 lane:data local-only`
- **Branch**: `task/T122-tactical-ruleset-data` · **Model/effort**: Sonnet / High · **Reviewer**: **Opus**/Medium: **very complex** under [§3.4](../build-process.md#34-why-the-reviewers-model-differs-from-the-implementers) criterion (c), since it adds fields to a serialized model type (`Ruleset`)
- **Start after**: none · **Merge after**: none. T123 and T124 start after this task. It is **never in flight with** T121 (any change to `data/rulesets/*.json`'s `combat` or `unitTypes` moves the tournament mid-run), or with another task that adds a `Ruleset` field or edits the three rulesets, the exporter or `tests/fixtures/corpus.json` (T56, T67, T72, T76, T81, T115, T118, T119).

- **Scope**:
  - **Protects**: the decompiled tactical-battle constants and computer-general tables as the rulesets carry them (every value in the table below, cell by cell, in all three rulesets), the 16 nations' battle colour triples as the original's nation records hold them; and every existing corpus value, ruleset value, world value and seeded outcome, none of which may move.
  - Every value below is **[confirmed: code, static, [`2026-10-04-decompiled-tactical-battle-rules.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/main/docs/reports/2026-10-04-decompiled-tactical-battle-rules.md) (research `f5c8579`, corrected in `b5db496`)]** with the section named; the field names are **[designed]**. `game-design.md`'s Combat, "The tactical battle", is the contract; this task carries its constants and nothing else.
  - **`unitTypes[].shotVulnerability`** (stat `+0x20`, report §4): light infantry 18, heavy infantry 2, archers 18, light cavalry 15, heavy cavalry 4. The moves, shots, range and `standardBattalionSize` the battle reads are already `unitTypes` fields and do not change.

  - **What stays where it is.** The matrix (`combat.detailedResolver.typeEffectiveness`, T120), `meleePowerDivisor` 2000, `meleeBasePowerFloor` 12, `meleeLossHardCap` 30000, the 40 % cap and its `+ 1`, `inRangeShotMultiplier` 2, and the write-back's quality floor 6, cap 9, promotion 1-in-4, unity ±25 (cap 990) and supply divisor 100, are already ruleset fields: T123 reads them there. The melee's `(5 − f)` and `(2f + 5)` factors and the Bresenham arithmetic are formula shape and stay in code, cited.
  - **Provenance.** Each new note cites the report section, preset-neutral, because the exporter copies the toy notes into `classical-faithful.json` (`NoToyProvenanceWordingTests`). `improved.json` carries the same values here: `improved`'s differences (`game-design.md`, "What `improved` changes", the user's decisions of 2026-10-04 on #496) are T130's switches, added later. No value differs in this task.
  - **Who reads them.** Nothing, until T123 and T124. No shipped outcome moves.
  - **The battle colours** **[confirmed: code, static, [`2026-10-04-decompiled-tactical-battle-rules.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/main/docs/reports/2026-10-04-decompiled-tactical-battle-rules.md) §10: `FUN_0044A6C8` replaces an icon's purple `0x800080` with the nation record's `+0x424`, its white with `+0x428` and its blue with `+0x42C`]**. The offsets are the in-memory and SAV nation record's (the space of `SaveNationTable`'s `+0x490`); the report names them by that use only and did not read their values. Each is a 4-byte Delphi `TColor` (`0x00BBGGRR`) [derived: the 4-byte stride]. The SAV holds the three words in 12 bytes right after its recruitment queue (`+0x424`…`+0x430`), a block the DAT's nation record does not have: the DAT record continues past its queue with wealth (`+0x409`) to the tax base (`+0x41B`), and none of the triples occurs anywhere in the DAT (checked across 111 saves by the review of PR 677; corrected 2026-10-04, replacing a derived uniform `0x27` shift that placed them inside the DAT's queue). So the exporter reads them from the nation records of the start save the fixtures name (`1_rome_270_winter_11.sav`), checks them against a second save, and the world gets `battleColorsHex` per nation, in that order. Its note cites the report §10 and the offsets.

- **Hazards**:
  - **The colours live in the SAV only** (the review of PR 677 read them in 111 saves: one triple per nation, none in the DAT). If they differ between saves of the same nation (the game setting them at runtime, or the player choosing them), stop and report: the world would then need a rule, not a value.
  - **The rulesets are the contract.** Every value goes corpus first, then `toy-ruleset.json` by hand, then the exporter; never hand-edit `classical-faithful.json` ([build-process.md §2.6](../build-process.md#2-how-the-build-avoids-conflicts)). The reproducibility test is local-only: run it on a machine with the original files and paste the output. Without them, stop and report.
  - **Do not re-read the report's values into anything else.** The `Form` table is the 20 values the clone carried as the matrix before T120 (#647); here they are what the code reads them as, the AI's placement formations. A reviewer checks every value cell by cell against the report, not against the old corpus.
  - **Add, never re-baseline.** No existing corpus value, ruleset value, golden or pinned hash moves. If one does, stop and report.
  - **No logic.** The task adds fields and their loading; it implements no rule. A rule that needs a field this list lacks is T123's or T124's to raise as a rework of this entry, not to add as a literal.
