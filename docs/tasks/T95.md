#### T95 Save and resume a game

- **Design milestone**: none. It is a correction for bug [#467](https://github.com/diegoami/imperial_conquest_2/issues/467), found by T24's implementer. It was planned on 2026-09-28 by the user's decision, inside the v0.4.0 gate (build-process §4.8: "a save that will not load"). **Labels**: `phase:3 lane:engine single-instance` · **Release**: `release:v0.4.0`
- **Branch**: `task/T95-save-and-resume` · **Model/effort**: Sonnet / High · **Reviewer**: **Opus / Medium**
- **Start after**: T24 · **Merge after**: T24. It wires T24's Load screen, so it is **never in flight with T25 or T94**, which also work under `godot/**`.
- **Owns**:
  - `src/IC2.Engine/Presentation/GameSession*.cs`: **only** building a session from a restored `SaveGame` (a second constructor or a factory), and the `save <path>` and `load <path>` commands
  - `src/IC2.Cli/Program.cs`: **only** a `--load <path>` flag that starts the session from a save, if the `load` command alone can't serve the CLI
  - `godot/UI/LoadGameScreen.cs` and `godot/UI/MainGameScreen.cs`: **only** resuming the chosen save, and a Save action in the main game screen
  - new tests under `tests/IC2.Engine.Tests/Presentation/**` and `tests/IC2.Engine.Tests/Ui/**`; `tests/fixtures/cli/*.golden.txt` regenerated under build-process §2.3 if the help text changes
- **Scope**: T20's `SaveManager` writes and reads a `SaveGame` (`WriteFile`, `LoadFile`, `PeekSummaryFile`), but nothing a player uses reaches it. `GameSession` has one constructor, which always calls `GameStateFactory.CreateInitial`, and no save or load command. So the CLI and T24's Godot UI play one sitting only, and T24's Load screen can list saves but not resume them.
- **Done when**:
  1. **Save.** `save <path>` writes the current game through `SaveManager.WriteFile`, from the CLI and from the Godot main game screen.
  2. **Resume.** A session built from a loaded `SaveGame` continues the same game: the same state, the same seats, and the same active seat and phase. `load <path>` (or `--load`) resumes it in the CLI, and T24's Load screen resumes the chosen save in Godot.
  3. **Deterministic continuation.** A seeded game saved at turn N and resumed plays the next turns exactly as the uninterrupted game does. A test compares both transcripts byte for byte, so the random stream resumes where it stopped.
  4. **The human seat after a load** is worked out from the saved state (`NationState.Control`), not from the scenario or `--seat`, per T83's #382 hazard. A test saves in a `--seat` session and resumes it.
  5. **Errors.** A missing file, a malformed save, and a save for a different world or ruleset are each refused with a message, and the session keeps running. A test for each.
  6. `dotnet build IC2.sln` and `dotnet test IC2.sln` green; a headless Godot check scene saves, resumes and ends a turn, exiting 0; `scripts/check-godot-churn.ps1` clean after it. The diff lists only Owns paths.
- **Hazards**:
  - **The random stream.** `GameState` carries `RandomSeed`. Check how the engine derives each turn's draws from it before assuming a resume is deterministic, and stop and report if the stream's position is not part of the saved state.
  - **T94 overlap.** T94 owns malformed-save handling in `MapViewer` and the #382 load-seat hazard for the Load *flow*. This task covers the engine and the resume path; say in the PR what it leaves to T94.
