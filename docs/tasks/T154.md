#### T154 A review run reads its brief from inside its own worktree

- **Design milestone**: none. Process tooling, the user's decision of 2026-10-09 ("L60 is a no brainer, plan it right after 0.5.0"), from the harness template's lesson L60: the brief passes as a file inside the worktree, so the prompt names no path outside it. T150 did this for the implementer (`external-implement.ps1` copies `-BriefFile` to `rendered/brief.md` in the worktree and feeds the copy). The review script still feeds the main checkout's `rendered/review-tier/<pr>-<reviewer>.md`, which is outside the review worktree, so a reviewer that goes back to re-read its brief is rejected by the `external_directory` guard (the wiki's Agent-failures page: "the brief outside the worktree"). **Labels**: `lane:infra release:v0.6.0`
- **Branch**: `task/T154-review-brief-in-worktree`, from `origin/main` · **Model/effort**: Sonnet / Low ([§3.3](../build-process.md#33-model-selection): the OpenCode default, the implementer picked from quota-tracker's `/recommend`) · **Reviewer**: the complex tier ([§3.4](../build-process.md#34-why-the-reviewers-model-differs-from-the-implementers)), GPT-6 Sol at `low`
- **Start after**: the v0.5.0 release. **Merge after**: [T151](T151.md) (it edits `New-ReviewWorktree` and the review worktree's path). It is **never in flight with** another task or fix under `scripts/external-*.ps1` or `scripts/*OpenCode*`.
- **Owns**:
  - `scripts/external-review.ps1`: **only** the brief's delivery: after the review worktree exists and before OpenCode starts, copy `-BriefFile` into it at `rendered/brief.md` (git-ignored, like the implementer's) and feed that copy; the `-WhatIf` line that prints the brief's path; and one `-SelfTest` case for Done-when 2.
- **Scope**:
  - **Protects**: no game code, data, ruleset, fixture or golden. The brief's text is unchanged (the copy is byte-identical). The reviewer agent's permissions do not change. Nothing else in the review run changes: the worktree's path, its removal policy (T151's) and the posting of the review stay as they are.
  - **Out of scope**: the documents. Appendix B's line on where the brief is, if one is needed, is this task's doc claim after the merge.
- **Done when**:
  1. A review run's prompt is read from `<review worktree>/rendered/brief.md`, a byte-identical copy of `-BriefFile`, and the run's log prints that path.
  2. A `-SelfTest` case builds a temporary worktree, runs the copy step, and shows the copy exists inside the worktree, matches the source byte for byte, and is ignored by git (`git status --porcelain` shows nothing for it).
  3. `pwsh scripts/external-review.ps1 -SelfTest` passes, `dotnet build IC2.sln --nologo -v q` and `dotnet test IC2.sln --nologo -v q` are green, and `git diff --name-only origin/main...HEAD` lists only Owns paths.
- **Hazards**:
  - **The implementer's copy is the model.** Reuse its path and its git-ignore rule rather than inventing a second convention.
  - **Never `git stash`** (Appendix A).
