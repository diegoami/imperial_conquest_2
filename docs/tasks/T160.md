- **Scope**:
  - **Protects**: when Transfer ships leaves the giving fleet with 0 ships, the receiver gets the giver's money and supplies **whole**, the giver is deleted, and **the treasury does not change**, in every preset.
  - **The rule** ([`2026-10-10-fleet-emptied-by-transfer-money-and-supplies.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/6b96537/docs/reports/2026-10-10-fleet-emptied-by-transfer-money-and-supplies.md), research `6b96537`, **[confirmed: Wine]** for the giver-emptied branch, cases Td0–Td2; **[code]** for "no cap on the sum"):
    - The receiver's money becomes `PurseAccounting.Credit(target.Money, source.Money)`: the sum, with no `economy.purseCapPerUnit` clamp. The supplies are pooled whole, as today.
    - **At the field's bound** (not observed in the original): the sum saturates at `PurseAccounting.PurseFieldMax` (32,767) and the excess is discarded, the purse policy `PurseAccounting.Credit` already documents. This is `[designed]`, the user's decision of 2026-10-11 (PR #963).
    - The treasury is never credited on this path. Today's `excessToTreasury` branch is removed.
    - The `[open]` "kept behaviour (T72)" wording for this branch is replaced by the rule above with its citation. The partial-transfer path keeps its `[open]` note: the report does not settle it.
  - **Out of scope**: the partial-transfer path; the receiver-emptied branch beyond what the same code path does (the report reads it from code only); the remake's refusal of a carrying fleet, which stays (a deliberate difference, PR #963); `docs/investigations/original-ui-command-audit.md` (a post-merge docs claim).
- **Done when**:
  1. **Whole, no cap.** An emptied giver with 400 and a receiver with 123 leave the receiver at 523, the giver deleted and the treasury unchanged. A case whose sum exceeds `economy.purseCapPerUnit` (1,000 in every shipped ruleset) keeps it whole: for example, 900 + 900 = 1,800. The test fails if the old clamp is put back.
  2. **The bound.** A sum above 32,767 (for example, 30,000 + 5,000) leaves the receiver at 32,767, discards the excess, and leaves the treasury unchanged.
  3. **Supplies and deletion.** The supplies are summed whole, and the giver's id appears nowhere in the state afterwards. A save round-trips.
  4. **The partial path is unchanged.** A transfer that leaves ships on both fleets behaves exactly as before: the existing partial-transfer tests pass unmodified.
  5. **Nothing regresses.** Build and test are green; any changed expectation or golden is listed with its reason; the diff lists only Owns paths.
- **Hazards**:
  - **Deleting an entity.** The giver fleet is removed: sweep for any reference to it (incident 7).
