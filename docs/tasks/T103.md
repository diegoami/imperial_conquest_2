#### T103 A command sets the nation's tax rate

- **Design milestone**: M3 (economy). This task is for bug [#468](https://github.com/diegoami/imperial_conquest_2/issues/468), which the UI command audit's Taxation row also found ([`original-ui-command-audit.md`](../investigations/original-ui-command-audit.md) §1.3). **Labels**: `phase:2 lane:engine`
- **Branch**: `task/T103-set-tax-rate` · **Model/effort**: Sonnet / Medium · **Reviewer**: **Opus**/Medium
- **Start after**: none · **Merge after**: none. It is **never in flight with** T104, T105, T106, T107 or T108, which edit the same verb tables and success script.
- **Owns**:
  - `src/IC2.Engine/Economy/Commands/SetTaxRateCommand.cs` and `SetTaxRateCommandHandler.cs` (new);
  - `src/IC2.Engine/Presentation/GameSession.cs` (the `set-tax` case and its help line only);
  - `src/IC2.Engine/Presentation/GameSession.Commands.cs` (the `set-tax` parser only);
  - `tests/IC2.Engine.Tests/Presentation/CommandCoverageTests.cs` (the curated verb map's new entry only);
  - `godot/UI/CommandVerbCatalog.cs` (the mirror's new entry only);
  - `tests/fixtures/cli/success.txt` and `success.golden.txt` (one `set-tax` line, and the regenerated golden);
  - `tests/IC2.Engine.Tests/Economy/SetTaxRateCommandTests.cs` (new).
- **Scope**: the original's `TChangeTax` dialog writes the nation's tax rate (nation `+0x44A`) on OK **[confirmed: `decompiled-fleet-tax-and-mercenary-formulas.md`, `rome-tax-increase-and-sidon-capture.md`; the OK write is derived: code, `TChangeTax_OK`]**. Nothing in the clone writes `NationState.TaxRatePercent`.
  - **`set-tax <percent>`** sets the active nation's `TaxRatePercent` at once. The quarterly income (`taxBase × rate / 100`), the unity drift, population growth and the loyalty draws already read the field, so they use the new rate from the next quarter on.
  - **Validation**: an integer from 0 to 100 **[designed]**. The original slider's minimum and maximum are in the EXE's form stream, which no report has read (audit §5, gap 2). Out of range, or not an integer: rejected, and the state is unchanged.
  - It prints no news line: no report shows one for a tax change.
- **Done when**:
  1. `SetTaxRateCommandTests`: on the classical-mediterranean scenario, `set-tax 20` as Rome sets Rome's `TaxRatePercent` to 20, and no other nation's. It fails on `main` (no command) and passes after.
  2. After `set-tax 20`, the next quarter's tax income for Rome equals `TaxIncome.Compute(taxBase, 20, ruleset)`, and Rome's unity drift uses `tax/2 = 10`, asserted against `NationUnityUpdate`'s own result.
  3. `set-tax -1`, `set-tax 101` and `set-tax x` are each rejected, with the state unchanged.
  4. `CommandCoverageTests` passes, with `set-tax` in its curated map and an **accepted** `set-tax` line in the success script's golden.
  5. `godot/UI/CommandVerbCatalog.cs` carries the same entry. The CI `godot-headless` job's `OrderCoverageCheck` is green on the PR.
  6. `dotnet build IC2.sln` and `dotnet test IC2.sln` are green, and the diff lists only Owns paths.
- **Hazards**:
  - **The range is [designed].** If the form-stream read finds a narrower slider, that is a rule change. It goes to the bug list and then a ruleset field (build-process §2.6), not a quiet edit here.
  - The AI's own tax decisions are not this task's: it changes no AI file.
  - `godot/UI/CommandVerbCatalog.cs` is the only `godot/**` path an engine task holds. Change only the new entry: no Godot task owns that file.
