#### T103 A command sets the nation's tax rate

- **Design milestone**: M3 (economy). This task is for bug [#468](https://github.com/diegoami/imperial_conquest_2/issues/468), which the UI command audit's Taxation row also found ([`original-ui-command-audit.md`](../investigations/original-ui-command-audit.md) §1.3). **Labels**: `phase:2 lane:engine`
- **Branch**: `task/T103-set-tax-rate` · **Model/effort**: Sonnet / Medium · **Reviewer**: **Opus**/Medium
- **Start after**: the original's Taxation range. The user decided on 2026-10-01 that the range is found out first, not designed. It is read live: the `TChangeTax` slider reports minimum 0, maximum 40, line size 1 and page size 5, and OK at either end writes 0 or 40 to nation `+0x44A` **[Wine candidate: [`2026-10-02-unit-map-mouse-orders-and-tax-range.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/main/docs/reports/2026-10-02-unit-map-mouse-orders-and-tax-range.md)]**. · **Merge after**: none. It is **never in flight with** T104, T105, T106, T107 or T108, which edit the same verb tables and success script.

  - `src/IC2.Engine/Economy/Commands/SetTaxRateCommand.cs` and `SetTaxRateCommandHandler.cs` (new);
  - `src/IC2.Engine/Presentation/GameSession.cs` (the `set-tax` case and its help line only);
  - `src/IC2.Engine/Presentation/GameSession.Commands.cs` (the `set-tax` parser only);
  - `tests/IC2.Engine.Tests/Presentation/CommandCoverageTests.cs` (the curated verb map's new entry only);
  - `godot/UI/CommandVerbCatalog.cs` (the mirror's new entry only);

  - `src/IC2.Engine/Model/Ruleset.cs` (the `EconomyRules` record only), the `economy` block of `data/rulesets/classical-faithful.json`, `improved.json` and `toy-ruleset.json`, and `scripts/export-classical-world.cs` (the economy mapping only): the range is 0 to 40, not the percentage's own 0 to 100;
  - `tests/IC2.Engine.Tests/Economy/SetTaxRateCommandTests.cs` (new).
- **Scope**: the original's `TChangeTax` dialog writes the nation's tax rate (nation `+0x44A`) on OK **[confirmed: `decompiled-fleet-tax-and-mercenary-formulas.md`, `rome-tax-increase-and-sidon-capture.md`; the OK write is derived: code, `TChangeTax_OK`]**. Nothing in the clone writes `NationState.TaxRatePercent`.
  - **`set-tax <percent>`** sets the active nation's `TaxRatePercent` at once. The quarterly income (`taxBase × rate / 100`), the unity drift, population growth and the loyalty draws already read the field, so they use the new rate from the next quarter on.
  - **Validation**: an integer from **0 to 40** inclusive, the original's slider range **[Wine candidate: [`2026-10-02-unit-map-mouse-orders-and-tax-range.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/main/docs/reports/2026-10-02-unit-map-mouse-orders-and-tax-range.md)]**. Out of range, or not an integer: rejected, and the state is unchanged. The two bounds are gameplay constants, so they go into the ruleset's `economy` block (0 and 40) under [build-process.md §2.6](../build-process.md#2-how-the-build-avoids-conflicts), and `improved.json` carries the same values. The bounds come from the dialog, not the DAT or the fixtures corpus, so each carries a `_provenance` note citing the report, and the export is re-run so that `classical-faithful.json` carries them as `toy-ruleset.json` does.
  - The slider's steps (1 per arrow key, 5 per Page key) are the dialog's, T109's; the command takes any integer in range.
  - It prints no news line: no report shows one for a tax change.
- **Done when**:
  1. `SetTaxRateCommandTests`: on the classical-mediterranean scenario, `set-tax 20` as Rome sets Rome's `TaxRatePercent` to 20, and no other nation's. It fails on `main` (no command) and passes after.
  2. After `set-tax 20`, the next quarter's tax income for Rome equals `TaxIncome.Compute(taxBase, 20, ruleset)`, and Rome's unity drift uses `tax/2 = 10`, asserted against `NationUnityUpdate`'s own result.
  3. Boundary tests on the range, read from the ruleset's bounds: `set-tax 0` and `set-tax 40` are accepted; `set-tax -1`, `set-tax 41` and `set-tax x` are each rejected, with the state unchanged. Each test cites [`2026-10-02-unit-map-mouse-orders-and-tax-range.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/main/docs/reports/2026-10-02-unit-map-mouse-orders-and-tax-range.md).
  4. `CommandCoverageTests` passes, with `set-tax` in its curated map and an **accepted** `set-tax` line in the success script's golden.
  5. `godot/UI/CommandVerbCatalog.cs` carries the same entry. The CI `godot-headless` job's `OrderCoverageCheck` is green on the PR.
  6. `dotnet build IC2.sln` and `dotnet test IC2.sln` are green, and the diff lists only Owns paths.
- **Hazards**:
  - **The range comes from the reading, never from a guess.** It is a Wine-only reading, a candidate until the desktop original confirms it: if the desktop disagrees, the ruleset's two bounds are what changes. 20 % is inside it.
  - **The 0–40 range is the dialog's, the player's.** It is not the growth formula's `/120` divisor. Whether the original's AI ever sets a rate above 40 is not read, and the AI's tax is not this command's.
  - The AI's own tax decisions are not this task's: it changes no AI file.
  - `godot/UI/CommandVerbCatalog.cs` is the only `godot/**` path an engine task holds. Change only the new entry: no Godot task owns that file.
