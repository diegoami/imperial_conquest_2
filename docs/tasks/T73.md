- **Scope**: Research has located three blocks of SAV state that `IC2.Data` drops. T21 cannot import relations or turn order faithfully without them (T21 review, [PR #319 item B2](https://github.com/diegoami/imperial_conquest_2/pull/319#issuecomment-5805187494)).
  - **The nation relation matrix.** Each nation record holds 16 signed shorts at `+0x26`: `0` peace, `1` trade, `2` alliance, `3` war, and a negative value is peace with a cooldown. One setter writes both `[a][b]` and `[b][a]`, so the matrix is symmetric by construction ([`decompiled-diplomacy-peace-terms-and-instant-battles.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/main/docs/reports/decompiled-diplomacy-peace-terms-and-instant-battles.md) §"The relation matrix", including its 2026-09-24 addition). **The DAT holds the starting matrix at DAT nation-record `+0x0B`** (the DAT loader reads it straight into runtime `+0x26`, and new-game init never overwrites it). That is the parser half of #322.
  - **The saved turn order and its index.** The 55-byte trailer is `+0` turn order (16 words), `+32` pending offer (already parsed by `SavePendingOffer`), `+36` current nation, `+38` turn-order index, `+40` week, `+42` year BC, `+44` season, `+46` 8 bytes of main-window geometry (UI state), and `+54` a 1-byte battle flag ([`decompiled-sav-file-layout.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/main/docs/reports/decompiled-sav-file-layout.md), the 2026-09-14 correction, checked on 54 saves). `SaveTurnState` reads only `+36…+45`.
  - **The news log.** It sits between the mercenary table and the trailer as `int16 newsIndex` (−1 … 39), then `newsIndex + 1` slots of 61 bytes. Each slot is a NUL-terminated single-byte string of at most 60 bytes, and stale bytes after the NUL are real file content. The layout `100,956 + 2 + A×656 + 2 + F×26 + 18,752 + 600 + 2 + (newsIndex+1)×61 + 55` accounts for all 54 measured saves exactly. **The DAT's last 2,440 bytes are the 40-slot new-game seed.** The index 26 comes from EXE code (`FUN_00448AA4`), and the DAT does not store it ([`news-log-format-and-messages.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/main/docs/reports/news-log-format-and-messages.md) §Q1).
  - **Out of scope**: mapping any of this into the engine (T21 for a save, #322 for a new game); the mercenary position (#321's separate question); the trailer's window geometry and battle flag, which are UI state.
- **Done when**:
  1. **Relations are parsed.**
     - `NationRecord` exposes the nation's 16-entry signed relation row for a SAV (`+0x26`) and for the DAT (`+0x0B`, a cited `DatLayout` constant).
     - The parse throws `InvalidDataException` when a diagonal entry is non-zero, when the matrix is not symmetric, or when a value lies outside a range whose bounds are **cited**. The lower bound comes from the setter's cooldown table (−24 after an alliance is the most negative value any documented writer produces); it is never the corpus minimum.
     - Tests on a synthetic save cover a war, a trade, an alliance, a cooldown, and each rejection.
  2. **The leader field is 27 bytes.** The SAV leader name is read from `+0x0B` up to `+0x25` inclusive, not 34 bytes. A synthetic record whose leader fills all 27 bytes with no NUL, followed by a non-zero relation row, parses to that 27-character leader. Relation bytes must not leak into it. Every corpus leader is unchanged, and the PR shows that.
  3. **Turn order is parsed.** `SaveTurnState` exposes `TurnOrder` (16 nation codes) and `TurnOrderIndex`. The parse throws unless the order is a permutation of 0..15, the index is 0..15, and `TurnOrder[TurnOrderIndex] == CurrentNationCode`. On `1_thracia_271_spring_3.sav`, a test shows Thracia at index 5 of 16. For the DAT, `SaveTurnState.Parse` still throws `DatDataNotPresentException`: the DAT has no trailer.
  4. **The news log is parsed.** `SaveNewsLog.Parse` returns the newest index and the `newsIndex + 1` slot texts for a SAV, in slot order (oldest first). It throws when the layout does not account for the file length exactly, when a slot has no NUL within 61 bytes, or when text holds a byte outside 0x20–0x7E. For the DAT it returns the 40 stored slots and **no** index. Tests:
     - A synthetic log that is full, one that is partial, and one that is empty (index −1).
     - A `" "` entry survives as a single space, never trimmed.
     - On the configured machine, the DAT's slot 0 and slot 26 match the report's quoted text (if the spacing differs, the bytes win and the PR says so), and slots 27–39 are empty.
  5. **Corpus check.** `CorpusFixtures/SaveTailSweepTests.cs` parses every save in the configured corpus (by directory, through `CorpusFileLocator`) and asserts:
     - all of 1–4's invariants hold;
     - the last date header in the news log names the same week, season and year as the trailer, wherever the log holds a header (the report finds 54 of 54).
     A save that breaks an invariant is a stop-and-report, never a loosened assertion. The test skips explicitly when the original files are not configured; CI runs it over the fixtures repository.
  6. **Docs affected** lists `docs/investigations/dat-file-layout.md` (the DAT's relation row at `+0x0B` and the news seed as parsed fields), for the main session to apply after the merge.
  7. `dotnet build IC2.sln` and `dotnet test IC2.sln` are green, and the diff lists only Owns paths.
- **Hazards**:
  - **The relation row starts inside the leader field as it is read today.** `SaveNationTable` reads the leader over 34 bytes (`offset + 11`, length 34), which runs to `+0x2C`. Every corpus leader has a NUL before `+0x26`, so nothing shows the overlap yet. Adding the row without narrowing the leader leaves two fields claiming the same bytes.
  - **Do not repair what the original writes.** The quarterly thaw only runs over the first 8 columns, so a cooldown between two nations both indexed ≥ 8 never decays. Such values are real, and the parser reports them as they are.
  - **Stale bytes after a slot's NUL are file content, not corruption.** 1,117 of 2,101 corpus slots carry them. Validate only the text up to the NUL.
  - **Stricter validation reaches every caller**: `SaveTurnState`'s (Done-when 3), and `SaveNationTable`'s relation checks and narrower leader field (Done-when 1–2).
    - `IC2.Inspect` (`Program.cs`, `CorpusOutcomes.cs`, `SaveJsonExporter.cs`) and `CorpusSweepTests` parse every corpus save through them. Run the full suite on the configured machine before claiming 7.
    - **Two callers are outside `IC2.sln`**, so `dotnet test` never runs them: `godot/MapViewer.cs` (~:390–392, both parses) and `scripts/export-classical-world.cs` (~:51, `SaveNationTable.Parse` on the DAT). Run the exporter once and show that its output is unchanged. Say in the PR that `MapViewer` was not exercised; it catches `InvalidDataException`.
