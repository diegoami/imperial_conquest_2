#### T165 Load game browses to any folder and opens the original's .sav files

- **Design milestone**: M18 (the Godot screens). Planned from bug [#1002](https://github.com/diegoami/imperial_conquest_2/issues/1002), the user's report of 2026-10-11: *"I would like to load files generated from the old game, but in the load game interface I cannot change directory."* Load game lists only `*.json` in `user://saves` (`LoadGameScreen.cs:54`, `:102`). The engine already imports an original `.sav` (`OriginalSaveImporter`, T21; `OriginalSaveImportRealSaveTests`), but no screen or verb exposes it. The user placed it in v0.5.3 on 2026-10-12. **Labels**: `lane:ui release:v0.5.3`
- **Branch**: `task/T165-load-original-saves`, from `origin/main` · **Implementer and reviewer**: the user's choice ([CLAUDE.md](../../CLAUDE.md) rule 17)
- **Start after**: none · **Merge after**: none.
- **Owns**:
  - `godot/UI/LoadGameScreen.cs` and `godot/UI/LoadGameScreen.tscn`: a Browse control that opens a file dialog over the whole file system, filtered to `*.json` and `*.sav`, beside today's list of `user://saves`.
  - `godot/UI/LoadGameModel.cs` (new, no `using Godot`): opens a chosen path. A `.json` goes through `SaveManager.LoadFile` as today; a `.sav` goes through `OriginalSaveImporter.Import` onto the shipped `classical-mediterranean` world and scenario and the `classical-faithful` ruleset (the importer's `RequiredWorldId` and `RequiredRulesetId`). Either returns a `GameSession` or a message.
  - `tests/IC2.Engine.Tests/IC2.Engine.Tests.csproj`: one `<Compile Include>` line linking `LoadGameModel.cs`, in the style of the other `godot/UI` links there.
  - Tests: `tests/IC2.Engine.Tests/Ui/LoadGameModelTests.cs` (new); one new headless check under `godot/Checks/`, or `SaveResumeCheck.cs` extended (its load steps only).
- **Scope**:
  - **Protects**: a player can open any remake save or original `.sav` from any folder through Load game, and a file that cannot be opened gives a message, never a crash or a half-started game.
  - **The rule**:
    - **Browse.** Load game keeps its list of `user://saves` and gains a Browse control. The dialog starts in the last folder browsed this session (otherwise the saves folder) and lists folders, `*.json` and `*.sav`.
    - **A `.json`** from any folder resumes exactly as a listed save does today (same world, ruleset and scenario checks and messages).
    - **A `.sav`** is imported with `OriginalSaveImporter.Import`, with the shipped scenario supplying the seed, as its parameters document. The importer sets each seat human or AI from the save's own human flag (`OriginalSaveImporter.cs:257`), so the player resumes as the save's human nation(s). A save with no human seat gets a message and starts nothing (`[designed]`: the original always has one; the implementer states what it searched). The import's own errors (`SaveContextMismatchException`, `InvalidDataException`) become a message naming the file.
    - **Saving** an imported game writes a remake `.json` save as today; nothing writes `.sav`.
  - **Why it stays whole** (build-process.md §4.11): the browser and the import share `LoadGameScreen.cs` and the new model, and a browser that cannot open `.sav` meets only half of the user's report.
  - **Hazard**: an imported original save has never been played through the app. If the engine fails on one (an exception, a stall, a refused first order), that is a defect in merged code: **stop and report it** for the bug list (build-process.md §4.6); do not patch the engine here.
  - **Out of scope**: a CLI import verb; writing `.sav`; importing onto any other world or ruleset.
- **Done when**:
  1. **Browse.** A test of the model, or the headless check, shows that a chosen folder's `*.json` and `*.sav` are offered and other files are not.
  2. **A remake save from another folder.** A headless check saves a game, copies the save to a temporary folder outside `user://saves`, opens it through Browse's path, and resumes it on the same turn and active seat. It fails on `origin/main`.
  3. **An original save.** Through `LoadGameModel`, a real fixture save (resolved by name, as the import tests do; for example `1_rome_270_winter_7.sav`) opens into a `GameSession` whose active seat is the save's human nation and whose turn matches the import, and one end of turn then completes without an exception. The test is skippable only when no fixtures are configured, like `OriginalSaveImportRealSaveTests`; CI configures them.
  4. **Bad files.** A truncated `.sav`, a `.sav` with no human seat (if one can be built from a fixture's bytes; otherwise the implementer says why not), and a `.json` naming an unknown world each give a message naming the file, and no session starts.
  5. **Nothing regresses.** Build, test and all Godot headless checks are green, and the diff lists only Owns paths.
