# T267 — Own-turn tactical Undo

Issue [#1700](https://github.com/diegoami/imperial_conquest_2/issues/1700),
implementing #1674. Owner decisions (2026-11-01): undo only the current human
tactical turn, repeatedly to its beginning; an own-turn battle-ending action
remains undoable before Battle ended OK; post-battle continuation pauses until
Undo or OK; history is session-only and resets on load.

Own exact TacticalBattleSession checkpoint/restore, GameSession tactical history
and deferred acknowledgement, tactical/result UI controls and replay/audio reset,
their focused engine/Godot controls and docs. No strategic Undo or redo.
Computer general remains an ordinary delegated command: it can be undone only
if it did not cross an opponent turn. A run spanning opponent turns clears prior
history; Undo does not rewind that run across them.

Restore the immutable full arena and draw state, with log chronology and campaign
state. Do not use the lossy faithful save/reopen path for Undo. Retain a fresh
presentation identity so restored frames are not discarded as duplicates. Clear
history at actual opponent handoff; HalfRound alone still precedes old-side
melee and is not that boundary. Refused/read-only actions create no history.

Compute a terminal conclusion once for preview, without campaign commit or AI
continuation. Undo discards it; OK commits it and continues exactly once, with
no second promotion/peace draw. Clearly refuse saving an unacknowledged result
rather than lose continuation state. Default CLI/strict faithful replay remains
unchanged when UI Undo is not enabled. No save schema/history serialization.

Validate placement, moves, targets, shots/losses/RNG repeatability, repeated Undo
to start, opponent-turn exclusion versus reactions, terminal Undo/OK and
AI-phase continuation, queue/sound cleanup and reset on load. Consult private
manual chapter 7/result references for existing UI; Undo is an explicit new QOL
feature, not original fidelity. Full CI before merge.
