#### T292 Optional original-assets loading with authored fallback (contract only)

Owner request [#1798](https://github.com/diegoami/imperial_conquest_2/issues/1798), v0.11. **This task defines the contract; implementation is split below and starts only after the owner decisions at the end.** The per-category support matrix is the deliverable of [#1740](https://github.com/diegoami/imperial_conquest_2/issues/1740) and is **not yet measured**: nothing here claims that any original category decodes today.

**Starting point (verified in the tree):** the game already loads visual packs through `AssetPackManifestLoader` / `AssetPackTextureLoader` (`assets/packs/<id>/manifest.json`, id restricted to one plain directory name, fallback `authored`), and the Settings screen already persists a pack choice. `AssetSettings` locates an original installation through the git-ignored `assets.local.ini`, used so far by tools and tests, not by the game. Pack choice is presentation-only.

**Architecture: an original-assets *pack*, built locally, not a second renderer.**
1. A private local conversion step reads the user's installation and writes a pack (same manifest schema) into a **per-user cache directory** (the Godot user-data folder, never the repository, a release or Pages). Keys it cannot produce are absent from the manifest.
2. The loader resolves each key through `original` first when that pack is selected and falls back **per key** to `authored`, so new-scenario art and partial installs work. Selecting `authored` is the default and needs nothing local.
3. Source choice is a Settings action: show status (not set / found N of M categories / unsupported version / source missing), "Choose folder", "Rebuild cache", "Clear cache". A lost source keeps the last good cache only if the owner approves (decision 3); otherwise it falls back and says so.
4. Browser (Pages) support is out of scope: Pages is observer recordings with no playable game ([T286](T286.md)). No original bytes, extracted media or caches enter git, releases or Pages; nothing is uploaded anywhere.

**Invariants:** asset choice changes no campaign state, RNG, orders, save bytes or Faithful/Improved behaviour; test by hashing a fixed-seed campaign under both packs. Approved UI layout and QOL controls stay. Use the manual and screenshots (operating-guide entry point) when checking any screen that changes.

**Follow-up tasks (proposed order):** (a) T292a #1740 measurement: which categories (terrain, city/army/fleet markers, unit icons, toolbar glyphs, battle art, sounds) load directly, decode at runtime or need conversion, with evidence from the research repo; (b) T292b cache builder and manifest writer, tested with synthetic fixtures (no original bytes in tests); (c) T292c per-key fallback in the loader plus status model with tests for no source / full / partial / unsupported / lost / switching; (d) T292d Settings UI and persistence; (e) T292e state-hash equality check across packs and the privacy check (no original-derived files tracked).

**Owner decisions needed before (b):** 1. Is a pack sufficient, or do original layout/interaction modes also belong in v0.11? (recommendation: pack only; layout stays as approved). 2. Cache location: Godot user-data folder (recommended) vs a user-chosen directory. 3. On a lost source, keep the last good cache or revert to authored (recommended: revert and say so). 4. Which categories are mandatory for the first release once #1740 measures them; sound last.

**Done when (contract task):** this page is reviewed, the decisions are answered, and T292a–e exist as issues. No code changes.
