#### T218 One rally target per nation for newly mobilized armies

- **Issue / release**: [#1404](https://github.com/diegoami/imperial_conquest_2/issues/1404), player QoL required for v0.8.0 by owner decision on 2026-10-25 (see [release plan §2.5](../release-plan.md#25-planned-v080-faithful-battles-and-quality-of-life)).
- **Owner decisions (2026-10-24)**: one fixed rally target per nation **in each campaign save**; apply it to armies newly created by both manual and automatic mobilization; the army first moves on the confirmed End turn containing that mobilization. A rally assignment never moves an existing receiving army.
- **Owns when approved**: optional nation rally-target metadata in the chosen storage, `GameSession`/MainGameScreen target lifecycle, mobilization-event binding and UI map-target controls, original-compatible SAV omission reporting if stored in native saves, focused persistence/planner/Godot checks. Reuse [T211](T211.md)'s fixed-cell/city `ArmyTravelTarget` and ordinary move command; [T209](T209.md)'s automatic mobilization already precedes T211 travel. Movement commands, combat, original SAV bytes and the original AI policy stay read-only.

### Proposed flow

The active human nation sets, replaces or clears its one rally target by choosing a fixed land cell or city on the map. The target is per nation and campaign, not per source city or a cross-campaign Setting. A city target keeps its city ID; army movement considers a legal adjacent cell arrival. The UI shows the current target and asks before replacing it. Setting or clearing it issues no game command and draws no RNG. A missing city, out-of-world cell, foreign seat or stale nation ID is handled visibly rather than breaking an older save.

Every accepted `MobilizeRecruitSlotCommand` publishes `RecruitMobilized` with source city, receiving army ID and `ArmyWasCreated`. When **a new army was created** for a nation with a rally target, assign that army one ordinary T211 travel target. Do not change an existing receiving army's plan merely because it received another unit. Apply the same event to manual and T209 automatic mobilization; an auto-created army moves at most once later in that confirmed End-turn pass. An army created manually before End turn first moves on the next confirmed End turn. There is no move on Cancel/Make more moves, no attack or implicit embark, and no action for another hotseat nation.

T211's existing travel pass performs the moves, reports progress and cancels the army target on refusal, blocked route, hostile contact or player intervention. The rally setting remains for later new armies unless the nation loses ownership of its chosen target city or the target becomes invalid; then show the reason and clear it before further assignments. A rally-created target must not override an army target chosen manually afterward. Older native saves and original SAV imports begin with no rally setting; original-compatible export reports omission when the mode is campaign metadata.

### Done when

1. A real mobilization event assigns the target only when `ArmyWasCreated`, for both specified mobilization paths; a unit joining an existing army does not replace its plan. Order is mobilize → rally target assignment → at most one normal target move → support → one `end`.
2. Map controls set, replace and clear a nation's rally target with visible confirmation and no game command; the target survives save/load in the approved storage and is isolated across hotseat nations and campaigns as decided. Older saves load safely; original-compatible SAV reports any omitted setting.
3. New armies pursue a fixed cell or city across turns through T211, stop on hostile/blocked/ownership changes, and never auto-attack. Manual orders and cancellation do not move unrelated armies or change the nation rally setting unexpectedly.
4. Build solution and Godot project; run focused persistence/event/route tests, relevant headless scenes with completion markers, then full CI green. Report any deliberate scope limits.
