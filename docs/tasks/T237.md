# T237 — Engine commands repeat the original's order gates

Triage of #920 and #1587, 2026-10-29. Several gates the original keeps in a dialog or a map click are not repeated by the engine command behind it, so the CLI, scripts and anything that submits `GameSession` commands directly can issue orders no player of the original could. The Godot app is not affected, because its dialogs and map clicks already check. Owner decision 2026-10-29 (#920 item 2): the engine refuses a recruit amount outside the dialog's range, reversing the 2026-10-01 decision; `docs/game-design.md` "Amounts" records it.

## Contract

- **Recruit amount** (#920 item 2): `RecruitStandingUnitCommandHandler` refuses an amount below one fifth of the type's standard battalion or above the full battalion, with a typed rejection. The bounds come from the same ruleset data the recruit dialog clamps to (`RecruitUnitDialog`), never a second copy of the numbers.
- **Build fleet** (#920 item 1): the engine refuses a fleet order at a city that is not a free coastal city, the same test as `BuildFleetDialogModel.FreeCoastalCities` (refusal R56). Move that test into the engine and have the dialog call it, rather than keeping two versions.
- **Army to a sea tile** (#1587): `MoveArmyCommandHandler` refuses a destination whose terrain armies cannot pass, matching `MapClickRules` (an army click on a non-land tile does nothing). This replaces the #226 behaviour, where the walk stopped at the shore; update `MoveArmySeaPassabilityTests` to pin the refusal instead. A walk through land that meets the sea part-way still stops at the shore as before.
- **Embarked army moved** (#920 item 3): an order to move an army aboard a fleet, which today succeeds while changing nothing, is refused with a typed rejection. Disembarking stays the fleet's order.
- AI behaviour is unchanged. Before merging, show that no AI phase issues an order these gates now refuse; any phase that does is reported as a bug, not silently gated.
- No save schema change, no new UI, no change to dialog bounds.

## Owns and done when

The four command handlers and their rejection codes, the shared free-coastal-city and recruit-bounds helpers, the dialog models that move onto them, and focused engine tests. For each gate: a test that fails before the change and passes after, plus a test that the in-range order is still accepted. The CLI transcripts named in #920 (`recruit-standing antium heavy_infantry 99999`, two fleet orders at Antium) are refused. The canonical-fixture and AI regression suites are unchanged. Build and hosted CI green. Closes #920 and #1587.
