#### T184 Original-compatible SAV binary writer

- **Design milestone**: M15; mandatory v0.6.1 save compatibility, [issue 1191](https://github.com/diegoami/imperial_conquest_2/issues/1191).
- **Branch / author / review**: `task/T184-sav-writer`, from `origin/main`; hard, Sol medium. Independent direct Kimi For Coding 1M review; exclude the OpenAI family (`-ExcludeModel sol` with existing scripts).
- **Start after / Merge after**: approved T184–T186 compatibility contracts. Low-level typed layout/synthetic writer work may start from the documented serialization sequence; merge requires the applicable region/prototype preservation findings from [research issue 37](https://github.com/diegoami/imperial-conquest-2-research/issues/37) evaluated into this project's contracts. This is a known semantic dependency, not an implementer discovery to paper over. T185 consumes this writer. Do not run competing edits to the named files.
- **Owns**: new `src/IC2.Data/OriginalSaveWriter.cs`, `src/IC2.Data/OriginalSaveWritePlan.cs`, `src/IC2.Data/OriginalSaveWriteReport.cs`, `src/IC2.Data/OriginalSaveLayout.cs`; new `tests/IC2.Data.Tests/OriginalSaveWriterTests.cs`, `tests/IC2.Data.Tests/OriginalSaveWriterRealSaveTests.cs`, `tests/IC2.Data.Tests/OriginalSaveWriterFixtureBuilder.cs`. No engine dependency. Existing readers, corpus expectations and synthetic builder remain unchanged; a necessary extra file requires a reviewed Owns amendment.
- **Scope / Protects**: serialize the original strategic SAV shape from a validated, complete binary write plan and an immutable private strategic SAV template. This layer handles binary layout, checked widths, exact text encoding, template preservation and safe file publication; T185 supplies domain meaning. It must not accept arbitrary overlapping byte patches as a substitute for a typed, audited region plan. No original DAT/SAV is modified, no original bytes enter git, and no asset/copyright policy changes. Native JSON persistence, game rules, orders and RNG stay unchanged. Output is compatible canonical state, not recovery of a native JSON save's lost historical original bytes.

  **Evidence and template prerequisite.** Pin research commit `d5f0bc797ec23c181e854f743db1b06343e2876d`, reports `decompiled-sav-file-layout.md` (saver `004484D0`, loader `004487C4`, September correction), `news-log-format-and-messages.md`, `2026-10-04-decompiled-tactical-battle-rules.md` §1, and the development investigation `dat-file-layout.md`. Older prose saying midbattle saves cannot exist is superseded by the tactical report. The writer requires a validated original **SAV**, not DAT, template read from an explicit private path or an existing configured/fixture resolver; identify its SHA-256 and shape in the report. Validate the bytes actually read, retain an immutable copy for the operation, and never write the input/template path or any existing destination, including aliases to either. Template bytes remain private, are not persisted inside JSON or bundled into a release. A missing, battle-bearing, malformed, ambiguous or incompatible template is a refusal, not permission to zero-fill or select another file silently.

  **Complete region policy.** Account for the entire output, in order: 89,600 map bytes; 334×34 city records; army count and count×656 records; fleet count and count×26 records; 16×1,172 nation records; 50×12 mercenary slots; signed news index and `(index+1)×61` news slots; 55-byte trailer. Strategic output has battle flag zero and no battle block or trailing bytes. Each record byte range is classified as a checked supplied live field, a researched canonical value, or a preserved template byte with a cited reason it remains valid in the exported state. Cover fixed text buffers and their unused residue, unused unit/mercenary slots, all nation subregions (including the large region not exposed by current readers), stored bookkeeping and the eight geometry bytes. Counts can relocate later sections; preservation is by logical region/record, never an old absolute offset. New records need an explicit validated prototype/default policy; never borrow unrelated live record state. Unknown meaning is not evidence of static meaning: if a region may affect live state and cannot be mapped or proven safe to preserve, stop with the exact byte range and evidence gap for main-session research/contract resolution.
- **Done when**:
  1. New synthetic fixtures independently specify all region offsets, lengths and boundary values, including zero/multiple armies and fleets, empty/partial/full news, variable table relocation, empty slots, negative signed values where legal, and unique sentinel bytes in every preserved region. Assert total length exactly and complete, nonoverlapping coverage. Wrong-format, malformed, battle and ambiguous templates are rejected. Tests do not merely call the writer's own offset helper to obtain expectations.
  2. Typed binary inputs check every count, signedness, width, index/sentinel, coordinate and string before allocation/publication. No narrowing wrap, overflow, lossy character replacement, NUL injection, or truncation; enforce original buffer terminators and limits (including 60 ASCII news bytes). Test each failure class at boundaries and one beyond. Battle/control payloads outside the strategic schema are rejected rather than silently discarded.
  3. Independently decode known field offsets from output and compare against supplied values, then read through the existing production readers as an additional check. Compare all preserved bytes against the input template using an independently specified allowed-change mask, including record relocation and unused string residue. Mutating a supplied field changes its intended bytes; mutating preserved template bytes survives exactly. A mask that simply permits every output byte does not satisfy this gate.
  4. Read back three or four justified private real templates, covering variable record counts and news lengths. An identity write plan preserves every byte; a changed plan preserves every unowned region and yields exact expected field bytes. Record filenames/hashes and actual pass/fail/skip counts, not contents. Missing private files are explicit unavailable coverage; synthetic tests still run and cannot stand in for this release gate.
  5. File output is fully validated before publication, uses exclusive temporary creation and no-replace publication, and refuses existing destinations or source/template aliases. Failure leaves prior files unchanged, no successful-looking partial SAV, and cleans only its own temporary artifact. Tests cover existing output, blocked temp/publication, input=output, template=output, and path aliases supported by the platform. Hash source/template before and after. Same plan and template produce identical output bytes without clock or RNG access.
  6. Build `IC2.sln` before full solution tests with configured private fixtures; record counts and evidence limits. Review the complete byte-region map against the pinned reports, not just current parser properties. Final diff stays inside Owns. The original-game open/continue/save/reopen integration gate belongs to T185 and remains required before claiming working export.
- **Docs affected**: main records the final binary API and checked region map after merge; contracts retain evidence limits. No corpus/golden regeneration to accommodate output.
- **Hazards**: original format detection checks only part of the structure and is insufficient validation alone. A zero unmapped-field count in the importer covers publicly parsed properties, not every SAV byte. Do not invent static defaults or copy template armies/nation bookkeeping over exported live values. Future battle serialization needs a separately reviewed contract.
