- **Scope**:
  - **Protects**: the player recruits where the original lets them, and All cities appears exactly when the original shows it.
  - **The rule** ([`2026-10-11-g1-original-checks.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/main/docs/reports/2026-10-11-g1-original-checks.md) G8, research `89c37ff`, **[confirmed: Wine + code]**; the list rule [`2026-09-29-which-cities-may-recruit-and-troop-amounts.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/main/docs/reports/2026-09-29-which-cities-may-recruit-and-troop-amounts.md)):
    - **The city list** (unchanged; `RecruitmentEligibility` already implements it): the capital, every town whose fortification is at least the ruleset's threshold (75), and any town that already holds queued units.
    - **All cities is listed only when more than one town holds queued units** (`TArmyRecruits_SetCityRecruits` 55717-55795). Today the dialog always adds it (`RecruitUnitDialog.cs` ~:321). With one or no town holding units, the list has no All cities entry. T162's opening rule (open on All cities when a town other than the capital holds units) still applies whenever the entry is listed.
    - **Recruit with All cities selected creates the unit at the capital** (`TArmyRecruits_RecruitUnit` 55920-56041: the fortification refusal is skipped for All cities, and the unit is created at the capital). Today it does nothing (`SubmitRecruit` returns, ~:362; `AllCitiesRecruitReason`). It submits the same `recruit` command as the capital's own view, with the capital's city id.
    - **The refusal at a listed town below 75%** (*"This city's fortification has fallen below 75%."*, R48) is unchanged: it fires for a non-capital town selected by name, not for All cities.
    - **The remark.** *"You cannot mobilise a unit at this time."* is the original's box for a **ready** selected unit that finds no army to join and no room for a new army (198 armies), not for an unready one, which is skipped with no box (g1 G9). The remark on `SlotNotReady` says so; the rejection's behaviour does not change.
  - **Why it stays whole** (build-process.md §4.11): the listing rule and Recruit from All cities are one dialog's two halves of the same original behaviour, in the same two files and tests, and the remark is a one-line correction beside them.
  - **Out of scope**: the city list rule itself; Mobilize and Disband (T162's); the mobilise refusal's wording (#721, #801); the AI.
- **Done when**:
  1. **All cities is listed only with two towns holding units.** A test with queued units at one town shows no All cities entry; with units at two towns it shows it; T162's opening rule holds whenever it is listed.
  2. **Recruit from All cities trains at the capital.** Selecting All cities and pressing Recruit submits the same command as the capital's view and the unit appears in the capital's queue; a test pins it. It fails on `origin/main`.
  3. **The refusal is unchanged.** A non-capital town below 75% that holds queued units is listed, and Recruit there still gets the fortification refusal; a test pins it.
  4. **The remark** on `SlotNotReady` names the ready-unit case, and no behaviour changes.
  5. **Nothing regresses.** Build, test and all Godot headless checks are green, and the diff lists only Owns paths.
