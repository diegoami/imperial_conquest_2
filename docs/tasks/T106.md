- **Scope**: the original's `TArmyToArmy` dialog shows two unit lists, with Transfer and Disband under each, and spinners for supply and money. Conservation is exact **[confirmed: `army-to-army-transfer-confirmed.md`]**. The clone has no command for it.
  - **`army-transfer <from> <to> [units=<i,j,…>] [supply=<tons>] [money=<talents>]`** moves the listed units of `from`, and the given supply and money, to `to`, all in one command. To move the other way, swap the two armies. Both armies belong to the active nation, and they stand at Chebyshev distance **exactly 1**, the original's partner rule. Every cap the report gives holds: units per army, troops per army, supply capacity, and the purse cap. Troops, supply and money are conserved exactly.
  - **`AdjacentPartner`**: `Army(state, armyId)` returns the **last** own army at Chebyshev distance exactly 1 (`FUN_00449D64`, through `FUN_004492A0`'s `distance == 1`). `Fleet(state, fleetId)` returns the last own **launched** fleet at distance exactly 1 (`FUN_00449DD8`) **[derived: code, audit §1.6]**. Either returns none when there is no such unit. The UI uses these for Transfer unit, Join armies, Join fleets and Transfer ships, so the player never picks the partner (the user's decision 8). The CLI keeps naming both ids.
  - Disbanding a single unit from either list is T107's `disband-unit`, not this command.
