# T233 — Staged army-dialog edits

Owner decision 2026-10-28: Change units and army Transfer/Split edits, including Disband, remain pending until OK; Cancel discards everything. This supersedes T111/PR736's immediate Split Disband exception. Source reference: private original manual §§4.6–4.8 and the manual audit (#1551); implementation findings #1556 and #1522.

## Contract

- All three editing dialogs display a private working copy. Rename, split/join units, transfers, allocations and disband requests cannot mutate the authoritative campaign, consume its RNG, emit committed events or change saved QoL metadata before OK. Existing command/eligibility and last-unit safeguards remain.
- OK validates the complete pending command plan against the unchanged opening state before applying anything. Refusal or stale campaign context keeps the dialog open with a clear reason and no partial commit. Cancel/Escape/close discards the plan. Preserve normal command bookkeeping, pending reports, event delivery and deterministic RNG on successful commit; repeated OK cannot apply twice.
- Use existing production command parsing/handlers for preview and commitment. Preview construction must not run save-load bootstrap, advance AI turns, depose a leader or drain pending battle/offer/news bookkeeping. Restrict editing plans to the intended strategic edit commands; save/load/end/battle commands are not editable actions.
- Retain Transfer's ordered whole-unit admission and selected-first final supply rebalance; preserve staging when disbanding another unit. Reindex surviving original identities safely. Split can commit valid pending disbands without creating an empty new army; an invalid requested split must not commit a prefix of edits.
- No save envelope/document/schema or original-SAV representation change. Pending GUI edits are transient. Whole-army toolbar Disband, Supply's distinct immediate actions and fleet policies are outside this task.

## Owns

Transient session editing/preflight/commit support; ChangeUnitsDialog, ArmyTransferDialog, SplitArmyDialog and their model/callback integration; affected actual-dialog checks and focused session/model tests. Existing command legality stays authoritative.

## Done when

1. Actual dialogs prove before-OK and Cancel nonmutation, successful mixed edits once, meaningful refusal/stale-context protection and preserved unit/resource identity, RNG and saved metadata.
2. Core preview/batch tests prove no bootstrap/pending-report loss, no partial accepted prefix on refusal and normal final bookkeeping/events. Existing split-input and army/fleet controls pass.
3. Builds, targeted tests and CI pass; current design and historical exception references identify the owner's new policy explicitly.
