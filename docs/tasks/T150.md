Process tooling, from the churn retrospective [#854](https://github.com/diegoami/imperial_conquest_2/issues/854): T140 took six implementer dispatches, two lost-work incidents and a main-session rewrite, mostly because the OpenCode guard's `ask` auto-rejected a benign path outside the worktree and ended the run. The user put it in the v0.5.0 gate on 2026-10-08 and asked for it before any other gate task. **Labels**: `lane:infra single-instance release:v0.5.0`
- **Branch**: `task/T150-implementer-churn`, from `origin/main` · **Model/effort**: Sonnet / Medium ([§3.3](../build-process.md#33-model-selection): not architecture, so the OpenCode default, then Sonnet) · **Reviewer**: the complex tier ([§3.4](../build-process.md#34-why-the-reviewers-model-differs-from-the-implementers)), GPT-6 Sol at `low`

It is **never in flight with** another task or fix under `scripts/*OpenCode*`, `scripts/external-*.ps1`, `scripts/Choose-Model.ps1`, `.opencode/**`, `.github/workflows/**` or `docs/environment.md` (whose claims about the permission block and `Choose-Model.ps1` follow at the merge, as doc claims: an implementer edits no `docs/`).
- **Owns**:

  - `scripts/Choose-Model.ps1`: **only** the new `-ExcludeFamily` parameter (Done-when 2);
  - `scripts/Invoke-OpenCodeWatched.ps1`: **only** what reports the outside paths a run touched (Done-when 3);
  - `.opencode/agents/external-implementer.md` and `.opencode/agents/external-reviewer.md`: **only** the `external_directory` block;

- **Scope**:
  - **Protects**: no game code, data, ruleset, test fixture or CLI golden changes. Outside the worktree the guard still asks for every path except the Godot shim (#856) and the two folders Done-when 3 names, and neither folder holds a credential: `~\.local\share` (the OpenCode data roots, with `auth.json` and `opencode.db`, which holds the OpenCode Go console login) stays unreachable. No reviewer's family rule changes ([§3.4](../build-process.md#34-why-the-reviewers-model-differs-from-the-implementers)): the fallback picks a different implementer, never a reviewer.
  - **Out of scope**: the review script's chain, the Claude agents, and any change to which model reviews which tier.
- **Done when**:
  1. **The brief lives in the worktree.** Before it starts OpenCode, `external-implement.ps1` copies `-BriefFile` to `rendered/brief.md` inside the worktree it made (git-ignored there) and names that path in the prompt. An absolute `-BriefFile` in the main checkout no longer appears in the prompt. `-WhatIf` prints the copy's destination.
  2. **A different family when the chain is spent.** This is new behaviour in both scripts:
     - **`Choose-Model.ps1`** gains `-ExcludeFamily <string[]>`, honoured for both roles. It drops every candidate whose family, read from the family map the script already parses, is in the list.
     - **`external-implement.ps1`** records each model it tried in this run, with its family and its failure class from the watcher (the classes the watcher already returns: `permission-rejected`, `idle`, `total-timeout`, `no-session`, `non-zero-exit`, …, or the quota skip).
     - **When every model of the chain has failed** (an `auto` chain, or an explicit `-Model`), and before today's exit 3, it calls `Choose-Model.ps1 -Role implementer -ExcludeFamily <every failed family>,luna -Pick`. The substitute never comes from the OpenAI family (Luna, Sol), so that Sol can always review the PR and Luna stays the simple tier's reviewer (the user's decision of 2026-10-08, after the proof runs picked Luna). If that returns a model, the script runs it once. If it returns none, exit 3 is unchanged.
     - **It writes a new "Implementer attempts" section into the PR body**: one line per attempt (model, route, failure class), then the model that ran.
     - **`-WhatIf -SimulateFailed <model[,model]>`** (new) prints the substitute that would be chosen, and why, without running anything. A check with two failed families (for example `mm-m3,deepseek-flash`) shows that neither family is chosen.
  3. **A benign outside path no longer ends the run** (the user's decision of 2026-10-08, #854 Fix 4, narrowed on review to the paths T140's runs actually hit). In both agent files, `external_directory` adds exactly two allows: `C:?Users?diego?.local?bin?*` (the tool shims on PATH: `gh`, `jq`, `godot`, …; it holds no credential) and `C:?Users?diego?AppData?Local?Temp?opencode?*` (where T140's run tried to write). Every other outside path, the rest of `~\.local` included, still asks. OpenCode has no "warn and continue", so the warning is the script's job:
     - **A path counts as touched** when a tool call recorded in the session export (a `read`, `write`, `edit`, `list`, `glob` or `grep` call's path argument, or a `bash` call's command line) names a path under one of those two roots. A path that appears only in the prompt or in tool output does not count.
     - **After the run**, the watcher returns that list, and the script prints it and appends it to the PR body under "Outside paths touched". It prints "none" when the list is empty.
     - **If the export failed**, it prints and appends "unknown: the session export failed" instead, and the run's exit code is unchanged.

     Appendix A's rule (stay inside the worktree, no scratch in TEMP) still holds. This only stops a slip from ending the run.
  4. **Every headless check runs in CI.** The `godot-headless` job runs each `*Check.tscn` under `godot/Checks/` and `godot/Screens/Checks/` as the existing ones are run. Each run must print the scene's own `<Name>: exiting with code 0.` line (the completion marker the job already requires, because `--quit-after` exits 0 for a scene that never ran), and fails on a missing marker, a non-zero exit or a `FAIL` line. A scene that cannot run on the CI runner (one that needs `assets.local.ini` or the private fixtures) is listed in the workflow, each with a one-line reason, and skipped. The list is in the PR body.
  5. **The proofs, in the PR body:**
     - (a) a `-WhatIf` run showing 1, and the `-SimulateFailed` check of 2;
     - (b) the two allows are shown by the pattern test of Done-when 3 (both separators, nothing under `~\.local\share` matched). A real run cannot show them before the merge: OpenCode reads the agent files from the main checkout, and a compliant model never reaches an outside path that its preamble forbids (the main session's proof runs of 2026-10-08, on #854). So the first real run after the merge whose session touches `~\.local\bin` or `%TEMP%\opencode`, and completes, is recorded on #854 with its "Outside paths touched" section. A rejection there reopens the task as a bug (the user's decision of 2026-10-08);
     - (c) a **separate** run whose prompt reads a non-secret sentinel, `C:\Users\diego\.local\share\ic2-deny-probe\sentinel.txt` (created for the proof, holding only the word `SENTINEL`, deleted after), is rejected, and the watcher classifies it `permission-rejected`. No real credential file is named in any prompt;
     - (d) a run whose prompt names `C:\Windows\win.ini` still asks and is rejected;
     - (e) the CI run of 4, green.
  6. All three scripts parse, `dotnet build IC2.sln --nologo -v q` and `dotnet test IC2.sln --nologo -v q` are green, and `git diff --name-only origin/main...HEAD` lists only Owns paths.
- **Hazards**:
  - **Credentials.** Never read, print or log `auth.json`, `opencode.db` or any key (the user's standing rule). No prompt names a real credential path; the deny proof uses the sentinel.
  - **The allow patterns.** Test each against both separators, and check that neither one matches anything under `~\.local\share`, before the real runs.
