### Observer transaction and replay requirements

1. Handler uses a command-local recorder owned by CommandContext. A copied local walk result is staged only there; no public callback is raised from a handler or global walker. Dispatcher rejection/handler exception drops that buffer exactly as it drops rejected domain events (`CommandDispatcher.cs:174-189`). After accepted state and existing seed advance are computed (`:192-200`), dispatcher appends an accepted-command observation (before/after immutable state references, actual copied route, exact existing event batch) to the session-owned observer recorder synchronously. Domain sink behavior/order at `:202-208` stays identical. No arbitrary UI callback runs inside engine execution.
2. Submit opens an observation transaction; each RunTurn attempt has a checkpoint/staging scope. Completed-system notifications capture noncommand state transitions after `TurnCoordinator.cs:244-253`, with a distinct boundary identity. Accepted command notifications are already staged independently of that outer system notification. Coordinator does not swallow a battle exception or pretend the incomplete system completed.
3. The existing special catch `GameSession.cs:1904-1907` recognizes AiPhaseBattleSuspended, retains all accepted command observations from that attempt, and commits the prefix plus the exception's exact AtAttack state as a suspension boundary. It does not wait for TurnResult.Events, synthesize domain events, set authoritative Session.State to AtAttack, rerun AI early or change the battle exception. OpenAiPhaseBattle then follows its existing logic. Submit flushes one immutable strategic batch at its existing normal return boundary. An unrelated exception rolls the observation transaction back and exposes no partial UI batch.
4. The lap owns a presentation-only logical sequence/cursor. First attempt assigns stable command and completed-system/battle-boundary identities within that lap. Resume reruns the engine exactly as today; the observer compares the already-published prefix (command kind/entity, before/after identity/fingerprint and route) and suppresses only its delivery. It never skips an engine command, rewrites RNG, advances authoritative State or drops a domain event. A new suffix gets new identities. Match and suppress replayed noncommand system boundaries too; do not show a rewind to lap start. Keep prefix identity across repeated suspensions, not just the last Submit batch.
5. At an already-fought attack, the nested AiPhaseBattleGate branch in `GameSession.cs:2046-2060`: it bypasses the inner dispatcher, republishes done.Events and returns done.After. Therefore this exact nested branch must explicitly feed a battle-result/reconciliation slot to the observer cursor; it cannot rely on dispatcher notification for that injected command. The first suspension reserves/records its battle boundary; injection later reconciles it once, preserving domain events unchanged. At new suspension record the current accepted suffix before opening that next battle. Closed/aborted session releases the lap prefix and staged references.
6. Recorder is optional, internal and buffered; UI subscribers only run after Submit. Disabling/consuming/failing the presentation observer must never affect gameplay, domain event publication or persisted state. The implementation must establish how recorder invariants/disabled observation fail without changing authoritative execution, and production tests must prove it. If stable accepted-command/boundary replay identity or exact prefix validation cannot be obtained through these owned files while preserving current replay, STOP before widening Owns and return a concrete amendment request. The source preflight establishes hook locations, not runtime feasibility or implementation approval.
