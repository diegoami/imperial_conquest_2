- **Scope**: Research [`dat-neighbour-mask.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/main/docs/reports/dat-neighbour-mask.md) (research `bfaeb1b`) is the source for every rule below:
  - **Where the mask is.** The original's DAT holds a symmetric 16-bit neighbour mask at nation-record `+0x2B`. The DAT loader `FUN_004481A0` copies it to the in-memory `+0x46` **[confirmed]**.
  - **What it holds.** 24 pairs, matching all 101 local saves **[confirmed]**.
  - **What T82 does instead.** It derives neighbours geometrically. The derivation finds all 24 pairs but adds six the original lacks: Rome–Greece, Thracia–Bithynia, Thracia–Seleucid, Seleucid–Macedonia, Seleucid–Greece and Ptolemaic–Greece.
  - **The fix.** This task loads the real mask into the world file, as T75 did for the starting relations, and makes the AI's neighbour checks use it.
- **Done when**:
  1. **The parse.** IC2.Data reads each DAT nation's mask at `+0x2B`. A DAT-backed test shows:
     - 24 symmetric pairs, and no nation neighbouring itself;
     - Rome's row: Carthage, Gaul and Illyria.

     A second test shows that at least three local saves' `+0x46` equal the DAT's mask.
  2. **The world carries it.** An optional `startingNeighbours` field lists each nation id with its neighbour ids. Loading a world rejects, with a typed error:
     - an asymmetric pair;
     - a nation that neighbours itself;
     - an unknown nation id;
     - a duplicated entry.

     There is one test per shape, through `GameDataValidation.Validate`.
  3. **The export writes it from the DAT, through the parse**, with a `_provenance` citing the report. Tests assert the 24 pairs, and that none of the six derived-only pairs is present. A second export run reproduces the file byte for byte.
  4. **The AI uses it.** `NeighbourGeography`'s neighbour query returns the world's `startingNeighbours` when the world has them, and the derivation otherwise. Tests:
     - on the classical world, the query answers the DAT's 24 pairs exactly, and Rome–Greece is not a neighbour pair;
     - the toy world, which has no field, keeps the derivation, and its goldens and the 50-seed soak are unchanged.
  5. **Seeded outcomes.** Every classical seeded test, measurement or golden that changes is listed in the PR with its reason. `seat-rome.golden.txt` is regenerated and every changed line explained.
  6. `dotnet build IC2.sln` and `dotnet test IC2.sln` green, with the DAT tests run, not skipped, and the diff lists only Owns paths.
- **Hazards**:
  - **Static here, mutable in T86.** The original rewrites the mask on conquest (`FUN_0044C528` merges the loser's neighbours into the winner's). This task keeps the mask as world data, unchanged in play; T86 moves it into the game state and applies the merge. Do not add it to `GameState` here.
  - **Two more readers.** The original also reads the mask in the quarterly rebellion (`FUN_0044C204`, the rebel city's recipient) and in the peace cascade (`FUN_00450C68`). If the engine implements either without the mask, report it with file and line; do not fix it here.
  - **Keep the derivation as the fallback.** A world without `startingNeighbours` still needs neighbours for the AI. Update its remark to say it is the fallback, and that the classical world no longer uses it.
- **Constraint**: `local-only`. The parse and the export read the original DAT.
