# T265 — Shared human supply and purse support service

Issue [#1696](https://github.com/diegoami/imperial_conquest_2/issues/1696),
engine foundation for #1509. Own new `Economy/HumanAutoSupport.cs`, its focused
engine tests and these docs. Turn-start/movement/settings wiring follows in a
separate integration task; this slice does not activate any campaign behavior.

Use an opt-in runtime policy, outside saved campaign state. Match existing
automation: army maximum dialog capacity from eligible free own city/fleet/army
providers; fleet maximum supply from owned nearby towns. Army purse target is
quarterly regular-plus-mercenary cost; the owner selected quarterly fleet upkeep
for fleet purses on 2026-11-01. Respect the normal purse cap and credit policy.
Do not add a treasury reserve, duplicate an affordability gate, buy from paid
foreign towns, repair fleets or affect AI-controlled nations.

Invoke the existing supply/funding handlers with isolated event buffers. Return
updated state, accepted events and typed refusals; never publish rejected
effects, recursively dispatch movement or advance the persisted root RNG.
The later caller owns the enclosing command/turn boundary. Preserve stable
provider and unit order and conservation when stock cannot fill everyone.
Null/all-disabled policy is reference-identical and consumes no RNG.

Done when controls exercise actual supply and treasury/purse changes, multiple
providers and caps, fleet targets, faithful debt versus Improved affordability,
AI exclusion, repeated fully supplied checks, and rejected-event isolation.
No save/schema or UI changes. Full CI before merge; #1509 stays open until
beginning-of-turn, intermediate movement, settings and end-turn-only repair
integration passes.
