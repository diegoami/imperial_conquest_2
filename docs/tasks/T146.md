- **Design milestone**: M12 (the end of the game and the leader's fall, T87), with M1's world export (T29).   - **The pool** **[confirmed: code + Wine + 2 desktop saves, [`2026-10-03-new-game-turn-order-shuffle.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/d1b5983/docs/reports/2026-10-03-new-game-turn-order-shuffle.md) (research `871ca91`, promoted), "DAT leader pool `0x2089A` (16 × `0x138`, 12 × 26-byte names)": a search of every clock seed found exactly one per desktop game whose 16 draws through this pool match the saved leaders; [`decompiled-new-game-mercenary-fill.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/d1b5983/docs/reports/decompiled-new-game-mercenary-fill.md) pins the same offset by the DAT loader's sequential reads (`0x1FCD6 + 0xBC4 + 0x1380 + 0x988 = 0x225A2`); `docs/investigations/dat-file-layout.md` lists it]**. The offset and layout are established, so the export is not conditional on a further research read. The pool is 4,992 bytes at DAT `0x2089A`: 16 nations in DAT nation order, each 12 records of 26 bytes, each a NUL-terminated name (every one of the 192 is NUL-terminated within its record, the longest 21 characters, as `SaveNationTable`'s remarks record from T73's review). `DatLeaderPool` parses it with `DatLayout`'s constants; the exporter writes each nation's 12 names, in pool order, as `nations[].leaderNames`, with provenance `confirmed` citing the offset and the report.
  - **The world's `leaderName`** becomes the nation's pool name at index 0 **[designed: the name a state carries before any New Game draw, which is what `GameStateFactory.CreateInitial` builds and what `OriginalSaveImporter` falls back on when a save has no leader]**, with provenance saying so. The placeholder `(unassigned -- drawn at New Game)` leaves the export. Validation: when `leaderNames` is present it has exactly 12 non-empty names, at least two of them distinct, and `leaderName` is one of them **[designed]**; it is optional, and a world without it validates as today.
  - **The New Game draw** **[confirmed: code, `FUN_00448AA4`, the turn-order report §4 and its code excerpt (`for (n = 0; n < 16; n++) leader[n] = pool[n][Random(12)]`), and the desktop seed search]**: for each nation of the world, in the world's nation order (the DAT's), one `NextInt(12)` (the pool's size), and the nation's `LeaderName` becomes that pool entry. **16 draws** on the classical world; none for a nation without a pool, so none on the toy worlds. `NewGameLeaders.Apply(state, world)` is called where a game starts, as T119 does for the turn order: `GameSession`'s New Game constructor and `AiGameRunner`; `GameStateFactory.CreateInitial` stays draw-free, and a resume or an import never draws. Both presets draw **[designed: the user's decision gives no preset difference]**. The draws come from their own stream, `SplitMix64Rng.ForStream(state.RandomSeed, "new-game.leaders")` **[designed name, after T119's `"new-game.turn-order"`: algorithm parity, not seed-for-seed parity, the user's decision of 2026-10-03]**, so no other draw moves. The original's New Game form lets the player edit a leader's name (`TPickLeaders`); that is the Godot New Game screen's, not this task's.
  - **A human seat's fall: two draws** **[derived: code, the report's "What happens at the end of a human's fall", `FUN_00449078` :47790–47791 and `FUN_0044c8f0` :50789–50794; Wine candidate: the after_state table S1–S12, e.g. Rome's Appius Claudius became Antiochus, Publius Scipio or Licinus Crassus, Gaul's Hengest became Arminius, Brennus or Horsa]**. After the window's figures are recorded (`RecordSeatFall`, which keeps the leader at the fall), the **first draw**, one `NextInt(12)`, writes `pool[i]` into `LeaderName` (it may equal the old leader); the **second draw** repeats `NextInt(12)` until `pool[j]` differs from the field's current content, which is the first draw, not the old leader, and writes it. So the final name can be the old leader again. Draw count: `1 + k`, where `k ≥ 1` is the number of tries the second draw needs. It applies to every human fall the session records: the turn-start deposition, the conquest and the defection elimination of a human seat, and a `--seat` session's lost seat; each fallen seat is redrawn once per call however many paths report it.
  - **A computer nation deposed at the quarter: one draw loop** **[derived: code, `FUN_0044c8f0` for a computer nation writes the news line with the old leader, then makes the second draw only; the first draw is inside `TPremierForm_HumanLeaderFalls`, which a computer nation does not reach; not played]**. `AiDepositionHandler` publishes `AiLeaderDeposed` with the **old** leader, as today (*"<nation> depose their leader <leader>."*), then repeats `NextInt(12)` until the name differs from the old leader, and writes it: `k ≥ 1` draws, and the new leader always differs.
  - **Rebirth: the draw it already makes now writes** **[derived: code, [`decompiled-quarterly-rebellion.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/d1b5983/docs/reports/decompiled-quarterly-rebellion.md), "one `Random(12)` from the nation's 12 names, with no 'differs from the current name' retry"]**. `Rebirth.Run` keeps its one `NextInt(12)` on the shared quarterly stream, unchanged in count and place; given the nation's pool (from `Rebellion`), the reborn nation's `LeaderName` becomes that entry; given none, it is unchanged, as today.
  - **The draws' streams** **[designed: [the user's decision of 2026-10-05 on PR #772](https://github.com/diegoami/imperial_conquest_2/pull/772#issuecomment-6000817560), own derived streams so no seeded outcome moves, after T119's and `ConquestCascade`'s precedent]**. Each event draws from `SplitMix64Rng.ForStream(State.RandomSeed, key)` (`state.RandomSeed` in the quarter handler), where the key names the occasion, the nation and the calendar point of the event: `leaders.fall/<nationId>/<YearBc>/<SeasonIndex>/<Week>/<TurnIndex>` for a human fall and `leaders.deposition/<nationId>/<YearBc>/<SeasonIndex>/<Week>/<TurnIndex>` for a computer deposition, read from `GameState.Calendar` (`CalendarState`'s four fields) at the event. `IRng.ForStream` returns the same sequence for the same root and name, so the key, not the root seed alone, is what makes two events of one nation draw afresh: a repeat would need the same nation, occasion, root seed **and** calendar point. Within one calendar point that cannot happen on a reachable path: a human seat falls once (it is handed to the computer, and the clone has no New player or New nation to make it human again), the session redraws a fallen seat once per call, and `AiDepositionHandler` visits each nation once per quarter boundary. So **no new saved field is needed**: the root seed and the calendar are already state, and a resumed game derives the same keys. If the implementer finds a reachable path on which one nation has two events of one occasion at one calendar point, stop and report: the fix would be a per-nation fall counter in `NationState`, a save-format change this task does not make without the user's decision. Rebirth's single draw stays on the shared quarterly stream, where it already is. The original draws all of these on its one generator; the clone keeps the count and the algorithm, not the seed.
