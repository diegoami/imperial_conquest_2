- **Scope**:
  - **Protects**: the game state. A save's `state` is unchanged field for field, and so is every `end` of an **uninterrupted** session, its first `end` included, so bug [#486](https://github.com/diegoami/imperial_conquest_2/issues/486) (the first `end` also lists the human's own earlier news) keeps its current behaviour, which this task neither fixes nor widens. `SaveFormat.CurrentVersion` (3) and `GameDataSchema.CurrentVersion` are unchanged, so T125 keeps save format version 4. Every CLI golden is byte-identical. Every save written before this task loads and resumes as today. Forbidden: an edit under `src/IC2.Engine/Persistence/**` or to `GameState`; a heuristic keyed on the turn index or the active seat (the T95 remarks explain why one is wrong for a hotseat game).
  - **What is wrong** **[confirmed: code, T95's review, #487 item 1]**. The ordinary constructor snapshots the news log (`_pendingNewsBaseline`, T87 N4) before it plays the AI seats that precede the human's seat, and the session's first `end` prints every entry added since that snapshot. `ResumeFrom` sets the baseline to `null`, because the save does not record it, so a session resumed from a save made **before** the saving session's first `end` prints only its own round's news there. On classical, 13 of the 16 `--seat` choices lose 4–5 News lines this way, a player's own city falling among them (for Ptolemaic, "Sidon (Ptolemaic) falls to Seleucid."). Later `end`s match, and `news` shows every line.
  - **The fix** **[designed]**. The save carries what that first `end` still owes. `SaveGame` gains an optional `FirstEndNewsOwed` (`int?`, JSON `firstEndNewsOwed`, default `null`). `BuildSaveGame` writes it only while `_pendingNewsBaseline` is not `null`: the number of entries the log has gained since the baseline, counted by the existing `CountNewsAppendedSince`. A resumed session that reads a number `k` rebuilds its baseline as the loaded log without its newest `k` entries, so its first `end` prints those `k` entries and its own round's, the same lines the uninterrupted session prints. `null` (a save made after the first `end`, or any older save) resumes exactly as today. The number is capped at the log's slot count, as `CountNewsAppendedSince` already is.
  - **Why no version bump**: the field is optional and its absence means what it means today, the same shape as the nested state's optional fields (`SaveFormat.CurrentVersion`'s remarks). If a test shows that the loader refuses the new field under version 3, the implementer stops and reports rather than bumping: T125 holds version 4.
  - **The wording items**: `ResumeFrom`'s R2-B1 paragraph stops calling the gap accepted and says how the save carries the owed news; its last parenthetical states #486 as #486 states it (R3-N2: the first `end`'s footer includes news from the human's own commands issued before it, and no later `end` does). The `SaveAndResumeTests` comment says that in `OfferFixture` the human seat plays first, so the lines a resumed first `end` lacked there came from the human's own commands, #486's half, and cites #486 (R3-N1).
