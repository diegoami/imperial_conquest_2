- **Scope / Protects**: extend existing File → Save As and its filesystem dialog with explicit native JSON and original SAV filters. A chosen `.sav` invokes T185's production exporter and reports the typed success/refusal/omission result. Existing `.json` Save As and ordinary Save retain behavior. Use the existing `file.save_as` command, `SaveAsDialog`, `SaveToChosenPath` and `SaveAsForCheck` seams; no second export implementation or speculative extra menu route. For export, select a private template through a filesystem dialog when no explicit configured template is available, then return to the pending output operation; cancel writes nothing. T185 validates selected paths and content. No persistent configuration, template copying into the release, or original-file modification.

  SAV is an export snapshot: success must **not** change the current native JSON save path or make later ordinary Save overwrite a binary SAV with JSON. Report “Exported” and the new path, plus concise omission information and template identity available in full feedback. When the shared T185 policy aliases an eligible generated mercenary placeholder in the exported copy, disclose every before/after name and its stable army/slot identity in the concise success details, with the complete mapping available in full feedback; use the same eligibility and alias as CLI. Unsupported preset/world/control/battle and unrepresentable state show the same reasons as CLI, including T185's precise UNKNOWN-region, historical-state, new-record residue or slot/record-lineage gaps. A live session has no bound original envelope, so the tax profile is not reachable from Save As. Template selection alone cannot turn these refusals into success. Existing output is refused even if the native file dialog's default overwrite confirmation was accepted; explain choosing a new name. Native JSON overwrite behavior is unchanged. Export neither issues an order nor advances a turn, closes a battle, changes controller flags, consumes draws or clears native unsaved state. A battle may still be saved to JSON under existing rules; SAV export is refused.
