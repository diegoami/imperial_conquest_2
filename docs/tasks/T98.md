#### T98 The OpenCode scripts on the 2.x CLI

- **Design milestone**: none. Process tooling: the OpenCode desktop app bundles the 2.x CLI and moved the shared database to its schema on 2026-10-01 (bug [#540](https://github.com/diegoami/imperial_conquest_2/issues/540)), and npm publishes no 2.x yet. **Labels**: `lane:infra single-instance`

- **Start after**: none · **Merge after**: bug #540's change (merged as a3f4602; it edits `scripts/Invoke-OpenCodeWatched.ps1` too). It is **never in flight with** another task or fix under `scripts/*OpenCode*`, `scripts/external-*.ps1`, `scripts/opencode-agents-v2/**` or `.opencode/**`.
- **Owns**:
  - `scripts/Invoke-OpenCodeWatched.ps1`;
  - `scripts/external-implement.ps1`;
  - `scripts/external-review.ps1`;
  - `.opencode/agents/external-implementer.md`;
  - `.opencode/agents/external-reviewer.md`;
  - `scripts/opencode-agents-v2/**` (new, only if the Permissions decision below needs it).
- **Scope**: the scripts run OpenCode **1.x** today (the npm `opencode-ai` package), with their own data directory since bug #540's change. The 2.x CLI (`%APPDATA%\ai.opencode.desktop\cli\<version>\opencode-cli.exe`, 2.0.18 on 2026-10-01) differs where the scripts depend on it:
  - **`run --dir` is gone.** The working directory is the process's own (`Start-Process -WorkingDirectory`).
  - **Variants.** `--variant <v>` is gone; the variant is part of the model, `provider/model#variant`.
  - **`run --title`** names the session the watcher looks for. Confirm 2.x keeps it (it is in 2.0.18's `run --help`).
  - **The background service.** By default `run` talks to a shared background service. The watcher must own and kill the process that does the work, so it passes `--standalone`. Establish whether the watcher's own `session list` and `export` calls see a standalone run's session; if they need a flag or the run's server, use it.
  - **Permissions** are the V2 model in 2.x, and a V2 agent broke every 1.x run on 2026-09-30, so one agent file can't be assumed to serve both. First establish whether 2.x accepts the 1.x permission syntax of `.opencode/agents/` (an agent whose `bash` deny rule rejects `git push`):
    - if it does, keep one 1.x-format file per agent;
    - if it doesn't, keep `.opencode/agents/` in the 1.x format, since every worktree carries those files. Under 2.x the scripts install a V2 copy over the agent file in the run's worktree. The copy comes from `scripts/opencode-agents-v2/`, which stays outside OpenCode's discovery path. The agent file is tracked, so `info/exclude` can't hide the change. Before the copy, the script marks the file `git update-index --skip-worktree`. After the run it clears the mark and restores the tracked version with `git checkout -- <file>`, in a `finally`. That way neither an implementer's commit nor its push can carry the V2 file to main.

    `--auto` is never passed.
  - **Output parsers.** Two parsers read 1.x stderr: `Get-OpenCodePermissionRejection` (issue #505) and `Test-OpenCodeAgentWarning` (the "agent … not found. Falling back to default agent" guard). Each must recognise its 2.x counterpart and keep its failure class.
  - **Session fields.** `session list --format json -n <n>` returns `id`, `title`, `directory`, `created` and `updated` (checked on 2.0.18). The watcher compares `created` and `updated` as epoch milliseconds, and the idle watch relies on `updated` advancing at step boundaries. Confirm both under 2.x. `export <session>` must still return the agent (`.info.agent`, read by `Get-OpenCodeSessionAgent`).

  **Which CLI runs.**
  - `IC2_OPENCODE_EXE` still wins.
  - Otherwise use the npm CLI, then the newest `opencode-cli.exe` under the desktop app's `cli\` folder. The desktop app's 2.x runs only when `IC2_OPENCODE_EXE` names it, or on a machine without the npm CLI. Why (the user's decision of 2026-10-03): the implementers' default model is an OpenCode Go model, whose login lives in the data directory's database. 2.x has no `console login` subcommand, and no way to log a 2.x data root into OpenCode Go is known yet ([PR #618](https://github.com/diegoami/imperial_conquest_2/pull/618), review round 1, R2). A 2.x default would make every `opencode-go` run fail and fall back to Claude Sonnet. Making 2.x the default again is a later change, once a 2.x Go login is proven.
  - The scripts read `--version` once. They build 1.x or 2.x arguments by the major version, log which version runs, and fail with exit 3 and a clear cause on an unknown major version.
  - 1.x stays supported, because a machine without the desktop app has only npm.

  **The data directory** (bug #540's change; its review follow-up #544 folds in here):
  - It is kept for both versions.
  - `XDG_DATA_HOME` is restored in the calling process after the run (a `finally`), while the run's children still see the isolated directory.
  - A relative `IC2_OPENCODE_DATA_HOME` is resolved to one absolute path before any directory is made.
  - The copy's source path, today hardcoded to `$HOME\.local\share\opencode\auth.json`, can be overridden by `IC2_OPENCODE_AUTH_SOURCE` (new), so a test can point it at a missing file without touching the real one.
  - With no `auth.json` to copy and no copy present, the run stops before any model is called, with a clear authentication cause.
  - The log line says "source missing" rather than "already current" when only the copy exists.
  - `XDG_CACHE_HOME` and `XDG_STATE_HOME` are isolated the same way and restored the same way, because the 2.x desktop app shares them too. Each gets its own subfolder of the root, `data`, `cache` and `state` (for example `…\ic2-opencode\data`), never one folder for all three.
- **Done when**:
  1. With the 2.x CLI, one watched run on the free model `opencode/mimo-v2.6-flash-free` and a one-line prompt, in a worktree, creates a session that the watcher detects and exits 0. The PR shows the log lines. The session's transcript export is kept under the run's `-LogDir`.
  2. With the 2.x CLI, a run whose prompt asks it to read a file outside its worktree is rejected, and the watcher classifies it `permission-rejected` (the #505 class), with the rejected path in its message.
  3. A `-WhatIf` style switch prints the argument line without starting OpenCode or billing a model, for both versions. For glm with its `max` variant it is `--model opencode/glm-5.3#max` under 2.x and `--model opencode/glm-5.3 --variant max` under 1.x.
  4. The idle timeout still kills the whole process tree under 2.x: a run with a 10 s idle timeout and a prompt that waits leaves no `opencode-cli` process behind.
  5. With `IC2_OPENCODE_EXE` pointing at the npm 1.x executable, Done-when 1 and 2 still pass.
  6. After a watched run under either version, the calling process's `XDG_DATA_HOME`, `XDG_CACHE_HOME` and `XDG_STATE_HOME` are back to their values before the run.
  7. A relative `IC2_OPENCODE_DATA_HOME` produces one absolute data directory, used by the run, the `session list` polling and the export.
  8. With an empty test data directory and `IC2_OPENCODE_AUTH_SOURCE` pointing at a missing file (never move or delete the real one), the run stops with an authentication cause before any session starts.
  9. After a 2.x implementer run in a worktree that tracks `.opencode/agents/external-implementer.md`, `git status --porcelain` lists no `.opencode/` path, `git ls-files -v` shows no skip-worktree mark on it, and the run's commits contain no `.opencode/` change.
  10. All three scripts parse without errors, `dotnet build IC2.sln` is green, and the diff lists only Owns paths.
- **Hazards**:
  - **Credentials.** Never read, print or log `auth.json` or any key (the user's standing rule). Copying it is fine.
  - **Billing.** Every Done-when run uses the free model. `external-review.ps1 -DryRun` still bills a model today, so don't use it as the no-billing check; that is what Done-when 3's switch is for.
  - **The desktop app's own data.** Never write to `~/.local/share/opencode/opencode.db`, or to the desktop app's cache or state directories.
  - **Concurrency.** Never run two OpenCode sessions at once.
  - **Docs.** This is a `lane:infra` change to process tooling, so the implementer edits no Markdown under `docs/`. Its PR's "Docs affected" names the lines that go stale, and the main session applies them after the merge. The lines are:
    - operating-guide.md §3's watched-run paragraph, including the `…\ic2-opencode-1x\…` log path, whose "1x" the port may make wrong;
    - build-process.md's descriptions of the scripts.
