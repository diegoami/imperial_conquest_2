- **Scope**:
  - **Protects**: T141's allocation, money bound and supply rebalance, the two-unit minimum, the 198-army cap, `DuplicateArmyId`, the new army's morale and the seat-asymmetric starting moves (`flags.seatAsymmetry`), unit and troop conservation, and the land army's placement whenever its south-east cell qualifies (`SplitPlacementTests`' shipped-world cases `(100,37) → (101,38)` and `(92,27) → (93,28)` pass unchanged). **The fleet placement**: `SplitPlacement.FleetCell` keeps `dy` outer, and every fleet test in `SplitPlacementTests` passes unchanged. The engine's other 3 × 3 scans, `LandingTile.FirstAdjacentLandTile` and `CoastalCity.FirstAdjacentSeaTile` (bug [#628](https://github.com/diegoami/imperial_conquest_2/issues/628)'s), are not changed. Join armies, Disband army and Embark keep their aboard refusals. Forbidden: an edit under `src/IC2.Engine/Ai/**` (no AI seat splits; the AI's mobilisation calls `MobilizationArmyCreation`, which is the one shared change); a ruleset key or flag; a change to the save format; a new verb or a change to `split-army`'s syntax; any change to the split dialog's layout or limits beyond the aboard branch.
  - **No aboard refusal** **[derived: code, the report's rule 1, `TUnitMap_SplitArmy` @ 0044755C checks only the owner (:47039) and more than one unit (:47041-47044), with Join armies' refusal (:46976-46978) for contrast; Wine candidate: four runs, `SA_01_aboard_before_split.v3.SAV` → `SA_02_after_split.v2.SAV`, release `run-exp-split-aboard`]**. `split-army` on an embarked army is handled as on a land army, in both presets **[designed for `improved`: the user's decision gives no preset difference]**.
  - **Where the new army stands.** The scan's centre is the carrying fleet's tile for an embarked army (`state.FleetById(army.AboardFleetId)`'s `X`, `Y`) and the army's own tile otherwise; `SplitPlacement.ArmyCellFor` resolves it, and both the handler and the Godot pre-check call it. The new army takes the scan's cell, on land, with `AboardFleetId` null and `CoveredTileCode` the cell's terrain code; the parent keeps its remaining units **aboard the same fleet**, and the fleet's link to it is unchanged **[derived: code, the report's rule 2, `FUN_00449F08` asks `FUN_004492C0(position, 1)` with the fleet's tile (:48724), sets the `+0x8` cell word (:48736), and the army is not aboard; Wine candidate: the new army stood on land at (102,47), not aboard, and army 0 stayed aboard with 2 units and 5,700 troops]**. With an embarked army whose fleet does not exist (a dangling link), the split is refused with `NoFreeAdjacentTile` **[designed: such a link has no tile; no new rejection code]**.
  - **What the new army holds**: moves 0 for a human owner and 1 for an AI one under `classical-faithful` (the handler's existing `seatAsymmetry` rule), purse and supply 0 before the dialog's allocation **[derived: code, :48732-48735; Wine candidate: moves 0, supplies 0, purse 0]**. Then T141's allocation and rebalance run exactly as for a land army **[derived: code, [`2026-10-03-army-to-army-ok-supply-rebalancing.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/main/docs/reports/2026-10-03-army-to-army-ok-supply-rebalancing.md) (research `a380a8e`), "All of the above applies to a split", which names no exception for an army aboard; an aboard split with supply over the parent's new capacity was not played]**.
  - **The scan nests x outer**: `FUN_004492C0` scans `dx` over −1, 0, +1 in the outer loop and `dy` over −1, 0, +1 in the inner loop, and keeps the **last** cell that qualifies **[derived: code, the report's rule 2, :47942-47943 and :47960-47962; the played position does not separate the two nestings, because (+1, +1) is last under both]**. So when (+1, +1) is blocked, the new army goes to (+1, 0), not (0, +1). Both `SplitPlacement.ArmyCell` and `MobilizationArmyCreation.PlacementCell` reproduce that one function, so both change; the remarks of each stop calling the nesting a `[derived]` guess and cite the report. **`FleetCell` stays `dy` outer** **[designed, as today: which routine places a split fleet is unread, and the one observed fleet split (`T_SPLIT_FLEET.SAV`, (101,46) → (101,47)) may be one that the two nestings separate]**.
  - **No free land tile: nothing happens, and nothing is said** **[derived: code, the report's rule 3, the scan leaves −1, `FUN_00449F08` creates nothing (:48725) and `TUnitMap_SplitArmy` does not open the dialog (:47047); not played]**. The rule is `FUN_00449F08`'s, so it holds for a land army as much as for one aboard. In the Godot app, `OpenSplitArmyDialog` calls `SplitPlacement.ArmyCellFor` on the army it would split; when it returns `null`, it opens no dialog, shows no message and submits nothing. The engine keeps its `armies.no-free-adjacent-tile` refusal for a `split-army` that reaches it, so a CLI script still learns that its order failed **[designed: the CLI is not a normal game ([§4.8](../build-process.md#48-the-playability-gate-until-v050)) and the original has no command layer; this is the report's "no message" applied to the game screen only]**.
  - **The Godot half removes T111's aboard refusal.** With a carrying fleet selected, or the army aboard selected, Split army opens T111's dialog on the army aboard, as for a land army; its limits, its `OK` line and its Disband buttons are unchanged. `ArmyDialogModels.SplitAboardRefusal` and `SplitArmyModel.IsAboard` go; `SplitArmyModel` still refuses one unit and the army cap with T111's messages.
