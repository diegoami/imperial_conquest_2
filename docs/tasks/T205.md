#### T205 Quick Split in two: strength-balanced whole-unit proposal

- **Release / priority**: v0.8.0 required QoL; P1. [Scope decision](../release-plan.md#25-planned-v080-faithful-battles-and-quality-of-life-automation).
- **Start after**: none. Independent of faithful Computer general correction #1355.
- **Owns**: `godot/UI/Dialogs/ArmyDialogModels.cs` (`SplitArmyModel` only), `godot/UI/Dialogs/SplitArmyDialog.cs`, `godot/UI/MainGameScreen.cs` (Split army opening route only), `godot/UI/GameCommandTable.cs` (one command row), `tests/IC2.Engine.Tests/Ui/ArmyDialogModelsTests.cs` (focused split tests), `tests/IC2.Engine.Tests/Ui/GameCommandTableTests.cs`, `godot/Checks/ArmyOrdersCheck.cs`. No engine split rules, combat formula, native save schema or other command handlers.

### Scope

The owner wants one **Split in two** action for a selected army. It opens the existing Split army dialog with a proposed distribution of **whole units**, leaving at least one in each army. It does not split any unit's troops, issue a command on opening, or replace the manual Split army action. The player can move units between lists, adjust money/supply and confirm or cancel as before.

Calculate projected field strength for both resulting armies with `ArmyPower.Compute`, using the current parent's morale and `ArmyManagement.NewArmyMorale` for the new army. Choose a legal nonempty/proper unit subset minimizing the absolute strength difference. For equal strength difference, choose the smallest troop-count difference, then the lexicographically earliest ascending source-slot list. Preserve each army's original relative unit order. With at most 20 units, the search must remain responsive at the cap; measure a worst-case 20-unit model invocation. Do not change the strength formula or use a different hidden metric.

The prefill changes only staged unit indexes. Money and supply start at their existing zero values; the dialog shows the projected strengths and retains its current resource controls. A refusal (too few units, army cap or no free land cell) follows the current Split army route. An army aboard a fleet uses the same legal route and preview.

### Done when

1. A selected own army has a distinct `Split in two` action beside `Split army`. Opening it uses the existing dialog with the deterministic strength-balanced legal proposal and submits **zero** commands. Manual `Split army` still opens empty.
2. Focused pure-model tests compare the proposal with an independent exhaustive oracle for varied type, troop and morale cases; cover equal-score tie-breaks, one/two/20-unit bounds, invalid split/cap, and repeated identical output. A 20-unit case finishes within a stated local time budget without changing state or RNG.
3. The dialog shows both projected strengths, lets the player edit the proposed whole-unit allocation, and keeps money/supply untouched until adjusted. Cancel leaves game state and command count unchanged; OK sends exactly one existing `split-army` command with the displayed indexes/resources.
4. `ArmyOrdersCheck` exercises the new action on land and aboard a fleet, manual Split army unchanged, and the no-free-tile and one-unit refusals. `GameCommandTableTests` covers the new row. Build the solution and Godot project; run focused tests, the headless check scene and the Godot churn guard. Record actual pass/fail/skip counts.
