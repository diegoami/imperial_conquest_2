- **Scope**: Four single, non-reproducing failures across four tasks (T63, T64's CI, T64's local run, T21's local run) all hit tests that build on the fly or scan the disk:

  The export tests run `dotnet run scripts/export-classical-world.cs`, which builds into a shared `%TEMP%\dotnet\runfile\…` directory. T62's review found the same race between two export tests (CS2012) and fixed only its own test with a non-parallel collection (`WorldTerrainExportScriptCollection`). T68 added a third test to that collection.
- **Done when**:
  1. **One collection.** Every test that runs a `dotnet run` script (`Export/**`, `WorldTerrainSidecarTests`) is in one non-parallel collection, defined in one place. A test lists them by reflection and fails if a test that starts `dotnet run` sits outside it.
  2. **Isolated output.** Each `dotnet run` gets its own build output, for example through `--artifacts-path` or an equivalent flag under a per-run temporary directory, which is deleted afterwards. Explain why the chosen flag isolates the build, citing the .NET SDK documentation. No run leaves **build output** behind: nothing under the per-run directory survives, and no `obj/` or `bin/` appears under `%TEMP%\dotnet\runfile\`. Show a before-and-after listing. *(Amended 2026-09-24 by the user's decision at T74's escalation. It first read "no run leaves a directory behind under `%TEMP%\dotnet\runfile\`". Meeting that meant deleting the SDK's own ~1 KB `build-start.cache` marker entry, and the only way to find it was a reverse-engineered, undocumented name, which failed on CI's Linux runner. That marker entry belongs to the SDK and is left alone. The runner deletes nothing under `runfile\`.)*
  3. **The guard ignores what tests write.** First find what writes into `src/**` or `godot/**` during a test run: a full-suite run with a before-and-after `git status --porcelain --ignored` over those trees. Then either the guard skips exactly those paths, with a remark naming each writer, or the writers move to the temporary directory. A writer outside this task's Owns list is **reported, not patched** ([build-process.md §4.6](../build-process.md#46-bugs-and-follow-ups)).
  4. **Stress check.** `dotnet test IC2.sln` runs 20 times in a row on the configured machine (`assets.local.ini` present) with zero failures. The PR gives the loop, the 20 pass counts and the total time. Any failure is captured with its test name and full message; the task is not done until the cause is fixed or reported as a bug.
  5. `dotnet build IC2.sln` and `dotnet test IC2.sln` are green, no assertion in `Export/**` changes, and the diff lists only Owns paths.
- **Hazards**:
  - **A non-parallel collection removes a symptom and does not prove a cause.** Done-when 2 and 3 are the cause-level fixes; 1 alone is not enough.
  - **Isolating output costs a cold build per run.** Say how long the suite takes before and after. A large slowdown is a reason to share one isolated directory inside the collection, not to drop isolation.
  - **The guard exists to catch real references to the candidates.** A path filter that is too broad (for example, everything under `obj/`) must still fail when a production file references a candidate; show that with a mutation.
- **Constraint**: `local-only`. Done-when 4 needs the configured original files, which the export tests read.
