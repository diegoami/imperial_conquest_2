# T259 — Deterministic barbarian boundary-arrival planner

Issue [#1685](https://github.com/diegoami/imperial_conquest_2/issues/1685),
part of [#1683](https://github.com/diegoami/imperial_conquest_2/issues/1683).
Owner decisions are in [the barbarian design](../design/barbarians.md).

Own `src/IC2.Engine/Barbarians/BarbarianArrivalPlanner.cs`,
`tests/IC2.Engine.Tests/Barbarians/BarbarianArrivalPlannerTests.cs` and these docs.

Implement pure arrival planning against current terrain and occupancy. Null
policy disables planning without RNG draws. Validate enabled configuration and
faction/world references. Count carried armies against the four-army cap; the
four-fleet cap prevents sea entry but still permits land entry. Use one 25%
chance check per call (the future seasonal caller owns cadence), equal choice
between legal land/sea modes and stable row-major entry order. Exclude cities
and occupied tiles. Sea entry requires an unoccupied sea route to a free land
landing. Return an in-bounds proposal without modifying state or creating units.

Done when meaningful controls cover failed chance, disabled/no-entry/no-draw,
both modes and map borders, occupied/city tiles, sea connectivity, army/fleet
caps and land fallback, degenerate maps, invalid configuration, seed replay
and unchanged input state. Run focused tests and relevant determinism controls.
No save schema, phase registration, campaign activation or GUI changes. The
subsequent executor must atomically create and revalidate army/fleet links;
faction lifecycle, hostile AI, upkeep, capture and campaign acceptance remain
separate slices. Passing this task is not completion of the barbarian feature.
