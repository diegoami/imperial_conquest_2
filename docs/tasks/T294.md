#### T294 Seeded random maps with five regional styles (contract and decomposition)

Owner request [#1809](https://github.com/diegoami/imperial_conquest_2/issues/1809), v0.11. Styles, the proposed New Game flow and the validation list are in [v011-campaigns-and-random-maps.md](../design/v011-campaigns-and-random-maps.md#fictional-regional-geography); the [terrain-authoring rule](../design/terrain-authoring.md) applies to every recipe (crest-only mountains, forest foothills, deliberate plain passes). **Contract only; no generator exists.**

**Verified constraints:** worlds are plain data (`data/worlds/<id>.json` plus a terrain sidecar), so a generated world can be a normal `World` value; the Near East maps use 276×185 and the classical one 320×140, each with 16 nations. Classical navigation applies only to `classical-mediterranean`, so generated worlds use the **generic AI policy** (the one Italy and the Near East use); no new AI tables are needed, but AI play on generated terrain must be measured, not assumed.

**Architecture:**
1. A pure, deterministic `MapGenerator(version, style, seed, size, parameters) → GeneratedWorld` in the engine layer. It never touches campaign RNG and uses its own seeded stream.
2. A generated world is **stored inside the save** (terrain sidecar plus settlements), so saves survive generator upgrades and preview-cache eviction. The generator version and parameters are recorded for provenance only; reloading never regenerates.
3. Per style, a recipe composes landmass, water, rivers, uplands (crest mountains, forest foothills, plain passes), settlements and ports, then runs the validator. Invalid output is rejected and retried with a bounded count (proposed 20), then fails with a message naming the failed check.
4. Validator: land/sea connectivity; navigable straits; ports reachable; legal settlement and army starts; nearby resources; expansion room; river drawing consistent with crossings; **practical crossing cost** (production movement rules, ordinary army budget) between settlement clusters, not just connectivity.
5. New Game flow: Random map → style and seed → three candidate previews → choose one → seats. A world editor is out of scope.

**Follow-up tasks:** (a) engine audit: terrain/river encodings, limits, port rules, pathfinding and AI assumptions; (b) generator core, seed stream and validator, with property tests over many seeds per style plus adversarial/disconnected cases; (c) the five recipes (Mediterranean first, as the nearest to existing data); (d) factions, naming and starting forces for a fictional map (authored lists, not transplanted historical powers); (e) save embedding and round-trip tests; (f) New Game preview UI; (g) AI play, performance and packaging checks.

**Owner decisions, 2026-11-09:** first release has **one map size**, **three previews**, and the generated world is **embedded in the save**. Faction/naming scheme is still open.

**Questions asked:**
1. Map sizes and nation counts offered (proposal: one size to start).
2. Faction/naming scheme for fictional maps.
3. Whether three previews is the right number.
4. Generated saves embed the whole world (proposal: yes; larger saves, but upgrade-proof).

**Done when (this contract task):** reviewed, decisions answered, (a)–(g) created as issues linked from #1809.
