#### T168 The UI's look, evaluated against the original, with font and palette candidates for the user to choose

- **Design milestone**: M18 (the Godot screens). Planned from [#899](https://github.com/diegoami/imperial_conquest_2/issues/899) (the user's request of 2026-10-09: an ancient-looking font, more font variety, a reworked colour scheme, compact panels, no Godot splash) and the user's priority of 2026-10-12 for `v0.6.0`: *"most important is the font refont (too impersonal and not compact enough)"*. **Labels**: `lane:ui release:v0.6.0`
- **Branch**: `task/T168-ui-evaluation`, from `origin/main` · **Implementer and reviewer**: the user's choice ([CLAUDE.md](../../CLAUDE.md) rule 17)
- **Start after**: none · **Merge after**: none. [T169](T169.md) applies the user's choice and starts after this task.
- **Owns**:
  - `docs/investigations/ui-redesign-evaluation.md` (new): the evaluation and the candidates, and its row in `docs/investigations/README.md`'s index.
  - `godot/Assets/Fonts/candidates/**` (new): the candidate font files, each with its licence file beside it (SIL OFL or another licence that allows bundling in the release).
  - `godot/Checks/FontCandidatesTour.cs` and `.tscn` (new): a windowed tour, not a headless check (its file name does not end in `Check`, so CI's loop skips it), that renders the same sample of every surface (a menu title, a dialog header, a panel of figures, a table row, a news line) once per candidate pairing and palette, and writes one screenshot per candidate under the git-ignored `rendered/`.
- **Scope**:
  - **Protects**: nothing in the game changes. No screen's look changes in this task; [T169](T169.md) applies what the user chooses.
  - **The evaluation** (the document): a screenshot of every screen and dialog as it stands (the existing screenshot tours, `godot/Checks/*ScreenshotTour*` and `ScreenshotTour.tscn`, give most of them), each set against the original's look where a recording or screenshot of the original exists in the research repository, judged on hierarchy, legibility, consistency, compactness (the user's two complaints: the army panel's font too large and its line spacing too loose, #899; the transfer dialog's font too big, #1070) and where the app reads as modern rather than ancient. Every claim about the original cites its source.
  - **Fonts:** at least three candidate pairings, each a display face with an inscriptional, ancient feel for titles, headers and the menu bar, and a compact, readable body face for panels, tables and the news log (with tabular figures, or a numeral face beside it). Every candidate's licence allows bundling it in the release, and the document names the licence and the source URL.
  - **Palettes:** at least two candidate palettes (for example parchment, bronze, stone, Tyrian purple), each with its contrast ratios for text on every panel colour (WCAG AA, 4.5:1 for body text, as [asset-specification.md §2.2](../asset-specification.md#22-the-accessibility-check-applied) applies to the nations' colours). The sixteen nations' colours stay the original's.
  - **A compact type scale**, proposed in the document: the sizes and line spacings T169 will apply, with the army panel's lines (T140's fields) shown at the proposed scale.
  - **The user decides.** The main session posts the tour's screenshots for the user, who picks a pairing, a palette and the scale (or asks for changes). The pick is recorded in the document's last section by the main session after the review, and [T169](T169.md)'s entry is updated to name it before T169 is dispatched.
  - **Out of scope**: applying any of it (T169); the city markers' three colours (#912, a separate task); the battle screen's own art (T128).
- **Why it stays whole** (build-process.md §4.11): the evaluation, the candidates and the tour are one deliverable, the material for one user decision; split, the user would review fonts without the screens they are for.
- **Done when**:
  1. **The evaluation** exists: one screenshot per screen and dialog, each judged against the criteria above, with every claim about the original sourced.
  2. **The candidates:** at least three font pairings and two palettes, every font file bundled under `godot/Assets/Fonts/candidates/` with its licence, and the document names each source and licence.
  3. **The tour** renders every candidate and writes its screenshots; the main session posts them for the user.
  4. **Nothing in the game changes:** `git diff --name-only origin/main...HEAD` lists only Owns paths; build, test and every headless check are green.
- **Hazards**:
  - **Licences.** A font whose licence does not allow redistribution in a released zip and installer is not a candidate, however good it looks.
  - **The tour needs a window.** Like the other screenshot tours, it cannot run headless; it is run by the main session or the implementer on the machine, and CI's loop does not pick it up (its name does not end in `Check`).
