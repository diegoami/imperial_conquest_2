#### T101 Asset keys for the toolbar icons

- **Design milestone**: M18 (the Godot UI). From the user's decision 2 of 2026-10-01 and the UI command audit's asset count ([`original-ui-command-audit.md`](../investigations/original-ui-command-audit.md) §3.5), which closes the gap [asset-specification.md §4.7](../asset-specification.md#47-chrome-with-no-key-today--the-main-screen-dialog-and-battle-result-gaps) left to "whichever task first wires the toolbar". **Labels**: `phase:3 lane:ui`
- **Branch**: `task/T101-toolbar-icon-keys` · **Model/effort**: Sonnet / Medium · **Reviewer**: **Opus**/Medium **+ human visual review**
- **Start after**: the user's go-ahead on the issue for the billed generation run (below) · **Merge after**: none. It launches no Godot, so it is not `single-instance` and may run alongside T100. It is **never in flight with** another task that edits `src/IC2.Engine/Assets/**`, `assets/**` or `scripts/generate-*-assets.*`.
- **Owns**:
  - `src/IC2.Engine/Assets/AssetKeys.cs` (a new `ui.command` group, and `AllKeys`);
  - `assets/prompts.json` (the new keys' prompts only);
  - `assets/packs/placeholder/manifest.json` and `assets/packs/placeholder/ui/**` (new);
  - `assets/packs/authored/manifest.json` and `assets/packs/authored/ui/**` (new);
  - `scripts/generate-placeholder-assets.ps1`;
  - `scripts/generate-authored-assets.py` (only if the new category needs its own conform rule);
  - `tests/IC2.Engine.Tests/Assets/**` (the existing tests whose key counts or category filters change, and new tests);
  - `docs/asset-specification.md` (§4.7's toolbar bullet, §6's key block, and one depiction line per new key).
- **Scope**: 36 new keys, one per toolbar command, from the audit's §3.5 count. Each is `ui.command.<id>.icon`, 32 × 32, 32-bit BGRA with straight alpha, under §1.2 and §1.3's chrome rule:
  - **Main toolbar (9)**: `open`, `save`, `end_turn`, `news`, `relations`, `taxation`, `balance_sheet`, `recruit_unit`, `build_fleet`.
  - **Area-map strip (12)**: `show_cities`, `show_capital`, `show_armies`, `show_fleets`, `show_all`, `show_mercs_light_infantry`, `show_mercs_heavy_infantry`, `show_mercs_archers`, `show_mercs_light_cavalry`, `show_mercs_heavy_cavalry`, `show_mercs_all`, `find_city`.
  - **Unit-map strip (15)**: `army_supply`, `army_recruit_mercenaries`, `army_transfer_unit`, `army_split`, `army_join`, `army_change_units`, `army_disband`, `fleet_supply`, `fleet_repair`, `fleet_transfer_ships`, `fleet_split`, `fleet_join`, `fleet_scuttle`, `city_fortify`, `cancel_selection`.

  The 16 nation buttons and All nations get **no key**: they are colour swatches. The Area-map strip's ToggleMap and gold-coin buttons get **no key**, because what they do is **[open]** (audit §1.5, §3.2). `cancel_selection` is **[designed]**: the strip's 15th button is unread, and Cancel selection fits it.

  - **Style [designed]**: toolbar icons are **pictorial and full-colour on a transparent background**, as the original's are. They are **not** tinted at draw time, unlike the markers. The authored pack's silhouette test (`AuthoredPack_SpriteAssets_CarryTransparencyAndALightNeutralSilhouette`) is narrowed to the marker categories. `ui.command.*` gets its own check: format, size, and at least one transparent pixel.
  - **The placeholder pack** gets a deterministic, byte-identical stand-in per key from `generate-placeholder-assets.ps1`. Each is a geometric pattern derived from the key, distinct from every other key's, with no font rendering, because fonts differ between machines.
  - **The authored pack** gets the 36 icons from `scripts/generate-authored-assets.py --key …`, after a `--dry-run` that lists them, in **one billed run for these keys only**. Its prompts describe generic subjects (a scroll for News, scales for the Balance sheet, a coin purse for Taxation, and so on), never the original game, its art or its screenshots (T51's DoD 7).
  - **§4.7** records the 36 keys and their commands, replacing its "naming left to whichever task first wires the toolbar". It also corrects the fleet strip's provisional labels to the audit's six orders (Supply, Repair, Transfer ships, Split, Join, Scuttle). §6's block gains the 36 keys.
- **Done when**:
  1. `AssetKeys.AllKeys` yields exactly the 25 existing keys plus the 36 above, and `AssetKeysTests` pins the new count and each new constant's string.
  2. `AssetSpecificationCoverageTests` passes against §6's updated block, in both directions.
  3. Re-running `generate-placeholder-assets.ps1` into a scratch directory reproduces the committed placeholder pack byte for byte (`git diff --no-index` empty), and `AssetValidationAgainstPlaceholderPackTests` and `PlaceholderPackIntegrationTests` pass.
  4. No two `ui.command.*` placeholder images are byte-identical: a test hashes them.
  5. `AuthoredPackConformanceTests` passes, with one prompt per key and the authored pack's `ValidateAssets` reporting zero missing. The `ui.command.*` images pass the format, size and transparency check. The marker silhouette check still covers every marker key it covered before.
  6. A grep of `assets/prompts.json` for "Imperial", "Conquest", "screenshot" and "original" finds nothing in the new prompts.
  7. The user's visual sign-off of the 36 authored icons: the main session posts a contact sheet on the PR.
  8. `dotnet build IC2.sln` and `dotnet test IC2.sln` are green with no generator key present, and the diff lists only Owns paths.
- **Hazards**:
  - **Billing.** The real generation run costs money and needs the API key from the git-ignored local config (T51). Run `--dry-run` first, then one `--key` run for the 36 keys only, never `--all`. Never print, log or commit the key.
  - **Non-determinism** (T51): never assert byte equality on the authored pack, only conformance.
  - Whether Godot honours the 32-bit BMP alpha is §1.2's open item. T100 is the first task that draws these icons, and it records the answer.
  - The original's art cannot ship. The icons are new work.
