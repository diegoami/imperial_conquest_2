#### T80 The CLI demo: every order succeeds once, and no command type can be left out

- **Design milestone**: M18 (the headless half). It is a correction for [#348](https://github.com/diegoami/imperial_conquest_2/issues/348), a known gap in v0.3.0's release notes (Fable F3, DeepSeek finding 4). **Labels**: `phase:3 lane:ui` · **Release**: `release:v0.4.0`
- **Branch**: `task/T80-cli-demo-success` · **Model/effort**: Sonnet / High · **Reviewer**: **Opus / Medium**
- **Start after**: — · **Merge after**: —. It should merge **before T24**, the Godot main screen, which drives the same commands.
- **Owns**:
  - `tests/fixtures/cli/**` (a new success-path script and its golden; the existing `demo.txt`/`demo.golden.txt` stay as they are)
  - a new scenario fixture for it, if one is needed, under `tests/fixtures/` (never `data/`)
  - `tests/IC2.Engine.Tests/Presentation/**`: new test files only
  - **Added 2026-09-27 after the first implementation (PR #452, the user's decisions on #356):** `data/scenarios/example-cli-*.json` and `data/worlds/example-cli-*.json`, **only if** an order needs a starting state no shipped scenario has, such as a fleet-owning nation at peace for `attack-fleet`. The CLI loads scenarios only from `data/` (T26's finding), and these follow T26's `example-` naming.
- **Scope**: The committed golden transcript issues all 28 command types, but 27 are rejected at validation and only `move` executes. It proves routing and validation, not that each order works. And nothing makes a newly added command type join the demo.
- **Done when**:
  1. **Every order succeeds once.** A second scripted scenario, with its own golden transcript, issues each of the 28 command types at least once **successfully**: each line's outcome in the transcript is an accepted command, not a rejection. A test runs it in-process and compares it with the golden byte for byte, as `GameSessionTests` does for the demo.
  2. **No command type is left out.** A test lists every `ICommand` type by reflection and fails, naming it, if a type has no CLI verb, or has no line in the success-path script that the golden shows accepted. Show both mutations in the PR: a throwaway `ICommand` type with no verb, and a type's script line removed.
  2b. **Keyed exceptions, and nothing else** (added 2026-09-27, the user's decision). The coverage test may exempt exactly these, each named in the test with its reason:
     - the three AI-only commands, which have no CLI verb **by design**: `AiFormAllianceCommand`, `AiFormTradeCommand` and `AiSwapTradePartnerCommand`. Their handlers refuse a non-AI issuer.
     - `HireMercenaryCommand`, keyed to [#229](https://github.com/diegoami/imperial_conquest_2/issues/229) (T56), **only if** the PR shows the mercenary pool is empty in every shipped scenario. It must also reconcile that with T56's own Scope, which says T22's soak fires the hire in the first quarters.
     - `EmbarkArmyCommand` and `DisembarkArmyCommand`, keyed to bug [#453](https://github.com/diegoami/imperial_conquest_2/issues/453) (T93).

     Each keyed exception names its issue. The task that closes that issue removes the exception and adds the command's line to the success script. `attack-fleet` and `peace-yes` get **no** exception: both must succeed. Use a different seed for `peace-yes`'s `Random(5)` roll if needed, and say why that seed. Use an `example-cli-` scenario for `attack-fleet` if needed.
  3. **The original demo is unchanged.** `demo.txt` and `demo.golden.txt` reproduce as before, since the release checklist item 7 pins them.
  4. `dotnet build IC2.sln` and `dotnet test IC2.sln` are green, and the diff lists only Owns paths.
- **Hazards**:
  - **Some orders need a set-up state**: an adjacent enemy to attack, a pending offer to accept, a fleet at a port, an army in debt. Build it with ordinary commands in the script where possible, and with a fixture scenario where not. Never special-case the CLI.
  - **Determinism.** The golden must reproduce from a fixed seed. Say which seed and why.
