With `HumanBattles = Tactical`, a human's `attack-army` whose legality passes (`AttackLegality`, unchanged) and whose attacker or defender nation has a `Human` seat zeroes the attacker's moves and opens the battle (T123's copy-in) instead of dispatching `AttackArmyCommand`.   - **The battle's orders**, as CLI verbs and as `GameSession` methods for T127: `battle show`, `battle place <unit> <x> <y>`, `battle move <unit> <x> <y>`, `battle attack <unit> <enemy>`, `battle shoot <unit> <enemy>`, `battle clear <unit>`, `battle end`, `battle general on|off`, `battle surrender` (with the confirmation), each mapping to one human order of T123 [designed: the verbs].   - **The draws.** One `IRng` stream per battle, derived from the state's seed and a stable battle key (`battle.tactical:<attackerArmyId>:<defenderArmyId>:<turnIndex>` [designed]).   - **The end** ("Write-back"). T123's write-back (steps 1–5), then step 6 through the existing T88 path: the peace treaty offer between a human and an AI side, gated on `strength(W) < strength(L)`, `unity(L) > 500`, `cities(L) > 7` and `Random(5) < 2` (`TBattleOver_OK`, report §9), the draw taken from the battle's stream after the promotions and only when the three tests pass. `strength(n)` is the decompile's `armies(n)`: `FUN_0044A8CC`'s army power summed over the nation's remaining armies after the loser's deletion (`0x0045940A`–`9447`, `CMP EDI,[ESP+8]` at `0x004594DC`, [`decompiled-war-cascade-and-peace-paths.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/main/docs/reports/decompiled-war-cascade-and-peace-paths.md) §2.3), the same sums the merged instant path compares (`InstantBattleResolver.cs` ~:304–306, `TotalArmyPower`); the session reuses that comparison, it does not re-derive it; between two human seats, the existing hotseat payment path. The `TacticalBattleReport` goes to `SessionOutput` for the *Battle ended* window. Every turn-level consequence that follows a battle today (elimination checks, victory, the news log) runs as after an instant battle.
  - **Saves** (the user's decisions of 2026-10-04 on [#496](https://github.com/diegoami/imperial_conquest_2/issues/496); `game-design.md`, "Saves"): `save` (and so the UI's Save and Save As) works during a battle. The clone's save gains an optional `Battle` section, the block's fields (header, 40 slots, 14 × 12 grid) in the clone's own JSON format, never an original `.sav` (principle 6), behind save-schema version 4; a version-3 save migrates with no battle. Loading a save with a battle reopens it and runs T123's `Resume`, the half-round setup for the side to move (`FUN_00439968`): moves refilled, targets cleared, the counter incremented, a pending melee lost, as the original resumes **[confirmed: code, static, report §3; Wine candidate: [`2026-10-04-tactical-battle-sweep.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/main/docs/reports/2026-10-04-tactical-battle-sweep.md) B2, [`2026-10-04-battle-probe.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/main/docs/reports/2026-10-04-battle-probe.md) items 2 and 4]**. The battle's draw stream position is saved with it [designed], so a reload is deterministic. This is `classical-faithful`'s policy, saving at any point; `improved`'s "only at the start of a half-round" is T130's switch. For it, T125 also provides, unused under `classical-faithful`: the `Battle` section records `atHalfRoundStart` (true when no order of the current half-round has been given since its setup), and a second load path, **exact restore**, rebuilds the state from the section as saved (counter, moves, targets, claims and the draw stream's position) **without** calling `Resume` [designed]. The session's load picks `Resume` unless the ruleset asks for exact restore and the section says `atHalfRoundStart`; T125 ships with no ruleset asking, so every classical reload goes through `Resume`.

- **Hazards**:
  - **No task changes `InstantBattleResolver`'s outcomes for battles the original still auto-resolves.** The branch sits in the session, before dispatch; the instant path is called exactly as today when it applies. A shipped seeded value that moves is a stop-and-report.
  - **The decoupling guard.** No file under `src/IC2.Engine/Battle/**` may reference the diplomacy namespace (`FieldBattleTests.AssertNoBattleSourceReferencesDiplomacy`): the peace step lives in `TacticalBattleSession.cs`, under `Presentation`.
  - **The AI phase is not this task's.** If an AI seat's turn attacks a human army, it still resolves at once (T116's option A) until T126. Do not suspend the AI loop here.
  - **`HumanBattles` is a session switch, not a rule.** It is never saved and never in a ruleset; a reloaded game takes the switch of the session that loads it. A save that holds an open battle reopens it whatever the switch: the battle is already being fought.
  - **The default stays `Instant`** so that the Godot UI keeps working on `main` between this merge and T127's; if the review or the user wants the CLI default changed, that re-baselines goldens and is a follow-up, not a change here.
  - **The clone never writes an original `.sav`.** "Saving the battle block" means the block's fields in the clone's save; the original's byte layout is T129's reader only.
  - **The resume is the original's, not a continuation.** Re-running the setup on reload is the rule under `classical-faithful`, even though it loses a pending melee; do not "fix" it here.
