# T220 — Visible recruitment quality and Average-or-better auto-mobilize

Owner requirements: #1499 and #1500 (2026-10-27). This supersedes T209's provisional automatic policy of collecting every manually ready slot.

## Contract

- Every training row in Recruit unit, the city detail panel and the nation overview shows its **current** quality as the same short words used for mobilized units. Put quality first so horizontal clipping cannot hide it. Do not predict a future quality or add a paragraph to each row.
- Auto-mobilize remains opt-in, global, and runs only for the active human nation on confirmed End turn. It requires both ordinary readiness and quality **Average or better**. The existing `ArmyDialogModels.QualityCaption` table defines Average as tier 6; derive quality using `MobilizationReadiness.QualityFor`, including custom divisors. Higher tiers qualify too.
- Preserve manual early mobilization, training, command refusals, queue compaction, deterministic IDs, AI behavior, state/RNG and save schemas. Existing settings retain their enable/disable choice.
- Cancel/Make more moves issues nothing. Accepted mobilization still precedes support; ordinary End turn runs once.

## Owns

`godot/UI/RecruitmentPanelViewModel.cs`, `godot/UI/Automation/AutoMobilizePlanner.cs`, `godot/UI/Dialogs/RecruitUnitDialog.cs`, `godot/UI/ContextPanel.cs`, `godot/UI/NationStatusModel.cs`, the auto-mobilize explanation/control in `godot/UI/SettingsScreen.cs`, matching `tests/IC2.Engine.Tests/Ui/` tests, and `RecruitQualityCheck`, `SettingsCheck`, `EndTurnBoxCheck`. Engine command/readiness rules are read-only.

## Done when

1. Production planner tests reject quality 4/5 and accept 6/higher in both presets, prove custom quality divisors are honored, retain human/AI and invalid-index controls, and exercise real commands including manual early mobilization.
2. Training models expose actual quality and its concise caption. The actual Recruit unit list places quality first, with the selected-row caption consistent; city/nation rows use the same value.
3. `RecruitQualityCheck`, `SettingsCheck` and `EndTurnBoxCheck` complete headlessly. The latter retains manually ready low-quality slots through confirmation and ordinary training advancement, alongside an automatically mobilized Average slot. No owner campaign/settings are touched.
4. Solution/Godot builds, relevant focused tests and CI pass; native save format does not change. Visual clipping/readability is assessed separately from headless behavior.

Docs affected: this contract, task index, and T209 policy cross-reference. No new original-game fidelity claim.
