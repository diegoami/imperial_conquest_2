## Contract

- Paid staging first floors the requested working amount at zero, then clamps against provider stock, signed target room, and (PerUnitPurses only) target purse affordability. Do not floor the final admitted amount. Army room uses the dialog bonus; fleet room uses ship capacity. Empty provider stock does not prevent returning excess.
- A nonzero signed amount can be purchased: return excess supplies to the selected foreign town and refund the target purse, debiting that town owner's treasury. Division truncates toward zero; returns of 1/4 tons refund zero, 5 tons refund one talent. Preserve Improved treasury funding and all other eligibility/provider policies.
- Keep `buy`/`buy-fleet-supply` command requests strictly positive. For a negative staged admission, send a positive request of one ton; the existing production purchase rule independently recomputes the same signed admission from current state. No negative-request grammar or engine rule change is needed. Zero staging submits nothing.
- Staging changes no live resources. Closing before purchase discards staging; closing afterward retains the already applied transfer. Refresh clears staging. Show a concise Return/Refund caption for a negative amount.

`SupplyDialogModel.AdjustStaged`/`TransferStaged`, negative staged-amount captions in `SupplyDialog`, production model/session regression tests and an actual Godot paid-refund check. Engine purchase/accounting rules and unrelated provider-switch behavior are read-only.
