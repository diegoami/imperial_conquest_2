#### T121 Re-run the auto-resolve tournament on the original's melee matrix

- **Design milestone**: none. It re-measures T59's tournament ([#250](https://github.com/diegoami/imperial_conquest_2/issues/250)) once T120 (#654) has put the original's melee matrix in the rulesets. The user's decision of 2026-10-04 makes it, with T120, an exception to the playability gate ([build-process.md §4.8](../build-process.md#48-the-playability-gate-until-v050)). **Labels**: `phase:2 lane:engine`
- **Branch**: `task/T121-tournament-rerun` · **Model/effort**: Sonnet / High · **Reviewer**: **Opus**/Medium: **very complex** under [§3.4](../build-process.md#34-why-the-reviewers-model-differs-from-the-implementers) criterion (e), since it re-baselines a seeded measurement (the tournament scorecard)
- **Start after**: T120 · **Merge after**: T120. It is **never in flight with** a task or fix that edits `src/IC2.Engine/Battle/**`, `data/rulesets/*.json` (`combat` or `unitTypes`) or `tools/AutoResolveTournament/**`, because any of them would move the numbers mid-run.
- **Owns**:
  - `tools/AutoResolveTournament/results/**`: regenerated by the tool's own `soak`, `run` and `smoke` commands, never edited by hand;
  - `docs/investigations/auto-resolve-tournament-results.md`;
  - `docs/investigations/README.md`: **only** the tournament row's "Corrected 2026-10-04" sentence;
  - `docs/investigations/auto-resolve-approaches.md`: **only** the two sentences T120 rewrote about T59's measurements (the 2026-10-04 banner, ~:39–42, and after §4.3's table, ~:441–443).

  No source and no test is owned. T120 re-pins `TournamentTests`' reduced-seed hash. If the tool, a candidate or a test needs a change for the run to work, stop and report.
- **Scope**: T59 measured C2–C5 on the rulesets' `combat.detailedResolver.typeEffectiveness`, which held DAT `0x1F3B8`'s two AI tables and not the melee matrix ([#647](https://github.com/diegoami/imperial_conquest_2/issues/647)). The results document carries a 2026-10-04 banner saying so. T120 corrects the matrix to DAT `0x1F7A6`'s. This task runs the same tournament again, on the same code, harness, metrics and seed set, and replaces the numbers. It measures; it does not redesign.
  - **What is re-run.** Everything the results document reports is re-run, by the commands of its §9:
    - `soak` (§5's E0 and B), run on the machine that runs the tournament, because the cost comparison is only meaningful on one machine;
    - `run` (the scorecard, §2–§6), with §8.0's seed rule, `S = 200` seeds per matchup (`TestArmies.SeedsPerMatchup`, the tool's default): 186,000 battles per candidate;
    - `smoke` (§7, the observed battles, seeds `k = 0 … 999`).
  - **C1 is the control.** C1 wraps the shipped `InstantBattleResolver` and reads no matrix. The `combat` and `unitTypes` blocks of `classical-faithful` are unchanged in value since T59 merged, apart from T120's matrix, and `TournamentTests`' reduced-seed hash was never re-pinned before T120. That premise did not hold: T121's first attempt found C1 changed (the merged resolver draws 25 times per battle where T59 measured 26) because of battle-path work merged since T59, not the matrix. By the user's decision of 2026-10-04 on [#655](https://github.com/diegoami/imperial_conquest_2/issues/655), C1 is re-measured like the others, and Done-when 3 proves the matrix did not move it.
  - **C2–C5 are measured as specified.** C2's and C5's D06 and D07 rules ([#648](https://github.com/diegoami/imperial_conquest_2/issues/648)) stay the designed placeholders of [`auto-resolve-approaches.md`](../investigations/auto-resolve-approaches.md). The user's decision of 2026-10-04 makes the v0.5.0 battle a fresh port of the decompiled `TBattleMap`, so those placeholders are superseded, not fixed. The re-run says so; it does not correct them.
  - **The document keeps its stance.** It records data plus analysis, not a decision. The tables stay in the neutral C1–C5 order, with no ranking, no verdict column and no pass totals. Where a new number reverses a sentence of §6 or §8, that sentence is rewritten to the new number. It is not deleted, and no conclusion the user has not drawn is added.
- **Done when**:
  1. **The soak baseline is re-measured on the run's machine.** After `dotnet build IC2.sln -c Release` (the `--no-build` commands here need it), `dotnet run -c Release --no-build --project tools/AutoResolveTournament -- soak` regenerates `results/soak-baseline.txt` with `replay/final-state mismatches 0`. `AiSoakTests.Fifty_fixed_seeds` (Release) prints E0. The PR gives E0 and B and compares them with the committed `1.81s` / `B = 150` / `sieges 0` / `naval 0`. It does not assume a cause: E0 is a wall-clock measurement and can move with the machine or the run alone. A change in a count (`B`, sieges, naval) is attributed only to a merged change the PR identifies by commit; a change in E0 alone is reported as measurement variation unless the PR shows otherwise.
  2. **The tournament is re-run with a stated seed set, and reproduced twice.** `… -- run --e0 <E0> --b <B>` with the default `S = 200` writes a `scorecard.json` whose header reads `"ruleset":"classical-faithful"` and `"seedsPerMatchup":200`. A second run, `… -- run --no-timing --e0 <E0> --b <B>` (parallel play, a different play order), writes a `scorecard.json` with the same SHA-256. Both printed hashes appear in the PR and in §1 of the results document, which replaces T59's `C6E46222…3FBF` and its history note with the new hash and the commit measured.

- **Hazards**:
  - **Do not retune a candidate, and do not fix #648.** A candidate that now scores badly is reported with the number it got. A D06 or D07 correction would make C2 a different candidate from the one the survey specified, and the v0.5.0 port supersedes it anyway.
  - **Determinism is the whole value.** If the two runs' hashes differ, the scorecard is not committed: stop and report. Wall-clock timings stay out of `scorecard.json`, as T59 kept them.
  - **The run is long.** It plays 930,000 battles per `run`, twice, plus the smoke test's 1,000 seeds per battle per candidate. Run in Release with nothing else running, and budget for it before starting.
  - **The smoke test needs the local asset corpus.** `smoke --corpus <asset directory>` reads the original saves for §9.2 and §9.3. Run on a machine that has them. If none is available, stop and report rather than leave §7 half re-measured.
  - **The cost section is a machine measurement.** E0, B and every per-battle cost come from one machine and one session, and the document names that machine as §5 does now. Do not mix a new candidate's timing with T59's E0.
  - **C1 is the control, not a target.** C1 moved since T59 because of a merged change to the shipped resolver, not the matrix. Done-when 3 proves that, names the commit, and only then re-records C1's numbers. Never change a candidate to make C1 match.
