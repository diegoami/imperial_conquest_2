- **Design milestone**: M18 (the Godot UI). From the user's decision 4 of 2026-10-01 on the UI command audit ([`original-ui-command-audit.md`](../investigations/original-ui-command-audit.md) §1.5 and §2.1). **Labels**: `phase:3 lane:ui single-instance`

- **Start after**: none · **Merge after**: T100. It is **never in flight with** another task or fix under `godot/**`, except an engine task's one-line entry in `godot/UI/CommandVerbCatalog.cs`.
- **Owns**:
  - `godot/UI/AreaMapView.cs` (new);
  - `godot/UI/AreaMapGeometry.cs` (new, Godot-free: tile to mini-map pixel, and the view rectangle);
  - `godot/UI/GameMapView.cs` (a public centre-on-tile method, the visible tile rectangle, and a view-changed event only);
  - `godot/UI/MainGameScreen.cs` (the mini-map's placement only);
  - `godot/Checks/AreaMapCheck.cs`, `godot/Checks/AreaMapCheck.tscn` (new);
  - `tests/IC2.Engine.Tests/Ui/AreaMapGeometryTests.cs` (new), and the one `<Compile Include>` line for `AreaMapGeometry.cs` in `tests/IC2.Engine.Tests/IC2.Engine.Tests.csproj`.
- **Scope**: the clone keeps one zoomable map for orders (`GameMapView`, the original's Unit map) and adds a small overview, the original's **Area map**: the whole 320 × 140 world, scaled. A click on it re-centres the order map on that tile **[confirmed: `2026-09-29-nation-view-origin-and-unit-map-clicks.md`]**, and it draws a rectangle for the order map's current view, which follows every pan and zoom **[derived: code, `TAreaMap_UnitMapCursor`]**. It takes no orders.
  - It draws terrain from the game state at one pixel or more per tile. It sits at the top of the right-hand column, above the context panel **[designed]**, and never overlaps the order map.
  - It draws no unit markers of its own. T110 adds the Area map menu's highlights and its toolbar strip on top of it.
- **Done when**:
  1. `AreaMapGeometryTests` pins the tile-to-pixel mapping at the mini-map's size, both ways, for the four corners and a middle tile. It pins the view rectangle for a given order-map centre and zoom, including clamping at the map's edges. It fails on `main` and passes after.
  2. The headless `AreaMapCheck` builds the real `MainGameScreen`, sends a mouse click to the mini-map at Rome's tile, and asserts that the order map's centre tile is then within one tile of Rome's.
  3. In the same check, after the order map is zoomed and panned, the mini-map's view rectangle equals `GameMapView`'s visible tile rectangle mapped through `AreaMapGeometry`.
  4. A click on the mini-map submits no command (the session's command count is unchanged), and the selection is unchanged.
  5. `MapClipCheck`, `MapClickCheck`, `MenuBarCheck` and `ContextPanelWidthCheck` pass: the mini-map stays outside the order map's rect, and the context panel keeps its 340 px floor.
  6. `dotnet build IC2.sln` and `dotnet test IC2.sln` are green, and the diff lists only Owns paths.
- **Hazards**:
  - The original's Area map is a separate window. Making it an embedded panel is the user's decision 4, so don't build a second window.
  - Draw the terrain once into a texture and redraw only the rectangle on a view change: a per-frame redraw of 44,800 tiles is wasteful.
  - Wiring `AreaMapCheck` into `.github/workflows/ci.yml` is a one-line follow-up after the merge, not this task's.
