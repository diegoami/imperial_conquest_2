# T228 — Maximum support and upkeep-derived army funding

Owner policy #1497 (2026-10-27) supersedes T207/T208's editable resource targets and treasury reserve. This is human QoL automation, not a claim that the original automatically performs these actions.

## Contract

- Settings exposes opt-in army/fleet supply, army funding and fleet repair without supply/repair/purse target or treasury-reserve editors. Existing enable/disable choices remain. Old numeric fields may remain as settings-file compatibility data but cannot control execution.
- Supply always tops up to the loaded maximum (army dialog capacity, fleet capacity), within eligible owned/free provider stock. Do not make paid purchases or invent new providers. Repair requests the loaded maximum remaining condition at owned towns, preserving cargo/construction gates and consuming movement through the existing command. It stays at confirmed End turn, not during travel.
- Army purse demand is the nominal quarterly upkeep of **all current regular and mercenary units**, computed by the existing ArmyUpkeep helper used by the information panel. Top up toward that demand without withdrawing existing money. Respect the ordinary per-transfer/receiving-purse cap; an already over-cap purse must never be reduced by a positive auto-funding request.
- No artificial treasury reserve. Faithful treasury funding may enter debt under the existing PerUnitPurses transfer policy; Improved/CentralTreasury remains balance-limited. The existing repair command already allows treasury debt in both presets; automation must not add an affordability gate. No manual command or billing rule changes.
- Retreat-and-supply town serviceability follows those same existing repair gates rather than a removed reserve. Keep danger, routing, ranking, split suggestions and completion policy unchanged.
- Run only on confirmed human End turn, preserve action order/Cancel/nonmutation during planning, and keep native/save/export formats unchanged. No new fleet purse-funding feature is introduced.

## Owns

SettingsScreen Automation rows; ArmyAutoSupportPlanner/FleetAutoSupportPlanner; the reserve-only serviceability condition in RetreatSupplyPlanner; corresponding MainGameScreen summary/target checks; legacy UserSettings numeric-field comments; focused planner/session tests, the obsolete automatic-funding expectation in TransferMoneyCommandTests, SettingsCheck/EndTurnBoxCheck and T207/T208/T219 policy cross-references. Manual tests and engine commands/billing, routing and save schemas are read-only.

## Done when

1. Mixed regular/mercenary controls pin actual quarterly demand independently, Faithful debt/zero/positive balances, Improved available balances, existing purse above cap, loaded transfer limits and direct accepted command accounting. Legacy target/reserve values cannot alter proposals.
2. Army/fleet supply and repair use maxima with zero legacy targets and negative treasury; provider/cargo/construction/town/zero-demand/off controls stay valid. Retreat repair does not reject a town solely for debt/reserve.
3. Actual Settings has no numeric target/reserve controls. Confirmed End turn proves derived funding/full repair/order, hotseat isolation and Cancel; existing mobilisation/rally/retreat controls remain. Relevant focused tests, builds and CI pass.

Docs affected: contract/index, T207/T208 policy cross-references and player-facing automation explanation. No owner profile/campaign/private save is modified.
