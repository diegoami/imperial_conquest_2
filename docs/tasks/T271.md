# T271 — Period unit presentation using existing archetypes

Issue [#1709](https://github.com/diegoami/imperial_conquest_2/issues/1709),
supporting T269 and #1681/#1682. Reuse the five existing troop archetypes,
numeric rules, naming ordinal scan and authored glyph system. Add optional
generated-battalion labels and visual identifiers, omitted by default. No new
chariot combat, movement, recruitment coefficient or tactical-general policy.

Own optional `UnitTypeRules` presentation metadata and validation/authoring
docs, naming callers for mobilization and unit split, tactical/strategic image
key selection, authored chariot glyphs with a reproducible native generator
and manifest entries, focused naming/model/asset/view-model controls and the
task catalogue. Historical scenario data is separate.

Done when an era ruleset can show chariot names/images while retaining its
canonical mobile-unit IDs and every numeric rule; new mobilization/splits use
the existing ordinal scan with its configured label; image selection changes
presentation only; assets conform; and classical/default controls and optional
field omission stay unchanged. Record the proxy in the campaign brief. Read
the relevant private recruitment/battle manual sections and screenshots before
presentation edits. Full CI before merge.

UI reference: private manual §5.3 (`M04_11_army_recruits_after_recruit.png`)
and §7 (`M06_16_orig_battle_unit_to_place_selected.png`) show the five troop
roles and per-unit battle display. The owner's historical-period presentation
decision is the explicit naming/art exception; original mechanics and default
labels remain intact. Chariot shapes extend the existing integer glyph system,
not original-game art. Optional pack extensions do not add required core keys.

The pre-existing authored-marker verifier discrepancy is tracked separately
by T272/#1710; do not hide it behind the new glyph checks.
