#### T129 The tactical battle's golden master: the port replays the original's recorded battles half-round by half-round

- **Design milestone**: M21 (the tactical battle, v0.5.0 *Battles*, [#496](https://github.com/diegoami/imperial_conquest_2/issues/496)). The user's decision of 2026-10-04 moved the check against the original in play out of the design and into the tasks, as a golden master built from the decompile's 11-point list. This is that golden master: it reads the original's mid-battle saves and replays them through the port with the original's own generator. **Labels**: `phase:2 lane:engine local-only`
- **Branch**: `task/T129-tactical-golden-master` · **Model/effort**: Sonnet / High · **Reviewer**: **Opus**/High: **very complex** under [§3.4](../build-process.md#34-why-the-reviewers-model-differs-from-the-implementers) criterion (c), since it adds a save-reader section to `IC2.Data`
- **Start after**: T123, T124 · **Merge after**: T123, T124, T125 (the clone's mid-battle save, Done-when 3). It is **never in flight with** a task that edits `src/IC2.Data/SaveFormat.cs`, `SaveTurnState.cs` or `src/IC2.Engine/Import/**`.
- **Owns**:
  - `src/IC2.Data/SaveBattleBlock.cs` (new): the 2,105-byte battle block that follows a set battle flag;
  - `src/IC2.Data/SaveTurnState.cs`: **only** parsing the battle flag (`+54`, today "not parsed here", ~:13) and exposing the block when it is set;
  - `src/IC2.Engine/Import/OriginalBattleBlockImport.cs` (new): a `SaveBattleBlock` and its imported `GameState` into T123's `TacticalBattleState`;
  - `tests/IC2.Data.Tests/SaveBattleBlockTests.cs` (new);
  - `tests/IC2.Engine.Tests/Battle/Tactical/GoldenMaster/**` (new);
  - in the private fixtures repository `ic2-test-fixtures` (not this one): a `battles/` folder with the saves named below, fetched by CI as T53's fixtures are.
- **Scope**:
  - **Protects**: the port's fidelity to the original's recorded battles, field by field and half-round by half-round under the original's generator, and the report's 11 checks, the resume through a clone save included. Forbidden: a tolerance, a skipped half-round or file, an expectation re-derived from the port's own output, a change to the port's rules to make a file pass (a mismatch is a finding, filed as a bug against T123 or T124), and any save or game file committed to this repository.
  - **The evidence** **[Wine candidate: [`2026-10-04-battle-probe.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/main/docs/reports/2026-10-04-battle-probe.md), [`2026-10-04-tactical-battle-sweep.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/main/docs/reports/2026-10-04-tactical-battle-sweep.md), research `dee8150`]**: the conquest repository's releases [`run-exp-battle-probe`](https://github.com/diegoami/ic2-conquest/releases/tag/run-exp-battle-probe) and [`run-exp-battle-sweep`](https://github.com/diegoami/ic2-conquest/releases/tag/run-exp-battle-sweep), 585 saves with a battle block between them. The lab build sets `RandSeed` to its baked seed at `TBattleMap.StartBattle`, which is both the start and the resume path, and writes one `BATTLEnn.SAV` per half-round **after a side's moves and before its melee**. So each series replays from its start save and its seed with the Delphi generator of T123's replay implementation. The block layout is the decompile's (§1), and the research repository's `scripts/battle-block-check.py` reads it independently.

  - **How a series is replayed.** Import the start save (T21's importer), set the attacker and defender and each side's control as the table says, seed the replay generator with the series' seed, and run T123's copy-in, T124's general and T123's half-rounds. At each point where the lab writes a save (the call to the half-round end), compare the port's battle block with the file's, all 9 header bytes, 40 slots and 168 cells. At the end, compare the post-battle strategic fields the write-back touches (both armies' units, money, supplies, unity, the news line). A resumed series starts from the imported block, reseeds, and runs T123's `Resume`.
  - **The two-human and the improved cases** are not in the evidence and are not checked here.
- **Done when**:
  1. `SaveBattleBlockTests` (local-only, skipping without the fixtures as `IC2.Data.Tests` does): every one of the fixtures' block saves parses; the block is 2,105 bytes after the flag and the file 134,254 bytes; for every save not crafted to break it, the icon grid equals `type × 3 + size (+20)` computed from the slots; the start shots read 7, 0, 25, 9, 0 by type.
  2. **Every listed series replays exactly.** For each row of the table marked with checks 1–10 or 3–10, every `BATTLEnn` block equals the port's at the same point, byte for byte, and the post-battle fields equal the post save's; the PR lists each series with its file count and `PASS`. A failing file is reported with the first differing field (slot, field, port value, original value) and the series is not marked passing.
  3. **The resume (check 11).** `resume05_gate2_a_r1`'s ten files equal the port's resume of `gate2_a_BATTLE05` under seed 1, and **none** equals the uninterrupted `gate2_a` tail, as the probe found. The same holds **through a clone save**: `gate2_a_BATTLE05`'s block, imported, saved by T125's mid-battle save, reloaded and resumed under seed 1, gives the same ten files (the user's decision of 2026-10-04 on #496: a classical reload resumes like the original).
  4. **The crafted saves.** `c2` and `c4` replay to the same battle; `c5`, `c6`, `d5` and `d6` keep their stale or doubled cells where the original's files do.
  5. **The peace draw.** The `Random(5)` after the promotions offers the treaty in `gate2_s2a`, `hi-hi-one_s1` and `hi-hi-one_s3`, and not in `gate2_a` or `hi-hi-one_s2`, as the reports observed.
  6. `git diff --stat origin/main...HEAD -- src/IC2.Engine/Battle src/IC2.Engine/Presentation` is empty (the golden master changes no rule), no save or game file is added to this repository (`git diff --stat origin/main...HEAD | grep -i "\.sav"` prints nothing), and `dotnet build IC2.sln` and `dotnet test IC2.sln` are green with the diff listing only Owns paths.
- **Hazards**:
  - **The evidence is Wine-only, on a lab build.** A mismatch can be the port's, the lab patch's or Wine's. File it as a bug with the field and the half-round; do not change the port in this task, and do not loosen a check. The user decides what a confirmed mismatch means.
  - **Known unexplained points.** The sweep saw a resume raise the counter by 2 once (the code gives 1), and Gaul's light infantry reading 1 move (the slow advance explains it). If either fails, report it against the report, not the port.
  - **Who is computer-controlled.** Rome is a human nation under *Computer general*: no `+3`, no sort, no slow advance for it. Getting this wrong fails check 1 and 4 at the first file.
  - **The saves are the user's game files.** They stay in the private fixtures repository; nothing from them is committed here. Without them the tests skip explicitly, and the PR shows a local run.
  - **The 11-point list is the report's.** A check not covered by a fixture (two humans, a human-played side, `improved`) is named as uncovered in the PR, not invented.
