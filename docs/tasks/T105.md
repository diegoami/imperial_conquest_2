- **Scope**: the supply dialog's money panel (`TAFSupply_ChangeMoney`) moves talents between the national treasury and one army's or fleet's purse. T38 built it as a function, `Economy/TreasuryPurseTransfer.cs`, and nothing issues it. This task wraps it as a command and changes nothing in the function.
  - **`transfer-money <army|fleet> <amount>`**: a positive amount moves money from the treasury to the purse, a negative one from the purse to the treasury. The function's own rules hold: the purse cap (`EconomyRules.PurseCapPerUnit`), and never more than the source holds.
  - Only the active nation's own army or fleet. A foreign or unknown id is rejected.
- **Done when**:
  1. `TransferMoneyCommandTests`: on the classical scenario, `transfer-money <Rome's army> 100` moves 100 from Rome's treasury to that army's purse, and `-50` moves 50 back. The treasury plus the purse is conserved exactly. It fails on `main` (no command) and passes after.
  2. The same for a fleet.
  3. An amount past the purse cap, or more than the source holds, is clamped exactly as `TreasuryPurseTransfer` clamps it, asserted against the function's own result for the same inputs.
  4. A foreign army, an unknown id, and a zero or non-integer amount are each rejected, with the state unchanged.
  5. `CommandCoverageTests` passes, with an **accepted** `transfer-money` line in the success golden. The CI `OrderCoverageCheck` is green with the mirror entry.
  6. `dotnet build IC2.sln` and `dotnet test IC2.sln` are green, and the diff lists only Owns paths.
- **Hazards**:
  - **A co-located fleet as the money's other side is [open]** (`TreasuryPurseTransfer.cs`'s own remarks). Don't add it.
  - Whether the dialog needs a supply provider nearby is the UI's gate, since the dialog opens only where one is (T111). Don't invent a location gate here.
  - `TreasuryPurseTransfer.cs` is not in Owns. If it lacks something, report it.
