- **Scope**: `EmbarkArmyCommandHandler` rejects unless the army and the fleet stand on the same tile. But `MoveArmyCommandHandler` blocks any tile where a city, an army or a fleet stands, and a fleet only ever stands on sea or on a city tile. So no army can ever embark, and nothing can ever disembark.
  - **The original's rule (the user, 2026-09-27):** an army embarks from a tile adjacent to its fleet, and then moves onto the fleet's tile. The handler already moves the army onto the fleet (~:50–53); only the check is wrong.
  - "Adjacent" uses the radius disembark already uses, `Economy.CommandAdjacencyRadiusTiles` (T70, bug #345), measured with the same `LandingTile.ChebyshevDistance`.
- **Done when**:
  1. **Adjacency.** An army within the radius of a fleet of its own nation embarks and ends on the fleet's tile. At radius + 1 it is rejected with a named rejection. Tests cover the boundary on both sides, and the same tile (radius 0) if the handler still allows it.
  2. **Everything else unchanged.** The capacity, trim and ownership rules and their existing tests stand.
  3. **End to end.** A test embarks an army from land, moves the fleet, and disembarks it onto a coastal tile through the real commands. The state validates and survives a `SaveManager` round trip.
  4. **T80's exception is gone.** `CommandCoverageTests` no longer exempts embark or disembark. The success script has an accepted line for each, and its golden is regenerated through the CLI with every changed line explained.
  5. **Provenance.** The rule cites the user's statement of 2026-09-27. If the implementer finds the original's embark routine in the decompile, it cites it. Otherwise it says what was searched.
