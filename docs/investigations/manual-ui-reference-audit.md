# Manual-to-UI reference audit

Date: 2026-10-28. Gameplay/UI baseline: `4d19e0345d233c4f897b54932a20db1e5f20d22f` (published v0.8.3). Audit requested in [#1551](https://github.com/diegoami/imperial_conquest_2/issues/1551) and performed by a `gpt-6.1-sol` agent at high reasoning effort, with parent source checks and issue triage. The observations below are pinned to that baseline; GitHub issues carry implementation status.

## Reference and method

The private research-authored original v1.01 manual is identified by its README as the October 2026 output of `diegoami/ic2-conquest#133`. The owner referenced its HTML recruitment section. The complete folder was obtained through rclone and kept under ignored `rendered/manual-reference/`; the [operating guide](../operating-guide.md#original-game-ui-reference-private) records access. No manual prose, screenshots, original binaries or private owner save data are included here.

The audit read the 11 narrative/reference chapters and source lists, inventoried 219 HTML headings, and cross-checked the new substantive expectations against the owner-referenced HTML. It inspected 18 relevant original screenshots. HTML and chapter Markdown each contain 109 image references to 104 unique images; the README says 95. This count disagreement is a documentation clarification, not evidence of a gameplay discrepancy. The checked expectation groups showed no substantive HTML/Markdown disagreement.

Comparison used current source, targeted historical issue/PR contracts, two production headless checks (16 RecruitSelectionCheck assertions and four RecruitQualityCheck assertions), and private synthetic model/production-command controls. The latter checked recruitment bounds/costs, build-port selection, fleet-transfer composition versus dispatch, and legal/illegal unit splits. No original-game execution, full test suite or owner save/settings writes were performed. The audit does not establish fresh installed-remake visual acceptance.

## Evidence conflicts and limits

[Research #91](https://github.com/diegoami/imperial-conquest-2-research/issues/91) records the manual/later-research recruitment distinctions, caller-specific fortification gates, contradictory quarterly tax-base summaries, alliance-war wording and screenshot-count metadata. Original nominal transport capacity does not override T232, and an original manual must not be rewritten to call T231 remake policy original behavior.

Research #91 is answered by [`2026-10-30-manual-clarifications91.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/a6f9024/docs/reports/2026-10-30-manual-clarifications91.md) (research `a6f9024`), a synthesis of promoted reports with no new playtest; neither research session read the manual itself, so its "supported wording" column is a proposal to check against the manual's actual text. Against the remake:

- **R04.** The original inserts All cities at the **top** when more than one town holds queued units; the remake appends it last (`RecruitUnitDialog.cs`, `FillCityDropdown`), which no recorded exception covers: [#1594](https://github.com/diegoami/imperial_conquest_2/issues/1594). The default town (queued units +1 for the capital, ties to the first listed) differs from the remake's opening, which is the owner's T162/T236 policy.
- **C01.** The list's decoded-level test and the Recruit button's raw-word test (≤ 74 refused unless capital) are the remake's since T155 ([game-design.md](../game-design.md), recruitment "Where"); the unplayed pending-order edge (word 572 passes) follows from the same raw-word test in both.
- **C02.** The report's proposed wording ("the tax base is recalculated … before that quarter's growth") conflicts with the Wine-observed tick in [`2026-10-12-g3-original-checks.md`](https://github.com/diegoami/imperial-conquest-2-research/blob/main/docs/reports/2026-10-12-g3-original-checks.md) Q2b, where wealth and tax base are zeroed first and rebuilt city by city after each city's growth, and the quarter's income uses the grown base (Rome +21, not +36). [game-design.md](../game-design.md) keeps the Q2b reading; the conflict is a research question, not a remake change.
- **C03.** The alliance gate (the proposer's edited row, its allies' wars, the committed matrix, a negative relation; the AI target's own wars unchecked; a human target always accepts) is the remake's `ProposeAllianceCommand` since T82.
- **Screenshot count.** 109 references to 104 unique images; the README's 95 likely predates the last chapter edits.

Verified matches include all five recruitment type minima/maxima/full-battalion initial costs, exclusive type buttons and Faithful debt Max, current early manual mobilisation quality, and correct raw initial capital queue visibility. A misleading initial-city inference was withdrawn after the model control; no empty-first-opening bug was filed.
